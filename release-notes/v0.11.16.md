## English

11 issues closed: #651 to #661.

### Compact while the agent works (#651)

- In *This session*, Compact is no longer disabled during a turn: it reads *Compact after this turn* and queues the compact on the server, with the optional note for the summary (`compact_queue`; `LiveInfo.compactQueued`, so every page shows it, a reload keeps it and a handoff to a new session file does not end it). The button then reads *Compact queued* with *Cancel*, and a line above the message box says the same.
- **Where it runs.** By default when the turn ends (`agent_end`). *Between steps* (Settings › *Where a compact you queue runs*, `ompw.compactWhere`, and a per-conversation choice in *This session*) runs it after a step's tools have all returned and before the next model request — the one other point where nothing is in flight, so nothing is lost. omp-webui's own extension (`server/omp/compact-step/`, loaded like the quota floor's) holds omp at that point in a dialog the server answers; omp then summarizes what is complete and carries the turn on by itself. A hold lets go on its own after 20 seconds. A conversation started with your own `--trusted-extension`, one where the extension did not start and one where omp's `compaction.autoContinue` is off wait for the end of the turn, and the page says which.
- Follow-ups waiting in omp's queue are taken out when the compact is queued and held by the server with any sent meanwhile (shown as ordinary queued chips), then sent in order after the compact. Stop cancels the request and hands the held messages back to the message box.
- `tests/contract/compact-between.test.ts` pins the order against the real omp (tool call, summary, the request carrying summary and tool result, then the held follow-ups).

### Quota floor (#652)

- Settings › **Quota floor** sets, per provider, the share of a usage window that may be left before a working conversation is held (1–99 %, off for every provider until you set one; each row shows the share left now). At or below it, the request in flight finishes and the conversation then waits before its next step, and goes on by itself after the window resets (plus one minute of grace).
- The conversation's own line says which state it is in (*the next step will wait*, *Waiting for the quota to reset* with the reason and the reset time, *Continuing past the quota floor*, or *cannot be held*). **Continue anyway** ignores the floor for that conversation until the provider is seen above it again; **Hold again** takes that back. The sidebar marks a held conversation; Settings › Running sessions says it waits for the quota.
- A held conversation outlives a server restart: the next server finds it held and lets it go at the reset. The floors are `quota-floor.json` (0600) and travel with *Move to another computer*.

### GitHub issues in the side panel (#653)

- The side panel's **Issues** tab lists the GitHub issues of the conversation's folder (*Open*, *Closed*, *All*, GitHub search syntax, refresh; at most 100). An issue opens with its labels, assignees, body and comments. **Insert into this conversation** puts it into the message box; **New conversation with it** opens *New chat* in that folder with it.
- **Read only**, through your own `gh` (`gh issue list`, `gh issue view`): nothing is written to GitHub. A folder with no GitHub remote, a repository whose settings name a program for git to run, a missing or signed-out `gh` and a GitHub that does not answer in 15 s are each said in the tab. Answers are kept 30 s.

### Sidebar and rail you arrange, Guard in the sidebar, Send feedback in Settings (#654, #660)

- The sidebar, the rail and the command palette's *Go to* read one list of pages (Usage, Memory, Questions, Commands, Settings, Guard). In each bar a page sits at the top, at the bottom or hidden, in any order: drag it (mouse, pen or finger; Esc puts it back), or use Settings › **Sidebar and rail** (*Move up*, *Move down*, the group, *Reset to default*). Kept on this device (`ompw.navLayout`). A hidden page is still in *Go to*; Guard is not offered to a page that came through the tunnel or the network.
- *Send feedback* is a button in Settings › Feedback, the command palette and the keyboard shortcuts card; the sidebar's foot no longer has it.

### Notifications whenever you are not looking (#655)

- A conversation that asks for your input or finishes notifies you unless you are looking at it: your window is the one in use **and** that conversation is on screen in it. A conversation that finishes while another one, Usage or Settings is on screen, or while the window is behind another or minimized, now notifies. One rule (`isLookingAt`, `shared/attention.ts`) for the browser, the macOS app's banner and Web Push; one notification per conversation, a newer one replacing the older.

### Notifications from another Mac (#656)

- The macOS app's Macs menu has *Notify me about conversations of:* with a tick per Mac, off until you tick one. With it on, the app notifies when that Mac's conversation asks or finishes, with its window open or closed; clicking opens the conversation in that Mac's window.
- The app reads `GET /api/notify/events` of that Mac, signed in exactly as its window is (Cloudflare Access and the server's access token, from that window's own sign-in; nothing else is sent, a redirect is not followed). The server refuses a request without the token (401) and one from the network that came neither through Access nor from that Mac (403); `/api/shell/events` stays local only. The stream ends when the Access token does and when remote access changes.
- Web pages over the tunnel or LAN HTTPS get *asks* and *finished* through Web Push; on iOS that needs *Add to Home Screen*.

### A timer on every command (#657)

- A running tool call shows its elapsed time on its card (whole seconds), a finished one how long it ran — kept across a reload. Your `!commands` and subagents' calls too. Settings › Conversations › *Show how long tool calls run*: all tool calls (default), shell commands only, or off (`ompw.toolTimer`).

### Quick prompts and Soft stop (#659, #658)

- The ⚡ button beside the message box lists messages you send often; one click sends one, as it says while the agent works: **Steer** now, or **Follow-up** after the turn. Settings › **Quick prompts** adds, edits, reorders and removes them (at most 20), with *Restore the defaults*; the command palette lists them too. While omp asks for an approval they are not offered (a message then denies the approval).
- **Soft stop** is a built-in quick prompt: the agent stops starting new work, finishes or safely pauses the step in progress, and writes a handoff as its last message (goal and status, done, in progress, uncommitted changes, next steps with commands, open questions). When that turn ends the server ends the conversation's omp process; the conversation is kept, says it was soft-stopped, and your next message carries on from the handoff. A turn still working ten minutes later is reminded once.

### Your own keyboard shortcuts (#661)

- Settings › Keyboard shortcuts: *Change* a binding and press the new keys; *Remove*, *Reset*, *Reset all shortcuts*. Kept on this device (`ompw.shortcuts`); every hint in the page shows the keys in force.
- A key another action already has where this one acts (the same surface, or anywhere for a global key or a quick prompt) is refused with that action named, or offered as a *Swap*. The surfaces' own keys (Esc, the command menu's arrows and Tab, Shift+Enter) are listed but not changed. A key that types text needs ⌘/Ctrl or Alt outside the global keys; keys the browser or macOS keep (⌘W, ⌘Q, ⌘T…) are warned about. No shortcut fires while an input method is composing. A quick prompt can have a key of its own.

### Fixes

- The side panel's nine tabs fit its default 400 px width again (compact tabs and the row's padding tightened).

### Performance

- Not measured for this release: the benchmark gate (#645) needs an idle Mac for about an hour and is moved to v0.11.17. The first page load is 202.9 KiB of gzip JS (budget 228 KiB), as `bun run build` reports.

## 中文

本次发布关闭了 11 个 issue：#651 到 #661。

### 工作中也能压缩（#651）

- “当前对话”里的“压缩”在 omp 工作时不再是灰的：按钮变成“本轮结束后压缩”，按下后服务器记下这次压缩（连同可选的摘要说明，`compact_queue`；`LiveInfo.compactQueued`，所以每个页面都能看到，刷新不会丢，交接到新的会话文件也不会取消）。之后按钮显示“已排队压缩”并带“取消”，输入框上方也有一行同样的提示。
- **何时执行。** 默认在本轮结束时（`agent_end`）。“两步之间”（设置 ›“你排队的压缩在何时执行”，`ompw.compactWhere`；“当前对话”里每个对话也可以单独选）在一步的工具全部返回之后、下一次模型请求之前执行——唯一另一个没有东西在途的时刻，所以什么都不会丢。omp-webui 自己的扩展（`server/omp/compact-step/`，和额度下限的扩展一样加载）在那一刻让 omp 停在一个由服务器回答的对话框里；omp 随后对已经完成的内容做摘要，并自己继续这一轮。停留 20 秒后会自行放行。用你自己的 `--trusted-extension` 启动的对话、扩展没有启动的对话，以及 omp 的 `compaction.autoContinue` 为关闭的对话，都会等到本轮结束，页面会说明是哪一种。
- 排队压缩时，omp 队列里等待的后续消息会被取出，和此期间新发的一起由服务器保管（显示为普通的排队标签），压缩之后再按顺序发出。“停止”会取消这次请求，并把保管的消息放回输入框。
- `tests/contract/compact-between.test.ts` 对照真实的 omp 固定了顺序（工具调用、摘要、带着摘要和工具结果的请求，然后是保管的后续消息）。

### 额度下限（#652）

- 设置 ›**额度下限**为每个提供商设一个下限：用量窗口还剩多少时，正在工作的对话要被暂缓（1–99%，在你设置之前对所有提供商都是关闭的；每一行显示现在还剩多少）。到达或低于下限时，正在进行的请求会完成，然后对话在下一步之前等待，窗口重置（再加一分钟宽限）后自己继续。
- 对话自己的那一行说明它处于哪种状态（“下一步将等待”、“正在等待额度重置”及原因和重置时间、“正在越过额度下限继续运行”或“无法暂缓”）。**仍然继续**让这个对话在提供商再次高于下限之前不理会下限；**重新暂缓**撤回它。侧边栏会标出被暂缓的对话；设置 › 运行中的对话会说明它在等额度。
- 被暂缓的对话能熬过服务器重启：下一个服务器会发现它仍在暂缓，并在重置时放行。下限保存在 `quota-floor.json`（0600），随“搬到另一台电脑”一起走。

### 侧边面板里的 GitHub issues（#653）

- 侧边面板的 **Issues** 标签页列出对话所在文件夹的 GitHub issues（“未关闭”“已关闭”“全部”、GitHub 搜索语法、刷新；最多 100 条）。打开一条可以看到标签、负责人、正文和评论。**放进这个对话**把它放进输入框；**用它开始新对话**在同一文件夹打开“新对话”并带上它。
- **只读**，通过你自己的 `gh`（`gh issue list`、`gh issue view`）：不会向 GitHub 写任何东西。没有 GitHub 远程仓库的文件夹、仓库设置里指定了让 git 运行的程序、`gh` 没装或没登录、GitHub 15 秒内没有回应，标签页都会分别说明。结果缓存 30 秒。

### 自己安排侧边栏和窄栏，防护进侧边栏，“发送反馈”移到设置（#654、#660）

- 侧边栏、窄栏和命令面板的“前往”来自同一份页面清单（用量、记忆、问题、命令、设置、防护）。每个栏里，页面可以放在上方、下方或隐藏，顺序随意：拖动它（鼠标、触控笔或手指；按 Esc 放回原处），或用设置 ›**侧边栏与快捷栏**（上移、下移、分组、“恢复默认”）。只保存在这台设备上（`ompw.navLayout`）。隐藏的页面仍在“前往”里；经隧道或网络打开的页面不提供“防护”。
- “发送反馈”是设置 › 反馈、命令面板和键盘快捷键卡片里的按钮；侧边栏底部不再有它。

### 只要你没在看，就会通知（#655）

- 对话需要你输入或已完成时，除非你正在看它，否则都会通知你：你的窗口是正在使用的那个，**并且**这个对话就显示在其中。现在，屏幕上显示的是另一个对话、用量或设置时，或者窗口在别的窗口后面、被最小化时完成的对话，都会通知。浏览器、macOS 应用的横幅和网页推送用的是同一条规则（`isLookingAt`，`shared/attention.ts`）；每个对话只保留一条通知，新的替换旧的。

### 来自另一台 Mac 的通知（#656）

- macOS 应用的“Macs”菜单里有“通知我这些 Mac 的对话：”，每台 Mac 一个勾，在你勾选之前都是关闭的。打开后，那台 Mac 的对话需要输入或完成时，无论它的窗口开着还是关着，应用都会通知；点击通知会在那台 Mac 的窗口里打开这个对话。
- 应用读取那台 Mac 的 `GET /api/notify/events`，登录方式和它的窗口完全一样（Cloudflare Access 和服务器的访问令牌，来自那个窗口自己的登录；不发送其他任何凭据，也不跟随重定向）。服务器拒绝没有令牌的请求（401），也拒绝既没经过 Access、又不是来自那台 Mac 本身的网络请求（403）；`/api/shell/events` 仍然只限本机。Access 令牌到期或远程访问设置改变时，这个流会结束。
- 经隧道或局域网 HTTPS 打开的网页通过网页推送收到“需要输入”和“已完成”；在 iOS 上需要先“添加到主屏幕”。

### 每条命令都有计时（#657）

- 运行中的工具调用在卡片上显示已用时间（按整秒），结束的显示用了多久——刷新后也还在。你自己的 `!` 命令和子代理的调用也一样。设置 › 对话 ›“显示工具调用的运行时间”：“所有工具调用”（默认）、“仅 Shell 命令”或“关闭”（`ompw.toolTimer`）。

### 快速指令和软结束（#659、#658）

- 输入框旁边的 ⚡ 按钮列出你常发的消息，点一下就发送；代理工作时按它设定的方式发：**立刻插入**马上送到，**后续消息**等本轮结束。设置 ›**快速指令**里可以添加、编辑、排序和删除（最多 20 条），还可以“恢复默认”；命令面板里也能找到它们。omp 请求批准期间不提供它们（这时发出的消息会拒绝那次批准）。
- **软结束**是一条内置的快速指令：代理不再开始新的工作，完成或安全地暂停手上这一步，然后把交接说明作为最后一条消息写出来（目标和状态、已完成的、进行中的、未提交的改动、下一步和要运行的命令、待决的问题）。那一轮结束时，服务器结束这个对话的 omp 进程；对话会保留，并说明它是软结束的，你的下一条消息会从交接说明处继续。十分钟后还在工作的那一轮会被提醒一次。

### 自定义快捷键（#661）

- 设置 › 键盘快捷键：点“更改”，按下新的按键；还有“移除”“恢复”“全部恢复默认”。只保存在这台设备上（`ompw.shortcuts`）；页面里所有的按键提示都显示当前生效的按键。
- 如果某组按键在这一项起作用的地方已经属于另一个操作（同一个界面，或者任何地方的全局快捷键或快速指令），会被拒绝并指出是哪个操作，或者提供“互换”。界面自带的按键（Esc、命令菜单的方向键和 Tab、Shift+Enter）会列出来，但不能更改。在全局快捷键之外，会输入文字的键需要配合 ⌘/Ctrl 或 Alt；浏览器或 macOS 占用的按键（⌘W、⌘Q、⌘T 等）会给出提醒。输入法正在组字时不会触发任何快捷键。快速指令也可以有自己的快捷键。

### 修复

- 侧边面板的九个标签页在默认 400 px 宽度下又能完整放下（收紧了紧凑标签和标签行的边距）。
