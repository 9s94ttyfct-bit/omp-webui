## English

### Install omp from the app, then a guided setup (#185)

- When omp isn't found, the app no longer quits: it offers to install omp with Homebrew, omp's own installer or bun, shows the exact command before it runs, and streams its output (with Cancel and Retry).
- A short setup follows: sign in to a provider, choose a default model and a permission mode, then start your first conversation. It can be skipped and run again from Settings.

### omp updates (#184)

- The app tells you when a newer omp is out (with a link to its release notes) and updates it with omp's own `omp update` as soon as no conversation is working. Settings › omp has "Update omp automatically" (off by default), which only updates while every conversation is idle.
- It warns before moving to an omp version this app isn't made for, and when the installed one is already outside the supported range.

### Paused conversations survive quitting (#194)

- A paused conversation now survives quitting the app (or stopping the server). Its omp and its running tools stay frozen in the background; after you open the app again it is still paused, and Resume continues exactly where it stopped.
- The quit dialog and Settings › Running sessions say that paused conversations stay in the background, and the quit dialog offers "Quit and End Paused". Conversations that are not paused still end when you quit.
- If a paused conversation's background helper is lost (for example after a restart of the Mac), the conversation is closed cleanly and opens as an ordinary conversation.

### MCP server switches (#204)

- You can switch MCP servers on and off from the "Loaded" dialog. The change is saved where the server is defined (your `mcp.json` or the folder's `.omp/mcp.json`). omp only connects MCP servers when it starts, so while the conversation is idle the dialog offers "Restart omp to apply", which resumes the same conversation in a new process; while it is busy, the change applies the next time omp starts.
- Settings › Mode marks MCP servers that omp has switched off: offline mode doesn't load them either.
- The switches in the Loaded dialog stay busy until the refreshed state is shown, so a quick second click can no longer flip the wrong way.

### Documentation (#205)

- The README's compatibility table lists every omp command, RPC, flag and file the web UI uses, and a test keeps it complete.

### Fix: your interface preferences no longer reset (#200)

- Theme, palette, language, panel widths and your other interface preferences no longer reset when the macOS app starts on another port (it moves when 7878 is taken). They are kept with the app's data and applied before the first paint, so nothing flashes. Preferences set before this version are picked up once, on the first launch.

### Fix: every side-panel tab fits (#196)

- With counts such as "Agents 1/55", the side-panel tabs no longer run off the edge: at the default width every tab is visible, and the inactive ones show their icon and count. In a narrower panel the active tab is kept in view, and the mouse wheel scrolls the tabs sideways.

### Fix: clicking a notification no longer closes your dialog (#203)

- Clicking a notification's dismiss or action button (such as Undo) while a dialog is open leaves the dialog open, and your place in it is kept.

### Fix: a conversation waiting out omp's own retry is no longer closed as idle (#202)

- While omp backs off before retrying (including waiting for a usage reset), the conversation now counts as working: it is no longer closed as idle, and the app asks before quitting.

### Fix: a failed omp update no longer shows "Updating…" (#206)

- An omp update that fails at once now says so and offers Retry; before, the notice could stay on "Updating…".

### Fix: reading back in a long conversation (#201)

- Scrolling up in a long conversation no longer jumps back to the bottom when something unrelated on the page updates.

## 中文

### 在应用内安装 omp，并引导完成设置（#185）

- 找不到 omp 时，应用不再直接退出，而是提供用 Homebrew、omp 官方安装脚本或 bun 安装 omp。运行前会显示将执行的命令，并实时显示安装输出（可取消、可重试）。
- 安装后有一个简短的设置向导：登录提供商、选择默认模型和权限模式，然后开始第一个对话。向导可以跳过，也可以在设置里重新运行。

### omp 更新（#184）

- 有新版 omp 时，应用会提示你（附更新说明链接），并在没有对话在工作时通过 omp 自己的 `omp update` 更新。“设置 › omp”里新增“自动更新 omp”（默认关闭），开启后只在所有对话都空闲时更新。
- 更新到本应用不支持的 omp 版本前会先警告；已安装的 omp 超出支持范围时也会提醒。

### 已暂停的对话在退出应用后保留（#194）

- 已暂停的对话现在可以在退出应用（或停止服务器）后保留：它的 omp 和正在运行的工具会在后台保持冻结；重新打开应用后它仍然处于暂停状态，点“继续”就能从停下的地方接着运行。
- 退出对话框和“设置 › 运行中的对话”会说明已暂停的对话会留在后台，退出对话框还提供“退出并结束已暂停的对话”。没有暂停的对话仍然随应用一起结束。
- 如果已暂停对话的后台辅助进程丢失（例如重启电脑后），这个对话会被干净地结束，之后会像普通对话一样重新打开。

### MCP 服务器开关（#204）

- 现在可以在“已加载”对话框里开关 MCP 服务器。改动会保存在定义该服务器的地方（你的 `mcp.json` 或该文件夹的 `.omp/mcp.json`）。omp 只在启动时连接 MCP 服务器，所以对话空闲时，对话框会提供“重启 omp 以生效”，用新的进程恢复同一个对话；对话忙时，改动会在 omp 下次启动时生效。
- “设置 › 模式”会标出 omp 里已关闭的 MCP 服务器：离线模式也不会加载它们。
- “已加载”对话框里的开关会保持忙碌，直到刷新后的状态显示出来，快速连点第二下不会再往错误的方向切换。

### 文档（#205）

- README 的兼容性表列出了网页界面用到的每一个 omp 命令、RPC、选项和文件，并有测试保证它完整。

### 修复：界面偏好不再被重置（#200）

- macOS 应用因 7878 端口被占用而改用其他端口启动时，主题、配色、语言、面板宽度等界面偏好不再丢失。偏好现在随应用数据一起保存，并在页面首次绘制前生效，不会闪烁。升级前设置的偏好会在升级后首次启动时自动导入一次。

### 修复：侧边面板的每个标签都能显示完整（#196）

- 带有“代理 1/55”这类计数时，侧边面板的标签不再超出边缘：默认宽度下所有标签都可见，未选中的标签显示图标和计数。面板较窄时，当前标签会保持可见，鼠标滚轮可以横向滚动标签。

### 修复：点击通知不再关闭已打开的对话框（#203）

- 打开对话框时点击通知的“关闭”或操作按钮（例如“撤销”），对话框会保持打开，光标位置也不变。

### 修复：等待 omp 自身重试的对话不再被当作空闲关闭（#202）

- omp 在重试前退避等待（包括等待用量重置）时，对话现在算作“工作中”：不会被当作空闲进程关闭，退出应用时也会先询问。

### 修复：omp 更新失败时不再一直显示“正在更新…”（#206）

- omp 更新一开始就失败时，现在会显示失败原因并提供“重试”；之前提示可能一直停在“正在更新…”。

### 修复：在长对话里往回看（#201）

- 在长对话里向上滚动阅读时，不会再因为页面上其他无关内容更新而被拉回到底部。
