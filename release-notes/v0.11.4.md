## English

### Safer content (#320, #321, #322, #323, #324, #325, #326)

- Exported HTML is now inert: opening an exported conversation runs no script, loads nothing from the network and goes nowhere, even if a reply contained raw HTML, a remote image or a redirect. Raw HTML in replies shows as text, as in the app.
- A reply with absurdly deep nesting (quotes, lists, open link labels) no longer crashes the tab or freezes the chat. It shows as plain text with a note, and a message that can't be displayed shows a placeholder while the rest of the conversation keeps working.
- The tool approval card shows the whole command, with a taller scrolling box, a visible scrollbar and a "more below" line. Invisible and bidi-control characters appear as visible markers (for example `⟨U+202E RLO⟩`), so what you approve is what runs.
- Links printed by programs in the built-in terminal now open in your browser in the macOS app, after a confirmation that shows the address.
- Links in replies that point nowhere (file paths, refused schemes, `irc:`) are plain text instead of opening a second copy of the app. Footnote references scroll to their note within the message.
- Long notifications no longer cover the screen or the Send button: a long toast is cut to three lines with "Show more", opens in a scrolling box, and stays up while it is open.
- Regenerate and Edit no longer request arbitrary addresses for a saved image whose reference is not a valid hash.

### Damaged session files (#332, #333)

- One malformed line in a session file (a `null` or other non-block entry in a message's content, a text block whose text is a number) no longer replaces the chat with the Reload screen. The conversation opens, what can be read of the message is shown, and the messages around it are as usual. Search indexes only real text.
- A usage figure that isn't a number (text, `null`, an object, `NaN`, an out-of-range value) no longer turns totals into junk like `0a` or `NaN`; it counts as 0 in the page and in the sidebar totals. Totals an older version had already stored this way are summed again from the file at the next start.

### Faster start, and a search index that stays small (#327, #328, #331)

- Search is ready as soon as the app starts. The first search after a restart used to wait 2 s with 1,200 conversations and 4 s with 4,800 while the whole index file was checked; it now answers in about 0.1 s. A damaged index is still found: after a crash or force-quit the whole file is checked, and a bad page met later moves the file aside and rebuilds it.
- The search index now gives its space back when you delete conversations: with all but three of 1,200 conversations deleted it is 24 MB instead of 230 MB, and its journal file no longer stays at 137 MB. It tidies itself in the background, and searches are answered meanwhile.
- Search no longer finds conversations that were deleted or moved while the app was closed (opening such a hit failed).

### Fix: the sidebar stopped refreshing while agents were busy (#329)

- The conversation list now refreshes at least every 1.5 s while conversations are being written, instead of waiting for all of them to stop.

### Fix: opening a long subagent transcript stopped the whole app (#330)

- A subagent's transcript is now read off the server's main thread. Opening a 58 MB one used to stop Send, Stop and streaming in every conversation for 0.7 s (4 s for 300 MB); they now keep going.

## 中文

### 内容更安全（#320、#321、#322、#323、#324、#325、#326）

- 导出的 HTML 现在是惰性的：打开导出的对话不会运行脚本、不会从网络加载内容、也不会跳转到别处，即使回复里有原始 HTML、远程图片或重定向。回复里的原始 HTML 与应用内一样显示为文本。
- 嵌套极深的回复（引用、列表、未闭合的链接标签）不会再让标签页崩溃或让对话卡死：它按纯文本显示并附说明；无法显示的消息会换成占位提示，对话其余部分照常可用。
- 工具批准卡片现在显示完整命令：更高的可滚动区域、始终可见的滚动条和“下面还有内容”的提示；不可见字符和双向控制字符会显示为可见标记（如 `⟨U+202E RLO⟩`），你批准的就是实际运行的。
- 程序在内置终端里打印的链接，在 macOS 应用中经确认（显示实际地址）后会在浏览器里打开。
- 回复里无处可去的链接（文件路径、被拒绝的协议、`irc:`）现在是纯文本，不会再打开一个应用副本；脚注引用会在消息内滚动到对应脚注。
- 很长的通知不再铺满屏幕或盖住“发送”按钮：长通知先截成三行并提供“显示更多”，展开后在可滚动的框里阅读，展开期间一直保留。
- 已保存图片的引用不是有效哈希时，“重新生成”和“编辑”不再请求任意地址。

### 损坏的会话文件（#332、#333）

- 会话文件中的一行格式错误（消息内容里的 `null` 或其他非内容块、文本块的文字是数字）不再让聊天页面变成“重新加载”界面：对话照常打开，显示这条消息中能读懂的部分，前后的消息不受影响。搜索只索引真正的文本。
- 不是数字的用量字段（文字、`null`、对象、`NaN`、超出范围的值）不再把合计变成 `0a`、`NaN` 之类的乱码，在页面和侧栏合计中都按 0 计算。旧版本已经存成乱码的合计，会在下次启动时从会话文件重新累加。

### 启动更快，搜索索引不再无限变大（#327、#328、#331）

- 应用一启动，搜索就可用。重启后的第一次搜索以前要等待：1200 个对话时约 2 秒，4800 个时约 4 秒（要检查整个索引文件）；现在约 0.1 秒就有结果。损坏的索引仍会被发现：崩溃或强制退出之后会检查整个文件，之后遇到坏页则把文件移到一旁并重建。
- 删除对话后，搜索索引会把空间还回去：1200 个对话删到只剩三个时，索引是 24 MB 而不是 230 MB，它的日志文件也不再停留在 137 MB。整理在后台进行，期间搜索照常响应。
- 搜索不再找出在应用关闭期间被删除或移动的对话（以前点开这样的结果会失败）。

### 修复：智能体忙碌时侧边栏停止刷新（#329）

- 对话正在被写入时，对话列表现在至少每 1.5 秒刷新一次，不再等所有写入都停下来。

### 修复：打开很长的子智能体记录会让整个应用卡住（#330）

- 子智能体的记录现在在服务器主线程之外读取。打开一个 58 MB 的记录，以前会让所有对话的发送、停止和流式输出停顿 0.7 秒（300 MB 时 4 秒）；现在它们不再受影响。
