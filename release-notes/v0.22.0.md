## English

### The built-in browser comes with the Mac app, and runs in Chrome's sandbox

The seven findings v0.21.0 left open for a decision are decided and fixed, together with one more found along the way. The tests that failed by chance in CI were tracked down one by one; seven of them were real bugs, fixed below. omp 18.17.0, out since, works with this version.

What you are most likely to notice:

- **The Mac app ships its browser.** CEF, the browser the agents of your conversations use in the app, is now inside the app (`Contents/Frameworks`) and is updated with it: there is nothing to install in Settings › Browser any more, which shows CEF's version and Clear browser data. The pages it opens run in Chrome's macOS sandbox, as in Chrome itself. The download is bigger for it (the dmg is about 189 MB instead of about 49 MB). The copies earlier versions downloaded into the data folder (about 330 MB each) are removed when the app starts.
- **A browser that is off costs nothing.** While Settings › Browser › Use the built-in browser is off when the app starts, the app does not load CEF at all (#188). Turning it on then restarts the app, as Clear browser data does.
- **A page signed in through Cloudflare Access can change the guard and the guidance.** Such a page is yours, so it may now change Settings › Safety (the guard's mode and its reviewer), a conversation's own guard, and the guidance and its templates, as the page on your computer may. A page on the network that holds only the token still may not. The Guard page (every risky call with its folder and the reviewer's reasons), the guidance conflict check and the remote access settings, including "Confirm risky commands from remote pages", stay on your computer.
- **Send feedback is in the sidebar again**, under the pages (an icon when the sidebar's foot is folded). It was only in Settings, the command palette and the shortcuts card, and people did not find it.

### Every fix

- The Mac app's built-in browser ran its pages without Chrome's sandbox (#168)
- The browser's page list kept a page's first title (its address) when the page set its title later (#187)
- The @ completion offered a page that is not on this computer dotfiles and names that look like secrets, which its Files tab hides (#57)
- Restoring or importing over existing files could not work on Windows: the backups and the restore assumed POSIX paths (#77)
- The built-in browser's page could not be reached and left with the keyboard: it is now a tab stop, Enter or Space gives it the keyboard and Ctrl+F6 takes it back (#113)
- Try again after a failed omp install showed the old failure instead of running the install again (#122)
- A signing keychain that did not open was deleted and made anew, which lost the permissions macOS had given the app (#162)
- `omp-webui --stop` did not run the server's shutdown on Windows (#176)
- The Guidance tab put the conversation's text back over what was typed right after a save
- Opening New chat again before the conversation it had just started was shown reused that conversation's process instead of starting a new one
- New chat's project-name field could take the cursor from the message box while you were typing, so the text went into the folder name
- An app update that failed could stay stuck for good, refusing every later install, when a file it made could not be removed (Windows holds a program it just ran)
- A Windows update refused for its version left the folder it had unpacked beside the app when Windows still held the program it had just tried
- On Windows a mode or setting change of a conversation could fail (EPERM) when omp was reading its settings file at that moment
- On a phone, New chat's Guidance chip did nothing: the pick was refused for a page that is not on the computer and the error was never shown, and on iOS the first tap only showed the template's preview. A refused pick is now a toast, the chip says why when it cannot change, and a tap picks at once
- When omp ended, the reason the page was shown could be cut off on a loaded machine

### Tests and CI

- The tests that failed by chance in the last 100 CI runs were looked into one by one and fixed at their cause, among them the side-question cancel test (#43), the WebSocket tests on Windows (a Bun bug that loses a socket's data while a test waits through `expect(…).rejects`, oven-sh/bun#44429), process numbers Windows hands out again, and ports taken on one address only. One could not be reproduced: the preset role tests on Windows, where `omp config` once ended with an error and said nothing; they now print omp's and the server's own words when they fail.
- CI keeps Playwright's system packages and browsers in its cache per Ubuntu release, so the end-to-end jobs no longer hang for 40 minutes on a slow mirror or fail on runners that moved to Ubuntu 26.04; the export tests take omp's pinned viewer scripts from a cache instead of the network.
- omp 18.17.0 gives up at once on an HTTP 402 (out of credit) instead of waiting for the limit's reset; the tests' stand-in providers now refuse with the status the running omp waits out (429 from 18.17 on, 402 before).

## 中文

### 内置浏览器随 Mac 应用一起提供，并运行在 Chrome 的沙盒里

v0.21.0 中留待决定的七个问题都已决定并修复，另外还修复了过程中发现的一个问题。CI 中偶发失败的测试都逐一查明了原因；其中七个是真正的缺陷，修复列在下面。之后发布的 omp 18.17.0 可以和这个版本一起使用。

你最可能注意到的：

- **Mac 应用自带浏览器。** CEF 是对话中的智能体在应用里使用的浏览器，现在放在应用内部（`Contents/Frameworks`），随应用一起更新：设置 › 浏览器里不再需要安装任何东西，只显示 CEF 的版本和“清除浏览器数据”。它打开的页面运行在 Chrome 的 macOS 沙盒里，和 Chrome 本身一样。下载因此变大（dmg 约 189 MB，原来约 49 MB）。旧版本下载到数据文件夹里的副本（每份约 330 MB）会在应用启动时删除。
- **关闭的浏览器不占资源。** 如果应用启动时设置 › 浏览器 › “使用内置浏览器”是关闭的，应用完全不会加载 CEF（#188）。之后打开它会重启应用，和“清除浏览器数据”一样。
- **通过 Cloudflare Access 登录的页面可以更改守卫和指引。** 这样的页面就是你本人的，所以现在可以和电脑上的页面一样，更改设置 › 安全（守卫的模式和审查模型）、单个对话自己的守卫，以及指引和指引模板。只持有令牌的网络页面仍然不能更改。守卫页面（每个有风险的调用，连同所在文件夹和审查模型的理由）、指引冲突检查和远程访问设置（包括“从远程页面确认有风险的命令”）仍然只能在电脑上操作。
- **“发送反馈”回到了侧边栏**，在页面列表下面（侧边栏底部折叠时显示为图标）。以前它只在设置、命令面板和快捷键卡片里，大家找不到。

### 全部修复

- Mac 应用的内置浏览器在没有 Chrome 沙盒的情况下运行页面（#168）
- 页面之后再设置标题时，浏览器的页面列表仍显示它的第一个标题（它的地址）（#187）
- 不在这台电脑上的页面里，@ 补全会列出点开头的文件和看起来像机密的名称，而文件标签页会隐藏它们（#57）
- 在 Windows 上无法恢复，也无法导入覆盖已有文件：备份和恢复都假定是 POSIX 路径（#77）
- 无法用键盘进入和离开内置浏览器的页面：现在它是一个 Tab 停靠点，按 Enter 或空格让它接收键盘，按 Ctrl+F6 交回（#113）
- omp 安装失败后点“重试”显示的是旧的失败，而不是重新安装（#122）
- 打不开的签名钥匙串会被删除并重建，导致 macOS 给应用的权限丢失（#162）
- 在 Windows 上，`omp-webui --stop` 不会执行服务器的关闭流程（#176）
- “指引”标签页在保存后，会把对话原来的文字盖回到刚输入的内容上
- 在新对话刚启动的对话页面出现之前再次打开“新对话”，会沿用那个对话的进程，而不是启动新进程
- 输入消息时，“新对话”的项目名称输入框可能抢走光标，文字被输入到文件夹名称里
- 应用更新失败时，如果它生成的某个文件删不掉（Windows 会占用刚运行过的程序），更新会一直卡住，之后的每次安装都被拒绝
- Windows 更新因版本不符被拒绝时，如果 Windows 仍占用刚试过的程序，解压出的文件夹会留在应用旁边
- 在 Windows 上，如果 omp 正好在读取对话的设置文件，更改对话的模式或设置可能失败（EPERM）
- omp 结束时，在负载高的机器上，页面显示的原因可能不完整
- 在手机上，“新对话”的“指引”按钮点了没反应：不在这台电脑上的页面选择会被拒绝，而错误从不显示；在 iOS 上第一次点按只会显示模板预览。现在被拒绝时会弹出提示，不能更改时按钮会说明原因，点一下就能选中

### 测试和 CI

- 最近 100 次 CI 运行中偶发失败的测试都逐一排查，并在原因处修复，包括取消旁问的测试（#43）、Windows 上的 WebSocket 测试（Bun 的一个缺陷：测试通过 `expect(…).rejects` 等待时会丢失套接字数据，oven-sh/bun#44429）、Windows 很快重复使用的进程号，以及只在一个地址上被占用的端口。有一个没能复现：Windows 上的预设角色测试，`omp config` 曾出错退出且没有任何输出；现在失败时会打印 omp 和服务器自己的说明。
- CI 按 Ubuntu 版本缓存 Playwright 需要的系统软件包和浏览器，端到端任务不再因为镜像太慢而卡住 40 分钟，也不会在换到 Ubuntu 26.04 的运行器上失败；导出测试从缓存而不是网络读取 omp 固定版本的查看器脚本。
- omp 18.17.0 遇到 HTTP 402（额度用尽）时会立即放弃，而不是等额度重置；测试用的模拟服务商现在按所运行的 omp 会等待的状态码拒绝（18.17 起是 429，之前是 402）。
