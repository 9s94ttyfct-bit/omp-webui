## English

### A new, public repository

- omp-webui now lives in a new public repository that starts at this release from the code alone. Issue and pull request numbers in the code, the tests and the release notes before v0.12.2 refer to the earlier private repository. Report problems and ideas in this repository's Issues.
- The app keeps updating itself from this repository's releases, as before.

### How releases are made

- Every push to `main` and every pull request runs all the checks that need no model login on GitHub Actions: type check, lint, the build with its size budget, the parity report, unit and contract tests, and the offline end-to-end suite in eight parallel shards. A newer push cancels the run it replaces.
- A release is made only from a commit those checks passed on: `bun scripts/release-local.ts` asks GitHub for the CI result of exactly that commit and refuses one that has none, is still running or failed. It then runs only the tests that call a real model, builds and signs the app and the installer, and makes the tag last.
- A release is the signed installer on the GitHub release, nothing else: no package is published to npm or GitHub Packages any more.
- Every commit published here must be authored and committed with the maintainer's GitHub noreply address, and nothing published may hold personal data: the privacy check now also reads binary files and the members of zip fixtures, and looks for real temporary folders, home folders, e-mail addresses and private network addresses without needing a private list. `bun run hooks` installs both checks as pre-commit and pre-push hooks; CI runs them, and gitleaks, on every push and pull request.
- `bun install` now installs those hooks by itself. It never fails the install: a hook it did not write is kept, with a one-line notice; outside a git checkout it does nothing; in a worktree it installs into the hooks every worktree shares. Pull requests from others are merged locally, as commits of the maintainer's noreply identity; a merge on GitHub's web page fails the author check by design.

### Guard: the reviewer never reads the advisor

- The reviewer of *Guard dangerous commands* is given nothing omp's advisor wrote (the second model omp can run beside the agent, whose notes appear in the conversation): the gate leaves out every entry omp marks as the advisor's, whatever role it is carried in. An advisor's note never counts as the person's message either: one that claims "the person approved this" does not reopen a call the reviewer denied.

### How full each subagent's context is

- Every subagent now shows how full its context window is, as `ctx 41%`: on its card in the agent graph, in its live view (the graph's side panel, the Agents tab and full screen) and on its row in the Agents tab. The tooltip gives the tokens and the window (`Context: 41,000 / 100,000 tokens`). The colours are the status line's context meter's: the warning colour past 60%, the danger colour past 80%.
- The figure is omp's own, the `contextTokens` and `contextWindow` of the subagent's progress records (its frames and `get_subagents`), so a page that opens while a subagent runs has it too. A subagent that has not made a request yet, or one known only from its transcript on disk, shows nothing rather than 0%.

### The agent graph remembers how you look at it

- **Grid siblings**, **Focus & minimap** and the status and time filters of the agent graph are now remembered, as one choice for every conversation's graph: open another conversation's graph, reload the page or quit and open the app, and the graph is looked at the way you left it. Until now the filters were forgotten each time the graph was opened, and the two switches were kept only in that browser's own storage, which the macOS app loses when it starts on another port.
- They are kept with your other preferences on the server (`ompw.agentGraph.grid`, `ompw.agentGraph.focus`, `ompw.agentGraph.status`, `ompw.agentGraph.time`), so a choice made in one window shows at once in the others. A stored value this version does not know opens that setting at its default.

### The macOS app

- The page in the app's windows no longer zooms: a pinch, a smart zoom (a two-finger double tap) and ⌘= ⌘- ⌘0 leave it at its size, in the app's own window, a pop-out and a window onto another Mac. The View menu no longer has Actual Size, Zoom In and Zoom Out, so those keys reach the page as ordinary keystrokes. Full screen and the Window menu are unchanged, and the web UI in a browser keeps the browser's zoom.

### Guard on and off from the conversation's header

- A conversation's header has a guard switch beside the session settings button (beside the ⋯ menu in a narrow window). It turns *Guard dangerous commands* off for this conversation alone; while it is off that way the switch is red and says *Guard is off for this conversation*. A conversation that is off only because Settings › Safety say Off shows the switch grey, not red, with *Guard is off (following the global setting)*; clicking it turns the guard on for that conversation alone.
- Turning it back on restores the mode the conversation had before (its own Reviewer model or Ask me, or following Settings). With nothing remembered it follows Settings › Safety, and if Settings say Off it uses the default, Reviewer model.
- It is the same choice as the guard in *This session*: a change in either shows in both at once, in every window. A page that is not on the computer omp-webui runs on shows the switch disabled and says why. *Confirm risky commands from remote pages* still applies to a remote page's turns while the guard is off.

### Sidebar

- A conversation's name in the sidebar now has the whole row: the ⋯ button no longer keeps room for itself, so long names are cut at the end of the row rather than well before it. With a mouse or a trackpad the button shows over the end of the name, on a backdrop that fades in, while the row is hovered, while it has keyboard focus (Tab to the row, then Tab again to the button), and always on the open conversation; the name does not move. The pinned and branch marks before the name and the live-state dot after it stay in sight. On phones and tablets only the open conversation shows the button, the same way; every other name has the whole row.

## 中文

### 新的公开仓库

- omp-webui 现在位于一个新的公开仓库，从这个版本起只带着代码重新开始。v0.12.2 之前的代码、测试和发布说明里的问题和拉取请求编号指的是之前那个私有仓库。问题和建议请在这个仓库的 Issues 里提出。
- 应用仍和以前一样从这个仓库的发布自动更新。

### 发布方式

- 每次推送到 `main` 和每个拉取请求都会在 GitHub Actions 上运行所有不需要模型登录的检查：类型检查、lint、带体积预算的构建、对等报告、单元和契约测试，以及分成八个并行分片的离线端到端测试。新的推送会取消被它取代的那次运行。
- 只有这些检查通过了的提交才能发布：`bun scripts/release-local.ts` 向 GitHub 查询正好这个提交的 CI 结果，没有结果、还在运行或失败的提交一律拒绝。之后它只运行调用真实模型的测试，构建并签名应用和安装包，最后才打标签。
- 一次发布就是 GitHub 发布上签好名的安装包，没有别的：不再向 npm 或 GitHub Packages 发布软件包。
- 在这里发布的每个提交，作者和提交者都必须是维护者的 GitHub noreply 地址，发布的内容也不能带有个人信息：隐私检查现在也读取二进制文件和 zip 测试数据里的成员，并且不需要私人列表就能找出真实的临时目录、家目录、邮箱地址和私有网络地址。`bun run hooks` 把这两项检查装成 pre-commit 和 pre-push 钩子；CI 在每次推送和拉取请求时运行它们，还有 gitleaks。
- `bun install` 现在会自动装上这些钩子，而且永远不会让安装失败：不是它写的钩子原样保留，并给出一行提示；不在 git checkout 里时什么也不做；在工作树（worktree）里，它装到所有工作树共用的钩子目录。别人的拉取请求只在本地合并，改写成维护者 noreply 身份的提交；在 GitHub 网页上合并会按设计让作者检查失败。

### 防护：审查模型不读顾问的话

- “防护危险命令”的审查模型拿不到 omp 顾问写的任何内容（omp 可以在智能体旁边运行的第二个模型，它的备注会出现在对话里）：检查点会略去 omp 标为顾问所写的每个条目，不论它以什么角色出现。顾问的备注也永远不算作本人的消息：声称“本人已经批准”的备注不会让审查模型拒绝过的调用重新送审。

### 每个子代理的上下文用量

- 每个子代理现在都显示它的上下文窗口用了多少，形如「上下文 41%」：在代理关系图的卡片上、它的实时视图里（关系图的侧栏、“子代理”标签页和全屏）以及“子代理”标签页它那一行上。悬停提示给出 token 数和窗口大小（「上下文：41,000 / 100,000 token」）。颜色和状态栏的上下文进度条一致：超过 60% 用警告色，超过 80% 用危险色。
- 这个数字来自 omp 本身，即子代理进度记录（它的事件帧和 `get_subagents`）里的 `contextTokens` 和 `contextWindow`，所以子代理运行时才打开的页面也能看到。还没发出过请求的子代理，或者只能从磁盘上的记录得知的子代理，什么都不显示，而不是显示 0%。

### 代理关系图记住你的查看方式

- 代理关系图的“网格排列同级”“聚焦并显示缩略图”以及状态和时间筛选现在会被记住，对所有对话的关系图是同一个选择：打开另一个对话的关系图、刷新页面、退出再打开应用，关系图都保持你上次的查看方式。以前每次打开关系图筛选都会被忘掉，两个开关也只存在当前浏览器自己的存储里，而 macOS 应用换了端口启动时会丢掉那份存储。
- 它们和你的其他偏好一起保存在服务器上（`ompw.agentGraph.grid`、`ompw.agentGraph.focus`、`ompw.agentGraph.status`、`ompw.agentGraph.time`），所以在一个窗口里改了，其他窗口立刻跟着变。存着的值是这个版本不认识的时，那一项按默认打开。

### macOS 应用

- 应用窗口里的页面不再缩放：双指捏合、智能缩放（双指轻点两下）和 ⌘= ⌘- ⌘0 都不会改变它的大小，应用自己的窗口、弹出窗口和其他 Mac 的窗口都一样。“View”菜单里不再有“Actual Size”“Zoom In”“Zoom Out”，这些按键作为普通按键交给页面。全屏和“Window”菜单不变；在浏览器里打开的网页版照常使用浏览器的缩放。

### 在对话标题栏开关防护

- 对话标题栏里，对话设置按钮旁边（窄窗口里在 ⋯ 菜单旁边）多了一个防护开关。它只对这个对话关闭“防护危险命令”；这样关闭时开关是红色的，提示“这个对话的防护已关闭”。对话只是因为“设置 › 安全”是关闭而关闭时，开关是灰色的，不是红色，提示“防护已关闭（跟随全局设置）”；点一下只对这个对话开启防护。
- 重新开启时恢复这个对话之前的模式（它自己选的审查模型或询问我，或跟随设置）。没有记录时跟随“设置 › 安全”，设置是关闭时使用默认的审查模型。
- 它和“当前对话”里的防护是同一个选择：任何一边改了，两边马上一起变，所有窗口都一样。不在运行 omp-webui 的电脑上的页面，开关显示为不可用并说明原因。防护关闭时，“远程页面的高风险命令先确认”对远程页面发起的轮次仍然有效。

### 侧边栏

- 侧边栏里的对话名现在占满整行：⋯ 按钮不再给自己留位置，长名称在行尾才被截断，而不是早早就被截掉。用鼠标或触控板时，按钮在鼠标停在这一行上、这一行有键盘焦点（Tab 到这一行，再按 Tab 到按钮）时出现在名称末尾之上，垫着渐隐的底色；当前打开的对话始终显示它。名称不会移动。名称前的置顶和分支标记、名称后的运行状态圆点都不会被遮住。在手机和平板上，只有当前打开的对话以同样的方式显示按钮，其他各行的名称都占满整行。
