## English

### A new, public repository

- omp-webui now lives in a new public repository that starts at this release from the code alone. Issue and pull request numbers in the code, the tests and the release notes before v0.12.2 refer to the earlier private repository. Report problems and ideas in this repository's Issues.
- The app keeps updating itself from this repository's releases, as before.

### How releases are made

- Every push to `main` and every pull request runs all the checks that need no model login on GitHub Actions: type check, lint, the build with its size budget, the parity report, unit and contract tests, and the offline end-to-end suite in eight parallel shards. A newer push cancels the run it replaces.
- A release is made only from a commit those checks passed on: `bun scripts/release-local.ts` asks GitHub for the CI result of exactly that commit and refuses one that has none, is still running or failed. It then runs only the tests that call a real model, builds and signs the app and the installer, and makes the tag last.
- A release is the signed installer on the GitHub release, nothing else: no package is published to npm or GitHub Packages any more.
- Every commit published here must be authored and committed with the maintainer's GitHub noreply address, and nothing published may hold personal data: the privacy check now also reads binary files and the members of zip fixtures, and looks for real temporary folders, home folders, e-mail addresses and private network addresses without needing a private list. `bun run hooks` installs both checks as pre-commit and pre-push hooks; CI runs them, and gitleaks, on every push and pull request.
- `bun install` now installs those hooks by itself. It never fails the install: a hook it did not write is kept, with a one-line notice; outside a git checkout it does nothing; in a worktree it installs into the hooks every worktree shares. Pull requests from others are merged locally, as commits of the maintainer's noreply identity; a merge on GitHub's web page fails the author check by design.

### Sidebar

- A conversation's name in the sidebar now has the whole row: the ⋯ button no longer keeps room for itself, so long names are cut at the end of the row rather than well before it. With a mouse or a trackpad the button shows over the end of the name, on a backdrop that fades in, while the row is hovered, while it has keyboard focus (Tab to the row, then Tab again to the button), and always on the open conversation; the name does not move. The pinned and branch marks before the name and the live-state dot after it stay in sight. On phones and tablets only the open conversation shows the button, the same way; every other name has the whole row.

## 中文

### 新的公开仓库

- omp-webui 现在位于一个新的公开仓库，从这个版本起只带着代码重新开始。v0.12.2 之前的代码、测试和发布说明里的问题和拉取请求编号指的是之前那个私有仓库。问题和建议请在这个仓库的 Issues 里提出。
- 应用仍和以前一样从这个仓库的发布自动更新。

### 发布方式

- 每次推送到 `main` 和每个拉取请求都会在 GitHub Actions 上运行所有不需要模型登录的检查：类型检查、lint、带体积预算的构建、对等报告、单元和契约测试，以及分成八个并行分片的离线端到端测试。新的推送会取消被它取代的那次运行。
- 只有这些检查通过了的提交才能发布：`bun scripts/release-local.ts` 向 GitHub 查询正好这个提交的 CI 结果，没有结果、还在运行或失败的提交一律拒绝。之后它只运行调用真实模型的测试，构建并签名应用和安装包，最后才打标签。
- 一次发布就是 GitHub 发布上签好名的安装包，没有别的：不再向 npm 或 GitHub Packages 发布软件包。
- 在这里发布的每个提交，作者和提交者都必须是维护者的 GitHub noreply 地址，发布的内容也不能带有个人信息：隐私检查现在也读取二进制文件和 zip 测试数据里的成员，并且不需要私人列表就能找出真实的临时目录、家目录、邮箱地址和私有网络地址。`bun run hooks` 把这两项检查装成 pre-commit 和 pre-push 钩子；CI 在每次推送和拉取请求时运行它们，还有 gitleaks。
- `bun install` 现在会自动装上这些钩子，而且永远不会让安装失败：不是它写的钩子原样保留，并给出一行提示；不在 git checkout 里时什么也不做；在工作树（worktree）里，它装到所有工作树共用的钩子目录。别人的拉取请求只在本地合并，改写成维护者 noreply 身份的提交；在 GitHub 网页上合并会按设计让作者检查失败。

### 侧边栏

- 侧边栏里的对话名现在占满整行：⋯ 按钮不再给自己留位置，长名称在行尾才被截断，而不是早早就被截掉。用鼠标或触控板时，按钮在鼠标停在这一行上、这一行有键盘焦点（Tab 到这一行，再按 Tab 到按钮）时出现在名称末尾之上，垫着渐隐的底色；当前打开的对话始终显示它。名称不会移动。名称前的置顶和分支标记、名称后的运行状态圆点都不会被遮住。在手机和平板上，只有当前打开的对话以同样的方式显示按钮，其他各行的名称都占满整行。
