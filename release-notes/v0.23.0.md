## English

### Let this Mac's agent run commands on another computer

- **Run commands on a computer from your Macs list.** Turn on **Remote computers** in a conversation's session controls and tick the computers it may use. That conversation's agent gets one more tool, `remote_run`, which runs a shell command on the chosen computer and gets back its output and exit code. The model, the conversation and its approvals stay on this Mac. Use it to look after a server with the stronger models this Mac has.
- **It uses the connection you already have.** The command goes through the other computer's own tunnel and runs in a login shell there, as if you typed it into its Terminal from a window signed in through Cloudflare Access. Nothing needs to change on the other computer (it needs v0.22.5 or later) or in Cloudflare.
- **Sign-in comes from the app's window onto that computer.** The Mac app hands that window's Cloudflare Access sign-in to this Mac's server, which keeps it in memory only. When it lapses (after the Access application's session duration, 24 hours unless you set it longer), open that computer's window from the Macs list and sign in again; the Macs list and the conversation show until when each computer is signed in.
- **Off everywhere until you turn it on.** Each conversation reaches only the computers you ticked for it, and only your own pages (this Mac's, and one signed in through Cloudflare Access) can tick them; an agent cannot. A conversation that a page holding only the access token has been on cannot use it.
- **Approvals as for any command.** `remote_run` follows the conversation's approval mode like `bash`, and the guard reads every remote command with no safe folder: deleting or overwriting anything there, `sudo`, `~/.ssh` and the like are held for your Allow. The approval names the computer.
- **Limits.** One command at a time, each in a fresh shell (nothing carries over between calls; pass `cwd`), no input after it starts, 120 s by default and at most an hour, the last 64 KB of output. Computers running Windows are not supported yet.

## 中文

### 让这台 Mac 的智能体在另一台电脑上执行命令

- **在 Mac 列表里的电脑上执行命令。** 在对话的会话控制里打开“远程电脑”，勾选它可以用的电脑。这个对话的智能体会多一个工具 `remote_run`：在选中的电脑上执行 shell 命令，取回输出和退出码。模型、对话和批准都留在这台 Mac 上。适合用这台 Mac 上更强的模型管理服务器。
- **用的是现有的连接。** 命令经那台电脑自己的隧道送过去，在那里的登录 shell 里运行，就像你在经 Cloudflare Access 登录的窗口里打开它的终端输入一样。那台电脑（需要 v0.22.5 或更新）和 Cloudflare 都不用改。
- **登录来自应用里那台电脑的窗口。** Mac 应用把那个窗口的 Cloudflare Access 登录交给这台 Mac 的服务器，只放在内存里。过期后（Access 应用的会话时长，默认 24 小时，可在 Cloudflare 里调长），从 Mac 列表打开那台电脑的窗口重新登录即可；Mac 列表和对话里会显示每台电脑登录到什么时候。
- **默认处处关闭。** 每个对话只能用你给它勾选的电脑，而且只有你自己的页面（这台 Mac 上的，以及经 Cloudflare Access 登录的）能勾选，智能体不能。只持有访问令牌的页面待过的对话不能用。
- **批准和普通命令一样。** `remote_run` 像 `bash` 一样跟随对话的批准模式；防护机制看远程命令时不把那边任何目录当安全目录：删除或覆盖文件、`sudo`、`~/.ssh` 等都会等你点允许。批准卡片会写明是哪台电脑。
- **限制。** 每次一条命令，各在一个新 shell 里运行（调用之间不保留状态，用 `cwd` 指定目录），开始后不能再输入，默认 120 秒、最长 1 小时，输出取最后 64 KB。暂不支持运行 Windows 的电脑。
