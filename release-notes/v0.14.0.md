## English

### omp 18.12.3 or newer

- omp-webui now supports omp `>=18.12.3 <19.0.0` (it was `>=18.11.0`). An older omp is warned about on every page, as any omp outside the range is; update it from Settings › App & system › omp.
- The permission mode **Ask and remember** came with omp 18.12.3. With an older omp it is shown disabled, with the omp version it needs, in the conversation's permission picker, in Settings and in the first-time setup, and the server refuses it: before, picking it on such an omp left the conversation running in another mode than the one shown.
- Behind the scenes, every change is now tested on both the oldest supported omp and the latest one, and the tests run against the latest omp every day, so an omp release that breaks omp-webui is found the day it comes out.

### Fix: Settings says where a broken config.yml went, whoever moved it

- When omp's `config.yml` cannot be read, the first omp to read it moves it aside (`config.yml.broken-…`) and starts from its defaults. Settings › Models showed a notice naming that copy only when omp-webui's own read was the one that moved it; when another omp did (a running conversation, omp in a terminal), Settings showed omp's defaults as if they were your settings. Now the notice appears either way, until a valid `config.yml` is read again or the copy is removed. This also fixes the intermittent test failure of #15.

### Fix: the Guard and remote confirmation see more risky command shapes

- The check that decides which tool calls go to the Guard's reviewer (and, with *Confirm risky commands from remote pages* on, to the remote page) let some command shapes through without asking anyone. It now flags them, with three new kinds on the Guard page's Policy tab and in the confirmation:
  - **A command put together when it runs**: a variable or a substitution where the command goes (`r=rm; $r -rf ~`, `$(echo rm) -rf ~`), `eval` or `bash -c` of something only known then, and any script piped into a shell (`printf '…' | sh`, `base64 -d … | bash`). A script written out before the pipe is read as well.
  - **Running commands on another computer**: `ssh host '…'` (what it runs there is read too), and what ssh runs here through `ProxyCommand`.
  - **Scheduled jobs and services**: `crontab -r`, `crontab -e`, a new crontab, `at`, `systemctl stop/disable/…`.
  - **Reading keys and passwords** now also covers printing a stored password or token: `security find-generic-password -w`, `security dump-keychain`, `gh auth token`, `gcloud auth print-access-token` and the like.
- A variable or `$(…)` used as an argument (`echo $(date)`, `ls "$HOME"`) and pipes into what is not a shell (`git log | less`) are not affected. Harmless commands of these shapes (`$EDITOR file`) now go to the reviewer too; set a kind to Allow on the Guard page if you prefer.

### Fix: a conversation open in a terminal is recognised with PI_CONFIG_DIR set

- Renaming or deleting a conversation that omp in a terminal has open for writing is refused, because omp would save the new name to a copy of it, or delete the file under that omp. omp-webui looked for omp's claim on the conversation only in `~/.omp`, so with `PI_CONFIG_DIR` set (or with omp's state under `$XDG_STATE_HOME`) it missed it, and the rename or delete went ahead. It now asks omp itself (`omp session lease`, omp 18.14.1 and later), and with an older omp it looks where omp keeps the claim. The same check keeps an import from **Move to another computer** from replacing a conversation a terminal is writing.

### Fix: Usage & cost reads omp's statistics with PI_CONFIG_DIR set

- omp keeps its config folder, and the statistics database the Usage & cost page reads for 7 days, 30 days and All time, under your home folder: `PI_CONFIG_DIR` names a folder of the home, even when it is written as an absolute path. omp-webui took the value as a full path, so with `PI_CONFIG_DIR` set it looked in the wrong place and the page fell back to omp's own 24 hours. It now looks where omp keeps the database.

### Fix: a conversation follows edits of its preset (#4)

- A conversation switched to a preset kept the preset's models as they were when it was switched: after the preset was edited (Settings, `config.yml`, `omp config set`), its subagents still got the old models until the preset was picked again. Now a running, paused or saved conversation on a preset takes the edit: its subagents get the new models and its own model moves with the preset's default. A conversation you moved to another model with the model picker (*Custom*) keeps what it has, and one whose preset was deleted says so on its chip (*name (deleted)*).

### Newer omp: typed /compact, secret prompts, streaming

- A compaction you start by typing `/compact`, or that an extension starts, now shows *Compacting context…* and how it ended, like an automatic one, and the conversation is not closed as idle while it runs (omp 18.13.3 and later).
- An extension that asks for a token or a password (omp 18.13.2 `secret` prompts) gets a masked field: what you type is hidden, and the browser neither suggests nor keeps it.
- While a reply streams, a reply that omp starts again no longer leaves the abandoned text on screen, narration shows as answer text from the start, and a picture appears as soon as it is ready (omp 18.13.2 and later).

### Parallel subagents: how many run at once

- A new **Parallel subagents** setting decides how many subagents one conversation runs at once (omp's own `task.maxConcurrency`). Set it for every new conversation in Settings › Models (it is omp's setting, shared with the terminal; omp's default is 32), or for one conversation in its session settings › Advanced: 1 to 16, Unlimited, or Default. A change applies to the next subagent that starts, without restarting the conversation.
- When a task call starts more subagents than the limit, omp runs the rest one after another as slots free up. Those waiting now show in the Agents tab as *queued*, after the running ones, with a note saying why; the Agent graph draws them dashed and counts them.

### The agent can restart its own wedged process

- A conversation's agent can now get itself out of a process that hangs (for example bash calls that never return while its other tools still work) without you: it calls `restart_session` with a reason and what to do next, and when its turn ends omp-webui ends its omp together with everything it started (background jobs, dev servers, MCP servers) and continues the same conversation in a fresh process, which is told what the agent asked to do next. The conversation shows *Restarted by the agent: reason* where it happened. History, todos and the goal are kept.
- It is refused while a question or approval waits for you, while the conversation is paused, and while subagents run (unless the agent asks to end them too), and it happens at most 3 times per conversation per hour.
- **This session › Restart the process › Force restart** does the same for you: it stops the turn and restarts the conversation's process, for a conversation that hangs.

### Groundwork for the server on Windows

- Everything the server asks of the operating system now goes through one platform layer, with a list of what each system can do, the first step towards running the server on Windows. Nothing changes on macOS or Linux.
- On Windows, remote access stays off: it waits until the risk check that confirms risky commands from another device understands Windows paths. Pausing a conversation is not available there either.
- For contributors: `bun run lint` now includes `scripts/check-platform.ts`, which refuses `process.platform` checks and macOS or POSIX commands outside `server/platform/` (a line that must stay says why with `// platform-allow: <reason>`), and tests skip by what the machine can do rather than by its name.

### CI notifications in the macOS app

- The CI tab's bell (*Notify when a run of this branch finishes*) is now in the macOS app too. The app shows the notification itself, and clicking it opens the CI tab. A page can ask the app for this one kind of notification only; any other is refused, as before. If macOS blocks the app's notifications, the tab says where to allow them (System Settings › Notifications › omp-webui).

### Markdown and accessibility fixes

- **Links to sections**: in the Markdown editor's preview, headings get the ids GitHub gives them, so a table of contents (`[Install](#install)`) scrolls to its heading, and a link to `guide.md#install` opens that file at the heading instead of at its top.
- **Task lists** in replies and in the Markdown editor: a screen reader names each checkbox by its task ("Write the tests, checkbox, checked"), not just "checkbox".
- **Escape on the Markdown editor's error screen**: when a file cannot be opened, one Escape closes the editor. Before, the first one only closed the Close button's tooltip.
- **Changes view**: on added and removed lines, the line numbers are darker and the code colours are mixed a little toward the text colour, so both meet the 4.5:1 contrast minimum in every palette, light and dark (the tint behind those lines made some of them too faint).
- **Todo list**: when an edit cannot be made (a task with no text, a task or phase that is no longer there), the reason is now shown in the page's language. Before, it was always in English.

### Fix: the quota floor holds the first step of a turn too

- When a conversation began a turn and the app did not know the provider's quota yet (the first look takes a few seconds), a fast model's first tool step could go through past the floor; only the next one was held. That first step now waits for the look, and is held when the floor is reached, or goes on at once when it is not.

### The sidebar's list toolbar stays put

- The row under the search field (the Pinned group's fold, the archive, the order and **Select**) used to be the list's first row and scrolled away with it. It now stays above the conversations while they scroll, so Select and the order are at hand however far down you are. Date headings still scroll with the rows they head.

### Fix: a Guidance template can be picked in New chat (#16)

- The Guidance list in New chat jumped up and down as the pointer moved over it: the text of the template under the pointer was added below the list, which made the list grow, or turn to the other side of the chip, and put another template under the pointer. A click picked whichever one was there. The text now has its own place in the list from the start (a hint until a template is pointed at), so the list keeps its size and place while it is open, and in a short window its templates scroll inside it.

### Fix: the server no longer holds every conversation's first message

- The conversation list shows the first 240 characters of each conversation's first message, and the server keeps them for as long as it runs. It kept the whole message they were cut from instead: a conversation that began with a pasted log or file held all of it in memory. It now keeps the 240 characters only (40 conversations that began with 1 MB each: 40 MB held before, nothing measurable now). The server's memory when idle and after listing the conversations is now measured against v0.13.0 by the benchmark gate, which fails when it grows more than 5 % (#9).

### For contributors: a test gate that holds on a busy Mac

- `bun run test:release`, and the macOS and live tests the release script runs on the maintainer's Mac (`test:mac`, `test:live`), now start half as many test workers as the Mac has cores, at least 2, instead of one per core; `OMPW_TEST_WORKERS` sets the count (#1). `bun run test`, `test:contract` and `test:all` keep one worker per core.
- Tests that failed on a loaded machine without anything being wrong now wait for what they test, not for a fixed time: the quota-floor tests (#2), the Stop bounds (#10), the hung-omp and omp lifecycle tests (#13). A test server that Bun's test runner ends in the middle of a file is started again, and the next test waits for it (#3). Upload tests no longer depend on how full the disk is (#8), and the memory tests of the family worker no longer see a compile JavaScriptCore still has queued (#12).
- End-to-end runs: a worker removes the conversations the previous spec file wrote, so one or two workers no longer push the fixture rows out of the sidebar (#7), and keeps the ones the next file writes before its first test; the Settings render count no longer counts a process the test itself started (#6); the remote-flow and Settings-help specs wait for what they read, and the palette spec samples the Settings card once it is drawn. The tests that call a real model (`live`, `dialogs`, `subagents-real`) pass against the current omp and Claude Haiku 5.5, and an offline test checks that a new chat's address becomes its file's (#11). Every e2e test and every unit and contract file has a time for the CI split, and a unit test keeps it so.
- The app's icons are rendered from the one master, `macos/icon.png`, by `bun run icons` (`scripts/icons.ts`): the web's favicon, Apple touch icon, 192 and 512 px icons and maskable icon, and the macOS app's iconset, which `bun run app` made with `sips` before. A unit test fails when a committed icon is not what the master renders to (#14). There is no vector source: the 1024 px master is the source.

## 中文

### 需要 omp 18.12.3 或更新版本

- omp-webui 现在支持的 omp 版本是 `>=18.12.3 <19.0.0`（原来是 `>=18.11.0`）。更旧的 omp 会像范围之外的任何 omp 一样，在每个页面上给出提醒；可以在“设置 › 应用与系统 › omp”里更新它。
- 权限模式“询问并记住”是 omp 18.12.3 才有的。omp 更旧时，对话的权限模式选择器、设置和首次设置里都会把它显示为不可选，并写明需要的 omp 版本，服务器也会拒绝它；以前在这样的 omp 上选它，对话实际运行的模式和界面显示的并不一样。
- 在幕后，每次改动现在都会在支持的最旧 omp 和最新 omp 上各测一遍，测试也会每天针对最新的 omp 跑一次，所以某个 omp 新版本弄坏了 omp-webui，当天就能发现。

### 修复：无论是谁挪走了坏掉的 config.yml，设置都会说明它去了哪里

- omp 的 `config.yml` 读不了时，第一个读到它的 omp 会把它挪到一边（`config.yml.broken-…`），然后从默认设置开始。以前只有当挪走它的是 omp-webui 自己那次读取时，“设置 › 模型”才会显示一条提示，写明那份副本在哪里；如果是别的 omp（正在运行的对话、终端里的 omp）先挪走了它，设置页面就把 omp 的默认值当成你的设置来显示。现在两种情况都会显示这条提示，直到重新读到有效的 `config.yml`，或者那份副本被删除为止。这也修好了 #15 里时有时无的测试失败。

### 修复：防护和远程确认能认出更多高风险命令写法

- 决定哪些工具调用要交给防护的审查模型（以及在打开“远程页面的高风险命令先确认”时交给远程页面）的检查，以前会放过几种命令写法，谁都不问。现在会把它们标出来，“防护”页面的“策略”标签和确认卡片里新增了三个类别：
  - **运行时才拼出来的命令**：命令的位置上是变量或替换（`r=rm; $r -rf ~`、`$(echo rm) -rf ~`），对运行时才知道的内容做 `eval` 或 `bash -c`，以及任何用管道交给 shell 的脚本（`printf '…' | sh`、`base64 -d … | bash`）。管道前写明的脚本也会照常读。
  - **在另一台电脑上运行命令**：`ssh host '…'`（在那边运行的命令也会读），以及 ssh 通过 `ProxyCommand` 在本机运行的命令。
  - **定时任务和系统服务**：`crontab -r`、`crontab -e`、换一份新的 crontab、`at`、`systemctl stop/disable/…`。
  - **读取密钥和密码**现在也包括打印保存的密码或令牌：`security find-generic-password -w`、`security dump-keychain`、`gh auth token`、`gcloud auth print-access-token` 等。
- 变量或 `$(…)` 只是参数时（`echo $(date)`、`ls "$HOME"`），以及管道接的不是 shell 时（`git log | less`），都不受影响。这类写法中无害的命令（`$EDITOR file`）现在也会交给审查模型；如果你愿意，可以在“防护”页面把对应类别设为放行。

### 修复：设置了 PI_CONFIG_DIR 时，也能认出终端里开着的对话

- 终端里的 omp 正在写入的对话，在这里重命名或删除会被拒绝，因为 omp 会把新名字存到它的一份副本里，或者在那个 omp 底下删掉文件。以前 omp-webui 只在 `~/.omp` 里找 omp 对这个对话的占用，所以设置了 `PI_CONFIG_DIR`（或 omp 的状态放在 `$XDG_STATE_HOME` 下）时就找不到，重命名或删除照常进行。现在直接问 omp 自己（`omp session lease`，omp 18.14.1 起）；omp 更旧时，就到 omp 存放占用的位置去找。同样的检查也让“迁移到另一台电脑”的导入不会替换掉终端正在写入的对话。

### 修复：设置了 PI_CONFIG_DIR 时，用量与费用也能读到 omp 的统计

- omp 把它的配置文件夹，以及“用量与费用”页面显示 7 天、30 天和全部时间所读的统计数据库，放在你的主目录下面：`PI_CONFIG_DIR` 指的是主目录里的一个文件夹，即使写成绝对路径也一样。以前 omp-webui 把这个值当成完整路径，所以设置了 `PI_CONFIG_DIR` 时会找错位置，页面只能退回到 omp 自己的 24 小时数据。现在会到 omp 存放数据库的地方去读。

### 修复：对话会跟随它所用预设的修改（#4）

- 切换到某个预设的对话，以前一直保留切换那一刻的预设模型：预设被修改之后（设置、`config.yml`、`omp config set`），它的子代理仍然用旧模型，直到再选一次这个预设。现在运行中、已暂停或已保存的对话都会跟上修改：子代理用新的模型，对话自己的模型也随预设的默认模型改变。用模型选择器换过模型的对话（“自定义”）保持不变；预设被删除时，预设按钮会写明（“名称（已删除）”）。

### 新版 omp：输入的 /compact、密钥提示、流式输出

- 在输入框里输入 `/compact`，或者由扩展发起的压缩，现在也会像自动压缩一样显示“正在压缩上下文…”和结果，压缩期间对话不会被当作空闲而关闭（omp 18.13.3 起）。
- 扩展要你输入令牌或密码时（omp 18.13.2 的 `secret` 提示），输入框会隐藏输入的内容，浏览器既不会提示也不会保存它。
- 回复正在流式输出时，omp 重新开始写的回复不再把放弃的文字留在屏幕上，旁白从一开始就显示为回答文字，图片一准备好就显示（omp 18.13.2 起）。

### 并行子代理：同时运行几个

- 新增 **并行子代理** 设置，决定一个对话同时运行多少个子代理（即 omp 自己的 `task.maxConcurrency`）。可以在 设置 › 模型 里为所有新对话设置（这是 omp 的设置，与终端共用；omp 默认是 32），也可以在某个对话的对话设置 › 高级 里单独设置：1 到 16、不限，或默认。改动从下一个启动的子代理起生效，不需要重启对话。
- 一次 task 调用启动的子代理超过上限时，omp 会在有空位时依次运行其余的。这些等待中的子代理现在会在“代理”标签页里排在运行中的后面，标为“排队中”，并说明原因；代理图用虚线画出它们，并计入统计。

### 智能体可以重启自己卡住的进程

- 对话的智能体现在可以不经过你，自己摆脱卡住的进程（例如 bash 调用一直不返回，而其他工具仍然可用）：它用一句原因和接下来要做的事调用 `restart_session`，在它这一轮结束时，omp-webui 结束它的 omp 以及它启动的所有东西（后台任务、开发服务器、MCP 服务器），并在新的进程中继续同一个对话，把智能体要求接着做的事告诉新进程。对话里在发生的位置显示“已由代理重启：原因”。历史、待办和目标都会保留。
- 有问题或批准在等你、对话已暂停、子代理仍在运行（除非智能体要求一并结束它们）时会拒绝；每个对话每小时最多 3 次。
- **当前对话 › 重启进程 › 强制重启** 让你也能这样做：它停止当前轮次并重启对话的进程，用于卡住的对话。

### 为在 Windows 上运行服务器打基础

- 服务器对操作系统的一切请求现在都经过同一个平台层，并列出每个系统能做什么，这是让服务器在 Windows 上运行的第一步。macOS 和 Linux 上什么都不变。
- 在 Windows 上，远程访问保持关闭：要等确认其他设备发来的高风险命令的风险检查能理解 Windows 路径。那里也不能暂停对话。
- 写给贡献者：`bun run lint` 现在包含 `scripts/check-platform.ts`，它不允许在 `server/platform/` 之外判断 `process.platform` 或调用 macOS / POSIX 命令（必须保留的那一行用 `// platform-allow: <原因>` 说明原因）；测试按机器能做什么跳过，而不是按系统名。

### macOS 应用里的 CI 通知

- CI 标签页的铃铛（“这个分支的运行结束时通知我”）现在 macOS 应用里也有了。通知由应用自己显示，点击会打开 CI 标签页。页面只能向应用请求这一种通知，其他任何通知都会像以前一样被拒绝。如果 macOS 屏蔽了应用的通知，标签页会说明在哪里允许（系统设置 › 通知 › omp-webui）。

### Markdown 与无障碍修复

- **指向章节的链接**：Markdown 编辑器的预览里，标题带有 GitHub 给的 id，所以目录（`[Install](#install)`）会滚动到对应的标题，指向 `guide.md#install` 的链接会在那个标题处打开文件，而不是停在文件开头。
- **任务列表**（回复里和 Markdown 编辑器里）：读屏软件会用任务内容来命名每个复选框（“Write the tests，复选框，已勾选”），而不只是“复选框”。
- **Markdown 编辑器错误画面上的 Esc**：文件打不开时，按一次 Esc 就能关闭编辑器。以前第一次 Esc 只会关掉“关闭”按钮的提示框。
- **变更视图**：新增和删除的行上，行号颜色更深，代码的语法颜色也略微向正文颜色靠拢，在每种配色的浅色和深色模式下都达到 4.5:1 的对比度下限（这些行的底色让其中一些颜色太浅了）。
- **待办列表**：修改无法完成时（任务没有内容、任务或阶段已不存在），原因现在会以页面的语言显示。以前总是英文。

### 修复：配额下限也会拦住一轮对话的第一步

- 对话开始新一轮、而应用还不知道提供商的配额时（第一次查询要几秒钟），快速模型的第一个工具步骤可能越过下限照常执行，只有下一步才会被拦住。现在第一步会等这次查询：到了下限就被拦住，没到就立即继续。

### 侧边栏列表的工具栏固定不动

- 搜索框下面那一行（“已置顶”分组的折叠、归档、排序和“选择”）以前是列表的第一行，会跟着列表一起滚走。现在对话滚动时它固定在对话上方，所以不管往下翻了多远，“选择”和排序都触手可及。日期标题仍然跟着它们所属的行一起滚动。

### 修复：新对话里可以选中模型指引模板了（#16）

- 新对话的“模型指引”列表会在指针移过时上下跳动：指针下那个模板的说明文字被加到列表下面，让列表变高，或者翻到按钮的另一侧，于是指针下换成了另一个模板，点下去选中的是当时在那儿的那个。现在说明文字从一开始就在列表里有自己的位置（没指向模板时是一句提示），所以列表打开期间大小和位置都不变；窗口较矮时，模板在列表内部滚动。

### 修复：服务器不再保存每个对话的整条首条消息

- 对话列表显示每个对话首条消息的前 240 个字符，服务器在运行期间一直保存它们。但它实际保存的是截出这 240 个字符的整条消息：以粘贴的日志或文件开头的对话，整段内容都留在内存里。现在只保存这 240 个字符（40 个以 1 MB 消息开头的对话：之前占用 40 MB，现在几乎为零）。服务器空闲时和列出对话后的内存，现在由基准关卡与 v0.13.0 对比，增长超过 5 % 即失败（#9）。

### 写给贡献者：在忙碌的 Mac 上也站得住的测试关卡

- `bun run test:release`，以及发布脚本在维护者 Mac 上运行的 macOS 测试和真实模型测试（`test:mac`、`test:live`），现在启动的测试工作进程数是这台 Mac 核心数的一半（至少 2 个），而不是每个核心一个；`OMPW_TEST_WORKERS` 可以指定数目（#1）。`bun run test`、`test:contract` 和 `test:all` 仍然每个核心一个工作进程。
- 以前在机器负载高时会失败、其实什么都没坏的测试，现在等待它们要测的事情发生，而不是等一段固定时间：配额下限测试（#2）、停止的时间上限（#10）、卡住的 omp 与 omp 生命周期的测试（#13）。Bun 的测试运行器在一个文件中途结束掉的测试服务器会被重新启动，下一个测试会等它就绪（#3）。上传测试不再取决于磁盘还剩多少空间（#8），家族工作线程的内存测试也不再受到 JavaScriptCore 尚在排队的编译的影响（#12）。
- 端到端测试：工作进程会删掉上一个测试文件写下的对话，所以只用一两个工作进程时，固定样例的对话行也不会被挤出侧边栏（#7），下一个文件在第一个用例之前写下的对话则会保留；设置页的渲染计数不再算上测试自己启动的进程（#6）；remote-flow 和设置助手的测试会等到要读的内容出现，配色测试等设置页的卡片画出来之后才取色。调用真实模型的测试（`live`、`dialogs`、`subagents-real`）在当前的 omp 和 Claude Haiku 5.5 上通过，另有一个离线测试检查新对话的地址会变成它的文件地址（#11）。每个端到端测试和每个单元、契约测试文件都有用于 CI 分片的耗时记录，并由一个单元测试守住。
- 应用图标都由唯一的主图 `macos/icon.png` 经 `bun run icons`（`scripts/icons.ts`）生成：网页的 favicon、Apple 触控图标、192 与 512 px 图标和 maskable 图标，以及 macOS 应用的 iconset（以前 `bun run app` 用 `sips` 生成）。提交的图标与主图生成的结果不一致时，单元测试会失败（#14）。没有矢量源文件：1024 px 的主图就是源文件。
