## English

### Fix: the app not starting after an omp install or update (#310)

- The app and server now start when an omp install or update finished while the app was closed. This used to fail with "Cannot access 'broadcastAll' before initialization" at every launch. A job record that can't be read is now set aside and shown as failed.

### Reliability (#311, #312, #313, #314, #315, #316, #317, #318, #319)

- After the server stops, the "server stopped" alert no longer keeps a CPU core at 100%.
- A damaged search or session index file is moved aside (`index.db.damaged`) and rebuilt, instead of stopping the server at every start.
- Settings › Mode measures the context again after omp is installed or updated.
- Close on a paused conversation that was mid-turn now ends it, instead of letting the rest of the turn run unattended.
- A stray line from omp that isn't a message no longer ends the server; the built-in terminal no longer leaks file descriptors when it fails to start; socket files left by a killed relay are cleaned up.
- Pause is refused on a conversation that is being closed.
- Commands the server runs to ask omp (settings, stats, models, help, export) have time limits, so a hung omp no longer blocks start-up or piles up processes.

### Messages and documentation (#304, #305, #306, #307, #308, #309)

- Chinese users now see the "paused while omp waits to retry" and "paused; resume it to continue" messages in Chinese instead of English.
- The screenshots are made from the script's own sample data only and no longer depend on your omp account; the screenshot script keeps the existing images if a run fails.
- The README describes the five side-panel tabs, side questions, accounts, export and organising conversations, says exactly what the tests read and which model they call, and the Chinese README now covers everything the English one does.

## 中文

### 修复：安装或更新 omp 后应用无法启动（#310）

- omp 的安装或更新在应用关闭期间完成时，应用和服务器现在能正常启动。此前每次启动都会报“Cannot access 'broadcastAll' before initialization”。读取不了的任务记录现在会被单独存放，并显示为失败。

### 稳定性（#311、#312、#313、#314、#315、#316、#317、#318、#319）

- 服务器停止后，“服务器已停止”的提示框不再让一个 CPU 核心一直占满。
- 损坏的搜索或会话索引文件会被移到一旁（`index.db.damaged`）并重建，不再让服务器每次启动都失败。
- 安装或更新 omp 之后，设置 › 模式 会重新测量上下文用量。
- 对在回合中途暂停的对话点“关闭”，现在会结束它，不再让剩下的回合无人看管地继续运行。
- omp 输出的非消息行不再让服务器退出；内置终端启动失败时不再泄漏文件描述符；被强制结束的 relay 留下的 socket 文件会被清理。
- 正在关闭的对话不能再被暂停。
- 服务器向 omp 查询的命令（设置、统计、模型、帮助、导出）都有了时间上限，omp 卡住时不会再拖住启动或堆积进程。

### 提示与文档（#304、#305、#306、#307、#308、#309）

- 对话暂停时，“正在等待 omp 重试”和“请先恢复再继续”这两条提示现在用中文显示，不再是英文。
- 截图只用脚本自带的示例数据生成，不再依赖你的 omp 账号；截图脚本运行失败时会保留原有图片。
- README 补全了五个侧边面板标签、旁问、账号、导出和整理对话，写明测试会读取什么、调用哪个模型；中文 README 也补齐了英文版的全部内容。
