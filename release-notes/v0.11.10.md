## English

24 issues fixed. Every fix has a regression test (or a recorded smoke run).

### New (#571, #572, #573, #574, #575, #578, #576, #577)

- Settings › Updates looks for a newer omp-webui release on GitHub at start and every six hours, and on "Check now"; the card shows the installed and the latest version and the release notes in the language of the interface.
- The updater reads this repository's public releases, so it works once the repository's releases are public; while they are not, the card says that no release is reachable instead of showing an error, and nothing is retried before the next turn.
- An update downloads the release's own installer, checks it against the size and the SHA-256 the release lists, mounts it read-only and checks the app inside it (its signature, its bundle identifier, its version and the signing identity it must have), and refuses the install and says why if any of that does not match.
- The old app is kept until the new one has started, and is put back if the update does not go through; a copy that is not the macOS app is never replaced, and the card says where to download the release by hand.
- Settings › Move to another computer exports what you have made in omp and in this app into one `.ompw` file, and imports such a file on the other Mac: the import checks the manifest and every checksum, shows a preview of what the file holds against what this Mac has, and offers Merge or Replace.
- Logins are left out by default; with "Include logins (encrypted)" on, a password of at least eight characters is required, the logins are encrypted with it, the same password is asked at import, and a wrong password is refused with nothing written.
- Before anything is changed, the import backs up the files it touches, so an import that fails or is stopped halfway can be undone with Restore; remote access settings always come back switched off, and the import answers only the page on this Mac, so a page that came through the tunnel cannot use it.
- A subagent's live view can fill the whole window: the sidebar, the conversation and the panel are hidden, not closed, so "Exit full screen", Esc or Back bring everything back exactly as it was, and the focus goes back to the button that opened it.
- The full-screen view has an address of its own, so a reload, Back and Forward keep it, and Previous and next (⌥↑ and ⌥↓) switch between the conversation's subagents.
- The header's "Open in a new window" pops the subagent out: in the macOS app it is a native window of its own that can enter macOS full screen in its own Space, and in a browser it is a new window with a Full screen button; closing it leaves the app's window as it was.
- The side panel is a top and a bottom pane with a divider between them, which you drag or move with the arrow keys, and each pane has a row of tabs of its own and can show any of the panel's tabs.
- The task progress strip and the "Waiting on N jobs" list become tabs of the panel: while a pane shows them they are no longer drawn above the composer, and they come back above it when the panel is closed.
- A tab is open in one pane at a time, a pane can be folded to its tab row, and the divider's position, the tabs and the folded state are remembered.
- The quota left in the chat header is a small ring instead of a bar, with the same colours and thresholds it had as a bar.
- Every quota pill in the header has the same look — a ring and the figure — and the reset of the conversation's own provider sits inside its own pill instead of between two pills.
- The side panel has a Files tab: it shows the folder the conversation works in and opens its files without leaving the app, read only, and only inside that folder.
- The tree lists one folder per request as you open it, leaves out dotfiles, dependency and build folders and what `.gitignore` names until you press the eye button, and the filter searches names across the whole project.
- A file can be copied by path, inserted into the message box as an @mention, and — on a page from this Mac only — opened in its default app or revealed in Finder.
- Settings › Remote access has a switch, "Let the AI help with remote access" (off by default), and a button, "Set up with AI", that turns it on and starts one new conversation whose agent walks you through the Cloudflare setup.
- The agent can read the remote access status, install cloudflared, start the Cloudflare sign-in, save the hostname, team, AUD and e-mail addresses, and set up, start and stop the tunnel; each of those is asked about by omp before it runs, in Auto-approve too.
- The agent never sees a token or the tunnel's credentials, it cannot turn the switch on itself, and none of it is open to a page that came through the tunnel.

### Remote access (#582, #589, #591, #598)

- A remote page stays connected while it is open: the server pings every remote socket every 30 s, so Cloudflare does not close a WebSocket that has carried nothing for about 100 s, and a hidden tab or a locked iPad keeps its connection.
- A page that lost its connection reconnects by itself; when its Access sign-in ended while the device was away, it loads itself again, which Cloudflare Access sends to its sign-in and back.
- The guide in the remote access card says how to sign in about once a month: set the application's Session Duration to 1 month and the global session duration in Access settings to 1 month, since both default to 24 hours.
- A page that opens a conversation attaches to the process that is running it, whichever page started the turn: a remote page streams the conversation as the app window does, instead of showing the saved transcript with its last tool as "No result" (#591).
- A remote page no longer changes a conversation's permission mode: the "Ask for every tool while remote" hold, its label, its warning and its take-back control are gone, and Settings › Remote access no longer has that switch (#589).
- A page that opens or reloads a conversation while its agent is in a long tool call (such as waiting on a subagent) shows the tool running and the running subagents in the Agents tab, instead of "A tool was still running when this conversation stopped" with Continue; a paused conversation keeps showing the subagents that were running when it was paused (#598).

### Subagents (#594)

- The Agents tab shows a subagent's retry wait with its real retry time and a countdown. When omp is late it says so ("omp hasn't retried yet · N late"), a paused conversation shows "Paused · retries once you resume", and after a resume omp gets 30 s to retry before the wait is shown as late; a wait the registry no longer lists is cleared. omp itself has no way to retry a waiting subagent now, so Stop is the only action (#594).

### Interface (#580, #588, #597)

- A preset just picked is named at once: the picker takes the model the switch gave the process, not the one omp's state still says, so it no longer reads "Custom" while the answer to omp is late (#580).
- A request with several questions is asked one question at a time, with a counter (1 / 3), Back and Next, and Submit over a review of every answer; Enter on a choice moves on, and Skip all declines the whole request. The app's window no longer scrolls behind the request, so the chat header stays where it is (#588).
- In the This session panel of a conversation, Auto-retry and Prompt-cache warming now show the value this omp process actually uses (what the conversation was set to from any page, else omp's configured setting), and their star saves it as omp's default like the other rows; the value stays the same after reopening the panel and on another page (#597).
- Every setting in This session has an About button that explains what it does, what each choice means, the cost, and what to pick: auto-compaction, auto-retry, steering delivery, follow-up delivery, interrupt tools on steer, fast mode, slow mode, prompt-cache warming and compact context (#597).

### Performance (#567, #568, #569, #570, #583, #585)

- Opening a conversation of thousands of messages is as fast as it was: the body is compressed in 1 MB blocks instead of zlib's 16 KB ones, which takes about a third less time and sends the very same bytes.
- The remote access chain (the Access token verifier, the tunnel and the settings that go with them) is loaded the first time something needs it, so a server that never turns remote access on no longer holds it in memory for its whole life.
- An answer of the size of the conversation list is compressed in place instead of on zlib's thread pool, so listing conversations costs about a quarter less CPU per request, while a bigger answer still goes to the pool.
- The first page load fetches what its first paint needs in three files; the rest comes when it is asked for, and a chunk that fails to load is a toast rather than a blank page.
- The first load's JavaScript stays inside the 5% budget after the new features landed (225.3 KiB gzip), and a build over the budget fails and names the modules that made it.
- The server at start loads only what it needs: the Files tab, git, the controls panel, export, statistics and the relay are loaded the first time they are used, so an idle server starts with fewer modules in memory (#585).

### Mobile (#579, #581)

- On an iPad the thinking level in the composer is drawn in the same size, weight and family as the controls beside it, and focusing it does not zoom the page.
- On an iPhone an agent's approval request fits the screen: the choices stay on the screen, they are 44 px on a touch screen, the card scrolls inside itself, and the keyboard's visual viewport bounds the block at the bottom.
- The toast stack is put away only while a request's choices need the room, and says so; Stop, Resume and the remote warning stay.

### Development (#584, #588)

- The tests that failed only under the parallel suite's load are made deterministic: four of them (the incremental store, the macOS server's control, the session pins and the used-up quota case) no longer depend on how busy the machine is, and the test servers no longer collide over a port when the suite runs in parallel (#584).
- The examples, placeholders and test fixtures use made-up names (omp.example.com, my-team, jdoe) instead of the developer's own, and a check refuses this machine's user name and home folder in a tracked file.
- The update-service tests wait for the update helper process to end instead of for a fixed 15 s, and the ask-stepper keyboard test presses Tab out of a radio group the way a person does, so neither depends on machine load (#584, #588).

### Known issues (#594, #599, #600)

- While a reply streams, the server's memory peaks higher than in v0.11.7 (about 103 MB against 89–92 MB in the benchmark); the idle server is not affected. This release ships with it so the other fixes reach you sooner; the cause is being tracked down (#599).
- A subagent waiting out a usage limit cannot be retried at once from the page: omp offers no command for it, so Stop is the only action, and after the Mac slept the retry can come later than the time shown (#594).
- In the conversation's This session panel, Auto-retry and Prompt-cache warming can show no value, with a star that says the configuration could not be read, when the conversation's temporary settings file is gone (#600).

本次发布修复了 24 个 issue。每个修复都附有回归测试或记录在案的冒烟验证。

### 新增（#571、#572、#573、#574、#575、#578、#576、#577）

- 设置 › 更新会在启动时、之后每六小时以及你点“立即检查”时，去 GitHub 上找 omp-webui 自己的新版本；卡片显示已安装和最新的版本号，以及按界面语言显示的发布说明。
- 更新器读取这个仓库的公开发布，因此等仓库的发布公开之后就能用；在还没有公开时，卡片只说暂时找不到可用的发布，而不是报错，在下一次定时之前也不会重试。
- 一次更新会下载发布里附带的安装包，按发布列出的字节数和 SHA-256 核对，只读挂载它，并检查里面的应用（签名、bundle identifier、版本号，以及必须一致的签名身份），任何一项不符就拒绝安装并说明原因。
- 旧的应用会留到新应用真的启动之后才被替换；更新不成时会把它放回去。不是一个 macOS 应用副本的安装（例如 bun server/main.ts 或 npm 包）永远不会被替换，卡片会说明该去哪里手动下载。
- 设置 › 迁移到另一台电脑把你在 omp 和这个应用里做的东西导出成一个 `.ompw` 文件，并在另一台 Mac 上导入这样的文件：导入会核对清单和每一个校验和，先显示文件里的东西与这台 Mac 现有东西的对照预览，再让你选合并还是替换。
- 登录信息默认不包含在内；打开“包含登录信息（已加密）”后必须输入至少八个字符的密码，登录信息用它加密，导入时要问同一个密码，密码错了会被拒绝，什么都不写入。
- 改动任何文件之前，导入会先备份它要碰的文件，因此中途失败或被停止的导入可以用“还原”撤销；远程访问的设置回来时总是关闭的，而且导入只回答这台 Mac 上的页面，因此从隧道进来的页面用不了它。
- 子代理的实时视图可以占满整个窗口：侧边栏、对话和侧边面板只是被隐藏，并没有关闭，因此“退出全屏”、Esc 或返回会把一切原样带回来，焦点也回到打开它的那个按钮。
- 全屏视图有自己的地址，因此重新加载、返回和前进都保留它；“上一个”和“下一个”（⌥↑ 和 ⌥↓）在这个对话的子代理之间切换。
- 标题栏的“在新窗口中打开”把子代理弹出去：在 macOS 应用里那是它自己的原生窗口，可以用绿色按钮进入自己 Space 里的 macOS 全屏；在浏览器里那是带“全屏”按钮的新窗口；关掉它不会动应用的主窗口。
- 侧边面板分成上下两个窗格，中间有一个可以拖动的分隔条（也可以用方向键移动），每个窗格有自己的标签行，都可以显示侧边面板的任何一个标签。

- 同一个标签只在一个窗格里打开，窗格可以折成只剩标签行，分隔条的位置、标签和折叠状态都会被记住。
- 对话标题栏里剩下的额度从一根横条变成一个小圆环，配色和原来的横条一样，阈值也一样。
- 标题栏里的每一个额度药丸都长得一样——一个圆环加一个数字——而当前对话自己那个服务商的重置时间放进了它自己的药丸里，不再夹在两个药丸中间。
- 侧边面板有了一个“文件”标签：它显示这个对话工作的文件夹，让人不用离开应用就能打开里面的文件，只能读，而且只在这个文件夹里。
- 文件树按你打开的层级一次列一个文件夹，点源文件、依赖和构建目录以及 `.gitignore` 点名的内容在按下“显示隐藏文件”之前都不出现，筛选框在整个项目里搜名字。
- 一个文件可以复制路径、按 @提及插入消息框，并且——只在来自这台 Mac 的页面上——用它的默认程序打开或在访达中显示。

### 远程访问（#582、#589、#591、#598）

- 远程页面开着的时候连接不会断：服务器每 30 秒 ping 一次每个远程 socket，因此 Cloudflare 不会关掉那个大约 100 秒没有传过东西的 WebSocket，隐藏的标签页或锁屏的 iPad 也能保持连接。
- 掉过连接的页面会自己重连；如果它的 Access 登录在设备离开期间过期了，它就重新加载自己，Cloudflare Access 会把它送去做登录，然后再送回来。
- 远程访问卡片里的指南说明怎样大约每月登录一次：把应用的 Session Duration 设为 1 个月，再把 Access 设置里的全局登录时长也设为 1 个月，因为两者默认都是 24 小时。
- 一个页面打开某个对话时，会挂到正在运行它的进程上，不管是哪个页面启动的这一轮：远程页面会像应用窗口一样显示流式输出，而不再显示保存下来的记录，并把最后一个工具显示为“没有结果”（#591）。
- 远程页面不再改变对话的权限模式：“每次工具都询问（远程时）”的锁定、它的标签、警告和收回控件都已删除，设置 › 远程访问也不再有那个开关（#589）。
- 页面打开或重新加载一个对话时，如果它的智能体正处在一次长时间的工具调用中（例如在等待子代理），这个工具会显示为运行中，正在运行的子代理显示在“子代理”标签页里，而不是显示“对话停止时有工具仍在运行。发送一条消息即可继续。”和“继续”；暂停的对话仍然显示暂停时正在运行的子代理（#598）。

### 子代理（#594）

- “子代理”标签页现在显示子代理等待重试的真实重试时间和倒计时。omp 晚于预期时会显示“omp 还没有重试 · 已晚 N”，对话暂停时显示“对话已暂停 · 恢复后重试”；恢复之后 omp 有 30 秒的时间重试，超过这段时间才显示为晚了；注册表不再列出的等待会被清除。omp 本身没有办法立即重试一个等待中的子代理，因此“停止”是唯一的操作（#594）。

### 界面（#580、#588、#597）

- 刚选的预设会立刻显示它的名字：选择器取的是那次切换给进程的模型，而不是 omp 的状态里还写着的那一个，因此在 omp 的答复迟到时它不再显示“自定义”（#580）。
- 一个包含多个问题的请求现在一次只问一个问题：有计数（1 / 3）、返回和下一个按钮，最后一步是提交，并附上每个答案的复核；在选项上按 Enter 进入下一题，“全部跳过”会拒绝整个请求。请求不再让应用窗口滚动，聊天标题栏因此留在原处（#588）。
- 在“当前对话”面板里，自动重试和提示缓存预热现在显示这个 omp 进程实际在用的值（这个对话在任何页面上被改过的值优先，否则是 omp 的配置），星标会把它保存为 omp 的全局默认值，和其他行一样；重新打开面板或在另一个页面打开时，值保持不变（#597）。
- “当前对话”里的每一项设置都有一个“关于”按钮，说明它做什么、每个选项是什么意思、代价是什么，以及该怎么选：自动压缩、自动重试、引导消息的送达方式、后续消息的送达方式、引导时中断工具、快速模式、慢速模式、提示缓存预热和压缩上下文（#597）。

### 性能（#567、#568、#569、#570、#583、#585）

- 打开一个有成千上万条消息的对话和以前一样快：响应体现在按 1 MB 一块压缩，而不是 zlib 自己的 16 KB 一块，耗时少了大约三分之一，发出的字节完全相同。
- 远程访问这一整条链路（Access token 的校验器、隧道和它的设置）第一次被用到时才加载，因此从不打开远程访问的服务器不会一辈子把它留在内存里。
- 和对话列表差不多大的响应在原地压缩，而不是交给 zlib 的线程池，因此列出对话每次请求少花大约四分之一的 CPU；更大的响应仍然交给线程池。
- 首页的第一次加载只取第一次绘制需要的内容，分三个文件；其余的被问到时才来，而加载失败的一块只弹一条提示，不会留下一片空白。
- 新功能落地之后，首次加载的 JavaScript 仍在 5% 的预算之内（gzip 后 225.3 KiB），超预算的构建会失败，并说出是哪些模块造成的。
- 服务器启动时只加载它需要的部分：文件标签、git、控制面板、导出、统计和中继在第一次被使用时才加载，因此空闲的服务器启动时内存里的模块更少（#585）。

### 手机与平板（#579、#581）

- 在 iPad 上，输入框里的思考级别和旁边的控件用同样的字号、字重和字体，点它也不会把页面放大。
- 在 iPhone 上，智能体的审批请求装得进屏幕：选项留在屏幕上，触摸屏上是 44 px，卡片自己滚动，键盘的可视区域决定底部那一块的边界。
- 提示条只在一个请求的选项需要空间时被收起，并且会说明这一点；“停止”“继续”和远程警告都留着。

### 开发（#584、#588）

- 只在并行测试的负载下才失败的测试变得确定了：其中四个（增量存储、macOS 服务器的控制、对话置顶和额度用完的用例）不再取决于机器有多忙，测试服务器并行跑时也不会再抢同一个端口（#584）。
- 示例、占位符和测试夹具使用编出来的名字（omp.example.com、my-team、jdoe），而不是开发者自己的；一项检查会拒绝受版本管理的文件里出现这台机器的用户名和主目录。
- 更新服务的测试会等待更新助手进程结束，而不是等固定的 15 秒；请求的键盘测试按 Tab 时像真人一样离开单选组，因此两者都不再取决于机器负载（#584、#588）。

### 已知问题（#594、#599、#600）

- 回复流式输出时，服务器内存的峰值比 v0.11.7 高（基准测试里约 103 MB，v0.11.7 为 89–92 MB）；空闲时的服务器不受影响。为了让其他修复早点到你手里，这个版本带着它发布；原因正在查（#599）。
- 等待用量上限解除的子代理无法从页面上立即重试：omp 没有提供这样的命令，因此“停止”是唯一的操作；Mac 睡眠过之后，重试可能比显示的时间晚（#594）。
- 在对话的“当前对话”面板里，如果这个对话的临时设置文件已经不在了，自动重试和提示缓存预热可能不显示值，星标会说无法读取配置（#600）。
