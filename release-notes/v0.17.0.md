## English

### A new chat is a new project

- New chat now starts a new project by default: type a name for its folder, or leave it empty and the folder is named from the time (`chat-2026-11-01-0930`, then `-2`, … in the same minute). The folder is made in the projects folder (Settings › Projects folder) when the first message is sent, not before: opening New chat and leaving makes nothing.
- "Change" beside "Made in …" picks another projects folder (on the computer omp-webui runs on). "Use an existing folder" opens the folder picker as before, and "Make a new project instead" goes back.
- Everything picked before the first message (model, thinking level, permission mode, guard, guidance, unattended, a goal) goes to the conversation in the new folder.
- New chat from a conversation's own context (an issue in the Issues tab, say) still opens in that conversation's folder.

### Change a conversation's folder

- *Change folder…* in a conversation's menu in the sidebar, or a click on its folder on the status line under the message box, picks another folder for it: omp works there from then on. It is omp's own `/move`; nothing in either folder is moved or changed (omp only files the conversation's transcript under the new folder in its own sessions folder). Not while the conversation is working or waiting for an answer.

### New chat remembers the guidance

- New chat starts with the model guidance the last new chat was started with: a template, text written there, or none. With nothing remembered, or when that template was deleted, it starts from the template Settings makes the default, as before.

### The CI tab names its repository

- The CI tab now shows which GitHub repository its runs are of (as `gh` reads it for the folder), with a link to its Actions page. A folder whose remote is another repository than you expect is plain to see.

### The tab's title names the repository

- The browser tab's title now starts with the repository of the conversation on screen (`omp-webui · omp`), taken from its remote's address (or, without a remote, from its folder's name). Conversations in different repositories, or in two checkouts of one, are told apart at a glance. Nothing is moved.

### A caret instead of the shimmer

- With live animations on, the reply being written no longer has a band of light over it: a caret breathes at the end of its text, and the turn's running time glows softly. Subtle, Normal and Lively still set how much; reduced motion still turns them off.

### Windows updates itself

- From 0.17.0 the Windows launcher updates itself from GitHub releases, as the macOS app does: Settings › Updates checks, downloads the new zip (its SHA-256 checked), and swaps the program folder after omp-webui quits, putting the old one back if the new one does not start. Your data (`%USERPROFILE%\.omp-webui`) is not touched.
- Coming from 0.16.0, update by hand once: download the 0.17.0 zip and replace the folder.
- The program is still unsigned: the checksum guards against a broken download, not against a compromised release. This was tested on CI's Windows runners, not yet on a Windows PC.

## 中文

### 新建对话就是新建项目

- 新建对话现在默认新建一个项目：为它的文件夹起个名字，或者留空，文件夹就按时间命名（`chat-2026-11-01-0930`，同一分钟内再建是 `-2`、……）。文件夹建在项目文件夹里（设置 › 项目文件夹），发出第一条消息时才建：打开新建对话再离开，什么也不会留下。
- “将创建于 …”旁边的“更改”可以换一个项目文件夹（在运行 omp-webui 的电脑上）。“改用已有文件夹”和以前一样打开文件夹选择器，“改为新建项目”可以切回来。
- 发第一条消息前选好的一切（模型、思考强度、权限模式、守卫、指引、无人值守、目标）都会带到新文件夹里的对话。
- 从某个对话里发起的新建对话（比如 Issues 标签页里的 issue）仍然在那个对话的文件夹里打开。

### 更改对话的文件夹

- 在侧边栏对话的菜单里选“更改文件夹…”，或点输入框下方状态栏里的文件夹，就能给对话换一个文件夹，之后 omp 就在那里工作。用的是 omp 自己的 `/move`；两个文件夹里的内容都不会被移动或修改（omp 只是在它自己的会话目录里把这个对话的记录归到新文件夹下）。对话正在工作或等你回答时不能更改。

### 新建对话记住指引

- 新建对话会沿用上一个新建对话开始时用的模型指引：一个模板、在那里写的文字，或者不用。还没有记住的，或者那个模板已经删掉了，就和以前一样从设置里的默认模板开始。

### CI 标签页显示仓库名

- CI 标签页现在显示它列出的是哪个 GitHub 仓库的运行（按 `gh` 对这个文件夹的识别），并链接到该仓库的 Actions 页面。文件夹的远程仓库和你以为的不一样时，一眼就能看出来。

### 标签页标题显示仓库名

- 浏览器标签页标题现在以当前对话所在的仓库名开头（`omp-webui · omp`），取自远程仓库地址（没有远程仓库时用文件夹名）。不同仓库、或同一仓库的两个副本里的对话，一眼就能分清。不会移动任何文件。

### 用光标代替流光

- 打开实时动画时，正在输出的回复上不再有一道扫过的光带：文字末尾有一个明暗呼吸的光标，这一轮的运行时间带一点柔光。轻微、正常、活泼仍然决定动效的多少；系统的“减少动态效果”仍会把它们关掉。

### Windows 自动更新

- 从 0.17.0 起，Windows 启动器和 macOS 应用一样从 GitHub 发布自动更新：设置 › 更新会检查、下载新的 zip（校验 SHA-256），在 omp-webui 退出后替换程序文件夹；新版本启动不了就换回旧的。数据（`%USERPROFILE%\.omp-webui`）不会动。
- 从 0.16.0 升级需要手动一次：下载 0.17.0 的 zip，替换整个文件夹。
- 程序仍然没有签名：校验和只防下载损坏，防不了被篡改的发布。这是在 CI 的 Windows 运行器上测试的，还没有在真正的 Windows 电脑上验证过。
