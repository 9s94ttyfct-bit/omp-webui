## English

### Delete no longer refused or held back by mistake

- **A conversation that has finished can be deleted at once.** Right after its first reply omp was still making its title in the background, and the delete was refused with "This conversation is working in the web UI". The title no longer holds the delete.
- **A new chat's folder is no longer "in use" by dozens of other conversations.** A conversation working in the projects folder itself (`~/omp`, where New chat makes each chat's folder) counted as working in every folder inside it, so ticking **Also move its folder to the Trash** named them all. Like one in the home folder, it no longer holds the folders inside.
- **The conversation's own helpers do not hold its folder.** MCP servers and other programs the deleted conversation's omp started end with it; the folder is checked again once they are gone (up to 5 seconds), instead of being reported as in use by a running process.

### omp 18.19

- omp 18.19 has no **Blocked** task state. With it, the task menu does not offer Blocked; older omp versions keep it.

## 中文

### 删除不再被误拦或误挡

- **已经结束的对话可以直接删除。** 第一次回复之后，omp 还在后台生成标题，删除会被拒绝并提示“这个对话正在网页界面里工作”。现在生成标题不会再挡住删除。
- **新对话的文件夹不再被几十个其他对话“占用”。** 在项目文件夹本身（`~/omp`，新对话会在这里为每个对话建文件夹）里工作的对话，被算成在它里面的每个文件夹里工作，所以勾选 **同时把它的文件夹移到废纸篓** 时会把它们全部列出。现在它和在主目录里工作的对话一样，不再占用里面的文件夹。
- **对话自己启动的程序不再挡住它的文件夹。** 被删除对话的 omp 启动的 MCP 服务器等程序会随它结束；等它们退出后（最多 5 秒）会重新检查文件夹，不会再显示被正在运行的进程占用。

### omp 18.19

- omp 18.19 没有 **已阻塞** 任务状态。使用它时，任务菜单不再提供“已阻塞”；较旧的 omp 版本保留这个选项。
