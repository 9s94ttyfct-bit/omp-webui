## English

17 issues fixed. Two more changes are refs only and close no issue: #576 (a folder change made while a folder watch starts is no longer lost) and #597 (the slow-mode explanation per model).

### New (#607, #609, #610)

- Settings › Safety, Guard dangerous commands (#609): a risky tool call is approved or refused before it runs, in the main agent and in every subagent. It is on by default, with the Reviewer model mode: another model reads the call and the recent conversation and approves or refuses it before it runs. What it is sent: the exact command or code of the call (up to 24,000 characters), the working folder, the purpose the agent stated for the call (up to 600 characters) and the last six turns of the conversation, each cut to 1,200 characters. That goes to the reviewer's provider. To keep it from leaving the computer, choose Ask me instead, or turn the guard off. If no reviewer can be reached, a subagent's call is refused and says it was not judged, and the main agent asks you instead. Recent decisions are listed behind Show decisions. A conversation that was already running before this update (paused, or waiting out a usage limit) is not covered until it is opened again; it says so.
- Move to another computer (#607): the whole file can be encrypted with a password. The password must be repeated, and a generator makes a strong one. A file that was changed on the way is refused.
- Session controls (#610): the star on a setting is filled when the value is omp's default, and hollow when it differs.

### Interface (#586, #590, #592, #593, #595, #596, #600, #605)

- A conversation and a subagent's live view stay at their end however the content grows, on desktop, iPad and iPhone. A reader who scrolled up is left where they are (#586, #595).
- The scroll-to-bottom arrow goes straight to the end while a reply grows (#596).
- A long conversation opens on its latest part, and earlier messages load as you scroll up, or with Show earlier messages (#590).
- Conversations running in other pages are kept in step, and a setting changed on one page shows on the others (#592, #593).
- An Escape pressed the moment a dialog opens closes that dialog, not the full-screen subagent view under it (#605).
- The This session panel shows the settings of the running conversation correctly, including when its temporary settings file is gone (#600).
- Slow mode's explanation describes only the mechanism of the active model, and a Claude slow-mode row appears when the conversation's model is of another provider (refs #597).

### Safety (#606, #608)

- Escape asks before it stops a running reply. A second Escape within 3 seconds stops it (#606).
- Remote access: an opt-in confirmation, off by default, asks on the remote page before a high-risk command runs in a turn that a remote page drives (#608).

### macOS app (#604)

- Quitting asks first, and Run in background is the default answer. The window closes while the server, the conversations and remote access keep running, and the Dock icon brings the window back. The setting is Settings › Quitting the app › When you quit the app: Ask, Run in background or Quit.
- Logging out, restarting and updating the app always quit.

### Performance (#599)

- The server's memory peak while a reply streams is reduced by streaming the conversation's gzip output and releasing the family worker's file text once a job is done. The measured figures are in the issue (#599).

### Development (#601, #602)

- The bench gates memory on the server's footprint, and a comparison that did not gate memory never passes (#601).
- Review fixes from v0.11.10 (#602): the leftovers in interrupted tool calls, the approval-mode reply, resume times, a paused call's arguments, and store tests that broke one another.
- A guard test pins what a paused conversation needs to survive an app update, with an opt-in cross-version check.

### Known issues (#594, #611, #622)

- A subagent waiting out a usage limit cannot be retried at once: omp offers no command for it, so Stop is the only action (#594, still open).
- The follow-ups to the remote-page confirmation of #608 are tracked in #611: repair of a `.risk` file's content, a false positive on loopback `/api/` requests, and a test.
- With a long conversation open, the server holds more memory than v0.11.7: in the benchmark about 67 MB against 55 MB after opening one, and a peak of about 71 MB against 56 MB while a reply streams. It is being tracked down (#622).
- This version is signed with a new local signing certificate (the old one was lost), so macOS treats the app as new once: it asks again for notifications, screen recording and accessibility the first time they are used. Later updates keep the grants.

## 中文

本次发布修复了 17 个 issue。另有两项只是参考，没有关闭任何 issue：#576（文件夹监视开始的同时发生的改动不再丢失）和 #597（按模型区分的慢速模式说明）。

### 新增（#607、#609、#610）

- 设置 › 安全 中的“防护危险命令”（#609）：有风险的工具调用在运行之前会被批准或拒绝，主智能体和每一个子代理都一样。它默认开启，模式为“审查模型”：由另一个模型阅读这次调用和最近的对话，并在运行前批准或拒绝。发送给它的内容包括：这次调用原样的命令或代码（最多 24,000 个字符）、工作文件夹、智能体为这次调用写下的用途（最多 600 个字符），以及对话的最近六轮（每轮最多 1,200 个字符）。这些内容会发送给审查模型所属的服务商。如果不想让它们离开这台电脑，请选择“询问我”，或关闭防护。联系不上审查模型时，子代理的调用会被拒绝，并说明它没有被评判；主智能体则会改为询问你。最近的决定可通过“显示决定记录”查看。在这次更新之前就在运行的对话（暂停的，或正在等待用量上限重置的）在重新打开之前不受防护，界面上会注明。
- 迁移到另一台电脑（#607）：整个文件可以用密码加密。密码需要再输入一次，也可以生成一个强密码。中途被改动过的文件会被拒绝。
- 当前对话的控件（#610）：某个设置旁的星标在值是 omp 的默认值时是实心的，不同时是空心的。

### 界面（#586、#590、#592、#593、#595、#596、#600、#605）

- 无论内容怎样增长，对话和子代理的实时视图都会停留在末尾，桌面端、iPad 和 iPhone 都是如此。读者向上滚动过的，会留在原来的位置（#586、#595）。
- 回到底部的箭头会在回复增长的同时直接到达末尾（#596）。
- 很长的对话打开时显示最新的部分，向上滚动或点击“显示更早的消息”时加载更早的消息（#590）。
- 在其他页面运行的对话会保持同步，在一个页面上改动的设置会显示在其他页面上（#592、#593）。
- 对话框刚打开时按下的 Esc 会关闭这个对话框，而不是关闭它下面的子代理全屏视图（#605）。
- “当前对话”面板能正确显示正在运行的对话的设置，即使它的临时设置文件已经不在了（#600）。
- 慢速模式的说明只描述当前模型的机制；当对话的模型属于另一个服务商时，会出现单独的 Claude 慢速模式一行（参考 #597）。

### 安全（#606、#608）

- Esc 在停止正在运行的回复之前会先询问。3 秒内第二次按 Esc 才会停止回复（#606）。
- 远程访问：一项需要主动开启、默认关闭的确认功能。在远程页面驱动的一轮中，有高风险的命令运行之前，远程页面会先询问（#608）。

### macOS 应用（#604）

- 退出时会先询问，默认答案是“在后台运行”。窗口会关闭，服务器、对话和远程访问继续运行，点击程序坞图标即可重新打开窗口。设置位于“退出应用”›“退出应用时”，可选“询问”“在后台运行”或“退出”。
- 注销、重启和更新应用时总是直接退出。

### 性能（#599）

- 回复流式输出时的服务器内存峰值有所降低：对话的 gzip 输出改为流式写入，并在任务完成后释放家族工作进程里的文件文本。具体测量数字见该 issue（#599）。

### 开发（#601、#602）

- 基准测试以服务器的内存占用为准，没有检查内存的比较永远不会通过（#601）。
- 修复了 v0.11.10 的审查遗留问题（#602）：被中断的工具调用、审批模式的回复、恢复时间、暂停的调用的参数，以及相互影响的存储测试。
- 新增一项守护测试，确保暂停的对话在应用更新后能保留所需的状态，并提供一项可选的跨版本检查。

### 已知问题（#594、#611、#622）

- 因用量上限而等待的子代理无法立即重试：omp 没有为它提供命令，因此“停止”是唯一的操作（#594，仍未关闭）。
- #608 远程页面确认功能的后续工作记录在 #611 中：修复 `.risk` 文件的内容、修正对本机 `/api/` 请求的误报，以及一项测试。
- 打开很长的对话时，服务器占用的内存比 v0.11.7 多：基准测试里打开之后约 67 MB（v0.11.7 约 55 MB），回复流式输出时峰值约 71 MB（v0.11.7 约 56 MB）。原因正在查（#622）。
- 这个版本用新的本机签名证书签名（原来的证书丢失了），因此 macOS 会把它当成一个新应用一次：第一次用到通知、屏幕录制和辅助功能时会再问一遍权限。以后的更新会保留这些授权。
