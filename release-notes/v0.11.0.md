## English

### One retry: omp's own (#249, #231, #236)

- Waiting out a usage limit is now omp's own retry only; the app's separate wait is gone. Settings shows and changes omp's `retry.waitForUsageReset`, shared with the terminal, and a conversation can override it from its quota pill.
- The conversation shows omp's own countdown with Cancel and Retry now, keeps showing it to tabs opened during the wait, and says so when omp hasn't retried at the time it announced, so a stuck wait can always be continued with one click.
- Quota pills count only the usage windows that apply to the model in use, offline conversations show only their own provider, and a failed check keeps the last known figures (marked as out of date).

### Waiting out a usage limit: more fixes (#252, #253, #254, #255, #256, #257, #258)

- A page opened or reloaded during the wait shows the countdown with Cancel and Retry now, not a false "retrying…".
- A paused conversation keeps its wait across quitting and reopening the app, and actions on a conversation paused past its retry time are refused ("Resume to retry") instead of silently starting the turn.
- After a reconnect the page shows omp's current attempt, and a phone whose clock differs from the Mac's no longer shows a false "omp hasn't retried".
- While omp waits, the message box says your message is sent when omp retries.
- A subagent's usage-limit wait shows in the Agents tab with a countdown.
- Retry now from two tabs at once no longer shows an error, and the settings explain that "Don't wait" only applies to waits longer than `retry.maxDelayMs`.

### Notifications reachable by keyboard in a dialog (#207)

- While a dialog is open, press ⌘⇧Y (Ctrl+Shift+Y) to focus the newest notification, Tab to move between its buttons, Enter to use one, and Esc to go back to the dialog without closing it.

### Fix: "No models" in a new chat after a mode or backend change (#208)

- An unused offline process that saw the backend change and change back is no longer handed to a new chat, and an empty model list is asked for again the next time the picker opens.

### Fix: installing and updating omp (#217, #218, #219, #222, #223, #224, #225)

- Quitting omp-webui (or stopping the server) during an omp install or update no longer cuts it off: the job finishes in the background, the next start shows how it ended, and the quit dialog says so.
- An update that is waiting says how many conversations are working, waiting for your answer or paused. "Update anyway" stops waiting for paused and waiting ones (their omp keeps the old version until restarted). Automatic updates say what they wait for.
- Looking up new omp versions uses the same registry credentials as `omp update`.
- When omp's installer can't be downloaded, the error is curl's own message instead of "omp was not found".
- The macOS app uses your login shell's environment: the same PATH as Terminal (your `node`, `python3`) and the variables your `.zshrc` exports; "Look again" reads it again.
- The first-run screen fits phone and minimum window widths, setup moves focus to each step and announces it, and choosing the default model no longer overwrites your other model roles.
- The macOS window background follows the page's theme colour.

### Fix: offline mode settings (#226, #227, #228, #229, #230)

- Changing the offline backend or settings no longer breaks offline conversations that are already open: each configuration has its own agent folder, and unused ones are cleaned up automatically.
- Changes to offline settings (backend, MCP servers, tools, skills) appear immediately in every open tab, so one tab can no longer overwrite another's choices.
- The offline `models.yml` contains only the chosen backend's provider, nothing else from your file.
- Settings warns when the backend address is not on this Mac or your local network; the key of your oMLX entry is not sent to such an address, and cloud metadata addresses are refused.
- Changing several settings in a row no longer starts several context measurements at once.

### Fix: MCP, skill and plugin switches (#220, #221, #225)

- An MCP server defined in both your `mcp.json` and the folder's can no longer be half-switched: its switch is off and says to edit it in the terminal.
- Turning on a skill that the folder's own settings turn off now says so at once instead of hanging for a few seconds.
- The "restart omp to apply" note for MCP servers no longer disappears when you reload the page or open another tab.
- A plugin installed for both you and a folder shows as two rows with separate switches, and your copy is marked when the folder's overrides it.

### Fix: paused conversations in the background (#245, #246, #247, #248)

- A paused conversation whose omp was killed no longer leaves its tools frozen in the background.
- A conversation taken over after a restart keeps its permission-mode settings when another omp-webui server starts, and changing the mode still works.
- The fallback folder for the background helpers' sockets is private to you, and one left behind can no longer stop conversations from starting.
- When a new server takes over a conversation from one that has stopped responding, omp's output now reaches the new one instead of stalling.

### Preferences stay in sync everywhere (#240, #241)

- A theme, palette, language or panel width chosen in one tab, window or browser now appears in the others immediately. Two servers sharing a data folder no longer overwrite each other's settings, invalid stored values are ignored, and dragging a panel edge saves the width once, when you let go.

### Fix: readability and accessibility (#237, #238, #239, #242, #243)

- Usage chart: each palette has its own series colours in light and dark, legend and tooltip text is readable on light palettes, bars no longer animate, and models beyond the eighth are grouped as "Other".
- The Auto-approve hint in the permission menu is readable in every light palette.
- The session row's menu button and the small text buttons (View subagents, Show raw arguments, Show all, +N more, Ask a follow-up) are at least 24 px high.
- The built-in terminal follows the palette, light/dark mode and the macOS appearance, with ANSI colours tuned for each palette.
- The model picker is announced as "Choose model", its favourite hearts no longer sit inside the options, and the unlock page has a proper heading.

### Feedback keeps your whole report and removes more private data (#209, #210, #216)

- "Copy text" always copies the whole report, and when a long report has to be cut to fit the link, "Open on GitHub" copies the full text first and keeps your form.
- Feedback now also removes passwords, Authorization headers, cookies, logins in links, signed-link keys, more key formats, your user name, and home folders with spaces or inside omp's session-folder names. The summary limit counts the "Bug:"/"Feature:" prefix, and the star reminder can be switched off in Settings › Feedback.

### Fix: unsent messages (#214, #215)

- Deleting a conversation also discards its unsent message, and only the 20 most recent unsent messages are kept. A message typed before a new conversation's file exists stays with that conversation.
- If omp takes a queued message while you are editing it, your edited text goes back to the message box with a notice instead of disappearing.

### Settings and docs (#211, #212)

- "Reset to default size" in Settings › Appearance keeps its label on one line.
- The README screenshots and texts show the current app (palettes, resizable panels, feedback, installing omp), and the install steps say the app can install omp for you.

### Faster with long and many conversations (#266, #267, #268, #269, #270)

- A long conversation that keeps growing no longer slows down the app: only the new part of its file is indexed (an append to a 30 MB conversation went from about 1.4 s to 2 ms), so replies in other conversations keep streaming smoothly.
- The sidebar appears right away on first start or after an update, while search finishes indexing in the background (search says so meanwhile).
- Long replies stream smoothly: rendering no longer gets slower as a reply grows.
- With thousands of conversations the sidebar stays fast (typing in the filter takes about 1 ms instead of 77 ms) and only changed conversations are sent to the page.
- A hanging usage check no longer freezes the quota display until restart.

### Chat fixes (#271, #272, #273, #274, #275, #276, #277, #278, #279)

- Pressing Enter to confirm Chinese (or other input-method) text no longer sends the half-typed message, also in the macOS app.
- Edit, Regenerate and Fork are hidden while a reply or command is running, and a failed edit puts your text back in the message box.
- The conversation stays at the end when images load late or the message box grows, and sending scrolls you to your message.
- Choosing the same search result again scrolls to it again.
- Deleting a conversation that is replying is refused with an explanation instead of killing the reply and then failing.
- The project filter goes back to all projects when its last conversation is deleted.
- Unsent messages survive reloading the page, including the automatic reload after an update.
- Esc stops a running reply from anywhere on the page, and on narrow screens the sidebar drawer closes with Esc.

### Security (#259, #260, #261, #262, #263, #264, #265)

- A malformed message can no longer stop the server, and a broken or duplicate login cookie no longer causes an error page; errors no longer reveal server details.
- Opening a conversation no longer runs commands a folder's own git settings ask for: the git status check refuses folders whose git configuration names a program to run, and neutralises hooks and attribute filters. (It needs git 2.40 or newer.)
- Other websites on your computer can't trigger the app's expensive actions, such as re-measuring the context or refreshing usage.
- The web version's data folder and its search index are readable only by you.
- A leftover temporary folder the app can't remove no longer stops conversations from starting.
- The macOS app opens new-window links only when they are web or mail links, and the sign-in link in Accounts only accepts web addresses.

## 中文

### 只有一种重试：omp 自己的重试（#249、#231、#236）

- 等待用量上限重置现在只由 omp 自己的重试完成，应用原来那套单独的等待已移除。设置里显示并修改的是 omp 的 `retry.waitForUsageReset`（与终端共用），每个对话也可以在额度标签里单独设置。
- 对话里显示 omp 自己的倒计时，带“取消”和“立即重试”；等待期间新打开的标签页也能看到。到了 omp 宣布的时间它仍没有重试时，页面会明确说明，一键就能继续。
- 额度标签只计算适用于当前模型的用量窗口；离线对话只显示自己的提供商；查询失败时保留最后一次的数据，并标明已过时。

### 等待用量上限重置：更多修复（#252、#253、#254、#255、#256、#257、#258）

- 等待期间打开或刷新页面，会显示倒计时以及“取消”和“立即重试”，不再误显示“正在重试…”。
- 暂停的对话在退出并重新打开应用后仍保留等待；对等待已到点的暂停对话执行操作会被拒绝并提示“恢复后才会重试”，不再悄悄开始那一轮。
- 重新连接后页面显示 omp 当前的重试次数；手机与 Mac 的时钟不一致时也不再误报“omp 还没有重试”。
- omp 等待期间，输入框会说明你的消息会在 omp 重试时发送。
- 子代理的用量上限等待会在“代理”标签页显示倒计时。
- 两个标签页同时点“立即重试”不再报错；设置里说明了“不等待”只对超过 `retry.maxDelayMs` 的等待生效。

### 对话框中可以用键盘操作通知（#207）

- 对话框打开时，按 ⌘⇧Y（Ctrl+Shift+Y）聚焦最新的通知，Tab 在按钮间切换，Enter 执行，Esc 回到对话框且不会关闭它。

### 修复：切换模式或后端后，新对话显示“No models”（#208）

- 经历过后端改动又改回的闲置离线进程不再交给新对话使用；空的模型列表也不再缓存，下次打开选择器时会重新获取。

### 修复：安装和更新 omp（#217、#218、#219、#222、#223、#224、#225）

- 在安装或更新 omp 的过程中退出 omp-webui（或停止服务），不会再把它中途打断：任务会在后台继续完成，下次启动时显示结果，退出对话框也会说明这一点。
- 更新在等待时，会分别说明有几个对话在工作、在等你回答、已暂停。“仍然更新”可以不再等待已暂停和在等回答的对话（它们的 omp 会继续使用旧版本，直到重新启动）。自动更新也会说明它在等什么。
- 查询 omp 新版本时，使用与 `omp update` 相同的软件源凭据。
- omp 官方安装脚本下载失败时，错误信息是 curl 的原话，而不是“找不到 omp”。
- macOS 应用使用你登录 shell 的环境：PATH 与终端一致（用的是你的 `node`、`python3`），并包含 `.zshrc` 导出的变量；“重新查找”会重新读取。
- 首次运行界面在手机宽度和最小窗口宽度下不再溢出；首次设置会把焦点移到每一步并朗读当前步骤；选择默认模型时不再覆盖你的其他模型角色。
- macOS 窗口背景颜色跟随页面的主题色。

### 修复：离线模式设置（#226、#227、#228、#229、#230）

- 更改离线后端或设置，不再影响已经打开的离线对话：每种配置都有自己的 agent 文件夹，不再使用的会自动清理。
- 离线设置（后端、MCP 服务器、工具、技能）的改动会立即出现在所有打开的标签页里，一个标签页不会再覆盖另一个的选择。
- 离线用的 `models.yml` 只包含所选后端的提供商，不再带上你文件里的其他内容。
- 后端地址不在本机或局域网时，设置页会给出警告；你的 oMLX 条目的密钥不会发送到这样的地址，云平台元数据地址会被拒绝。
- 连续修改几项设置时，不会再同时启动多次上下文测量。

### 修复：MCP、技能和插件开关（#220、#221、#225）

- 同时定义在你的 `mcp.json` 和文件夹配置里的 MCP 服务器不会再被切换到一半：它的开关会关闭，并提示请在终端里编辑。
- 打开一个被文件夹自身设置禁用的技能时，会立刻提示，不再卡住几秒。
- MCP 服务器的“重启 omp 以生效”提示不会因为刷新页面或打开另一个标签页而消失。
- 同时安装在你和文件夹两个范围的插件显示为两行、各有独立开关；文件夹里的同名插件覆盖了你的那份时会有标记。

### 修复：在后台保留的已暂停对话（#245、#246、#247、#248）

- 已暂停对话的 omp 被强制结束后，它的工具进程不会再冻结着留在后台。
- 重启后被接管的对话，在另一个 omp-webui 服务器启动时仍保留它的权限模式设置，切换模式也仍然有效。
- 后台辅助进程使用的备用套接字文件夹只属于你；遗留的文件夹不会再导致对话无法启动。
- 新服务器从一个已无响应的服务器那里接管对话时，omp 的输出会送到新服务器，不再卡住。

### 偏好设置在所有页面同步（#240、#241）

- 在一个标签页、窗口或浏览器里切换主题、配色、语言或面板宽度，其他已打开的页面会立即跟随。共用同一数据目录的多个服务器不再互相覆盖设置；无效的已保存值会被忽略；拖动面板边缘只在松开时保存一次宽度。

### 修复：可读性与无障碍（#237、#238、#239、#242、#243）

- 用量图表：每套配色的浅色和深色都有自己的系列颜色；图例和提示文字在浅色配色下清晰可读；柱子不再播放动画；第 8 个之后的模型合并显示为“其他”。
- 权限菜单里“自动批准”的说明文字在所有浅色配色下都清晰可读。
- 会话行的菜单按钮和小的文字按钮（查看子代理、显示原始参数、显示全部、+N 更多、继续追问）高度至少为 24 px。
- 内置终端跟随配色、浅色/深色模式和 macOS 外观，ANSI 颜色按每套配色调整。
- 模型选择器会被朗读为“选择模型”，收藏用的心形按钮不再放在选项里面，解锁页面有了正式的标题。

### 反馈保留完整内容，并移除更多隐私数据（#209、#210、#216）

- “复制文本”总是复制完整的报告；较长的报告需要截短才能放进链接时，“在 GitHub 打开”会先复制全文，并保留你填写的内容。
- 反馈现在还会移除密码、Authorization 头、Cookie、链接里的登录信息、带签名链接的密钥、更多格式的密钥、你的用户名，以及带空格的主目录路径和 omp 会话文件夹名里的主目录。摘要的长度限制会把“Bug:”/“Feature:”前缀算进去；星标提醒可以在“设置 › 反馈”里关闭。

### 修复：未发送的消息（#214、#215）

- 删除对话时会一并丢弃它未发送的草稿，并且最多只保留最近 20 条草稿。在新对话生成文件之前输入的草稿会继续跟着这个对话。
- 编辑排队中的消息时，如果 omp 已经取走了它，你改过的文字会放回输入框并给出提示，不再凭空消失。

### 设置与文档（#211、#212）

- “设置 › 外观”里的“恢复默认大小”按钮文字不再折成两行。
- README 的截图和文字展示了当前的应用（配色、可调整大小的面板、反馈、安装 omp），安装步骤也说明了应用可以帮你安装 omp。

### 对话很长、很多时更快（#266、#267、#268、#269、#270）

- 不断变长的对话不会再拖慢应用：只为文件新增的部分建立索引（往 30 MB 的对话追加内容，从约 1.4 秒降到 2 毫秒），其他对话的回复也能流畅显示。
- 第一次启动或更新后，侧边栏会立即显示，搜索索引在后台完成（期间搜索会有提示）。
- 很长的回复也能流畅显示：回复越长，渲染不再越慢。
- 对话有几千个时侧边栏依然很快（在筛选框输入从 77 毫秒降到约 1 毫秒），页面只接收有变化的对话。
- 用量查询卡住时，额度显示不会再一直停住直到重启。

### 对话修复（#271、#272、#273、#274、#275、#276、#277、#278、#279）

- 用回车确认中文（或其他输入法）输入时，不会再把没打完的消息发送出去，macOS 应用里也一样。
- 回复或命令正在运行时，不再显示“编辑”“重新生成”和“分支”；编辑失败时，你的文字会放回输入框。
- 图片加载较晚或输入框变高时，对话会停留在最底部；发送后会滚动到你的消息。
- 再次选择同一个搜索结果时，会再次滚动到它。
- 删除正在回复的对话会被拒绝并给出说明，不会再先中止回复然后又报删除失败。
- 某个项目的最后一个对话被删除后，项目筛选会回到“全部项目”。
- 未发送的消息在刷新页面后仍然保留，包括更新后自动刷新的情况。
- 在页面任何位置按 Esc 都能停止正在进行的回复；窄屏下的侧边栏抽屉也可以用 Esc 关闭。

### 安全（#259、#260、#261、#262、#263、#264、#265）

- 格式错误的消息不会再让服务器停止；损坏或重复的登录 Cookie 也不会再导致错误页面，错误信息不再透露服务器细节。
- 打开对话时，不会再运行文件夹自身 git 设置要求执行的命令：git 状态检查会拒绝在配置里指定了要运行程序的文件夹，并屏蔽钩子和属性过滤器。（需要 git 2.40 或更新版本。）
- 你电脑上的其他网站无法触发应用里开销较大的操作，比如重新测量上下文或刷新用量。
- 网页版的数据文件夹和搜索索引只有你自己能读取。
- 应用无法删除的遗留临时文件夹，不会再导致对话无法启动。
- macOS 应用只会打开网页或邮件类的新窗口链接，“账号”里的登录链接也只接受网页地址。
