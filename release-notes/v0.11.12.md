14 issues closed: #611, #612, #613, #615, #616, #617, #618, #619, #620, #621, #622, #623, #625 and #626. One change is refs only and closes nothing: #614, the first step of windows onto other Macs, is in this release while the issue stays open. The nits to autoscroll and to the running list are in too (#586, #587).

### New (#613, #615, #616, #617)

- Host load (#613): the bottom of the sidebar — in the narrow rail when the sidebar is folded — says how busy the Mac that runs the server is: `CPU 12% · GPU 3% · MEM 61%`, then a dot coloured by memory pressure (green when normal, amber at a warning, red when critical, grey when the system gives none; no GPU when none can be read; the line fades while the page is not connected). A click opens the graphs, and the same pane is the panel's Host tab: a figure block each for CPU, GPU and memory, the last hour (a point per read) and the last 24 hours (a point a minute), the stretches above normal pressure tinted on the memory graph, breaks where nothing was read (the Mac slept, the server was not running), and a table of what the server, omp and the relay each use, with CPU as a share of one core as Activity Monitor shows it. It is read with no permission and no `sudo`: CPU from the kernel's per-core timers, memory as Activity Monitor's memory used with the kernel's pressure level, GPU's device utilisation from IOKit in a thread of its own. That thread starts on the first read, not at start, and answers with a deadline of 2 s (5 s for the first read, which starts it): a driver that hangs costs that thread and not the server, which stops it and records host load without the GPU for the rest of the run; a start that crashed inside the probe is remembered, so the next start leaves the GPU out too, and `OMP_WEBUI_HOST_GPU=0` turns the probe off while `=1` asks for it again. The server reads every 2 s while a page shows this and every 10 s otherwise, a page that is hidden or in a parked window asks for nothing, and history for the last hour and the last day (about 52 KB) lives in the server's memory only, so the graphs reach back before anyone opened them and start again when the server restarts. Linux has CPU and memory only. Nearly none of it is in the first load: the line is a chunk fetched after the sidebar appears, the graphs (and the chart library the usage page uses too) when the pane is opened.

- Memory page (#616): the sidebar's Memory lists omp's long-term memory, what `memory.backend: mnemopi` keeps — the memories every project recalls and each project's own. It searches text, the reason the agent gave, a folder or an id; it narrows by whose memory it is, by project, by kind (notes the agent saved or you added, excerpts of conversations omp kept by itself, which are off until asked for, and what omp consolidated) and by retired ones; and it opens each memory in full with where it came from: the tool that saved it, its reason, the folder, and the conversation, as a link when that conversation is one of yours. You can edit, add, retire, restore and delete. A deletion asks first and offers to retire the consolidated copy omp made of it in the same step, and a text that looks like a key or token is saved only once you tick that it is meant. A copy of the store (in `<data dir>/memory-backups/<bank>/`) is taken before every delete, and before an edit of a memory that no copy holds yet, and otherwise at most once every 10 minutes, so a run of deletes within a minute shares one copy that holds every memory the run deletes. The newest 10 copies are kept, and they keep what was deleted, secrets included, and the README says how to go back to one. When omp's settings cannot be read the page says so and changes nothing, and every route of it is refused to a page that is not on this computer, whether it came through the tunnel or over the network, whatever token it holds. Its code and strings load when the page is opened.

- Dropped files (#617): any file can be dropped into the message box, pasted into it, or picked with the Add file button, where before only pictures could. A small choice appears beside the box (the arrow keys move between its two buttons, Return takes one, Esc or the close button cancels, and the keyboard goes back to the message box; a click outside does not dismiss it). Attach puts the file itself into the message: a picture as a picture (8 MiB each, 20 MiB per message), a text file as text in a `<file name=… size=…>` block with a fenced code block inside it, shown in the conversation as a tag that expands (256 KiB per file, 512 KiB per message; whether a file is text is decided by the whole file being UTF-8, not by its extension, so a file in another encoding can only be inserted by path). Insert path writes the file's absolute path into the message, quoted when it holds spaces — a plain path and not an @ mention, because omp reads the files an @ mention names. A picture pasted from the clipboard attaches at once, unless a choice was remembered for pictures. omp expands an @ mention anywhere in a message, attached text included, so the choice and the file's tag warn about a file that holds one: omp reads that file into the prompt without a tool approval. PDF and Office documents, other binary files and folders can only be inserted by path, since omp's prompt takes text and pictures and its read tool converts those documents by path. In the macOS app the window keeps the real path of what was dropped, because WebKit never tells a page a file's path, so Insert path writes where the file actually is, folders included; pasted content and files picked with the button have no path even there, so they upload as in a browser. A browser's page — on this Mac or through the tunnel — cannot know a path, so Insert path first uploads a copy into `.omp-webui/uploads/<YYYY-MM-DD>/<name>` inside the conversation's folder, with a progress bar and Cancel, and then inserts that path. Names are cut down to a bare file name with no control or invisible characters, nothing is ever overwritten (`name (1).ext` instead), links are not followed, and the page names only the conversation, so an upload can never land outside that folder. Limits: 50 MiB a file, 500 MiB and 20 000 entries per uploads folder, 20 files in one drop; uploads into one folder are taken one at a time, so those limits hold however many arrive at once, and a body that sends nothing for 30 s is given up with its own message. No upload is accepted into a conversation whose `.omp-webui` is one of any omp-webui's data folders — this server's, the macOS app's, or the web version's — and the app's Insert path still works there. `.omp-webui/.gitignore` keeps what was uploaded out of git. A drop mid-upload says the earlier files were not sent. The app and a browser remember the choice for each kind of file separately, because only the app can insert a real path; Settings › Dropped files changes or forgets it.

- Projects folder (#615): Settings › Projects folder is where new projects are made — the folder you choose, else `~/omp`, which is shown as the default even while it is not there and is made, as that one folder only, when the first project folder is made in it. If something that is not a folder sits at `~/omp` (a file, a link to nothing), it says so and nothing is made over it, and a link to a real folder is used as it is. The new-chat folder picker has New project folder: type a name and it makes `<projects folder>/<name>` and starts the chat there, while the folders that already exist stay pickable; the form's Back closes it. The setting can only be changed on the computer the server runs on, so its controls are read-only on a page that came through the tunnel or over the network, and its refusals are worded on the page in the interface's language.

### macOS app (#614)

- Windows onto other Macs (#614, first step; macOS 14 or later): the Macs menu, between View and Window, keeps a list of other Macs you reach through Cloudflare Access, with Add Mac… and Manage Macs…. Choosing one opens a window of its own onto the omp-webui running there — its conversations, its agent — signed in through Access inside the window (the one-time PIN sent by email works there; Google's own sign-in refuses web views). The window says whose it is where the page cannot paint over it: its title starts with that Mac's name and *(remote)*, and a tinted bar above the page reads `REMOTE · <name> · <host> · <state>` with a Disconnect button, because everything the agent runs in that window runs on that Mac, as its user. A window onto another Mac is a remote page with exactly a remote page's rights: the other Mac's server cannot tell the app from a browser and is not changed. Adding a Mac looks at its address before saving it and says what it found — a redirect to Access, or in words why it could not tell, and a Mac it could not reach can be added anyway. A remote window is kept away from this Mac by the window itself, since a page of another Mac runs beside this Mac's own server on `127.0.0.1`: a content blocker refuses http and ws requests and every address of a name or a range that could be this Mac or its network, and a link opens in another app only after a real click, at most one a second. Run in Background, quitting and an update close these windows; their conversations keep running on the other Macs. Not in this step: moving files to or from another Mac, notifications from a remote window, a Mac on the local network without Cloudflare, and a sign-in that an identity provider refuses to show in a web view (an identity provider on a private or single-label name cannot be used at all).

### Safety (#611, #621)

- Local-only settings are decided by the connection, not by a header or the bind address (#621): the routes that belong to the Mac the server runs on — the tunnel's settings, the guard's, the updater's, moving to another computer, opening and revealing a file, the projects folder — are refused to every page whose connection does not come from this Mac, whatever token it holds. That covers a page on the local network when the server is bound to a network address, which until now could do all of it with the token. Such a page is a remote page for everything else too: it gets the guarded Files tab and the confirmation before a risky command, and no guard or update messages, and it can still sign in. The check is by the socket's peer address, the Host and the headers a proxy adds; a forwarder that adds none (`ssh -L`, `socat`, an nginx `proxy_pass` left at its defaults) still reaches the server as this computer, and the README says so.
- A server bound to a network address has no page on this computer, and the README now says so plainly instead of telling its owner to open `127.0.0.1`: the setting that belongs to this Mac is changed by stopping it and starting it once without `OMP_WEBUI_HOST`. What Settings keeps stays in the data folder and applies on the next bound start; a contract test drives that whole flow, including the sockets' local flag on a loopback server and on a bound one.
- The guard covers every port an omp-webui may serve on (#611): its own, its preferred port and the 20 above it, the ports of other instances' `server.pid` records, and the development proxy's, instead of the bound port alone, so a loopback `/api/` on another port is asked about and an unrelated one passes. Another instance's data folders are protected too (the app's and the web version's, where the token is), and a variable port is asked about in its unquoted forms. The `.risk` file is now compared by content at every look, and one that is not a regular file, or a pipe planted at its path, is replaced instead of read. This closes the follow-ups of #608 that #611 tracked.

### Performance (#622)

- Opening a long conversation and paging through it no longer leaves the server bigger than it was in v0.11.7. The worker that builds a conversation's history stops 3 s after its last job instead of 30 s, so its heap and the indexes of the files go with it; the windows a reader pages in above or below are not kept as bodies; the index is built from 2 MB pieces and holds each parent id once. In one interleaved series (a provisional one: the machine's load average was 76, 99 and 42 at the three starts), the server's footprint after a long conversation was 48.0 MB against v0.11.7's 50.2 MB and v0.11.11's 69.0 MB, and its peak while a reply streams was 52.6 MB against 54.6 MB and 73.9 MB. A parent id that is not Latin-1 (an accent, an emoji) is kept exactly instead of being mangled, and a window of a path whose parent was written after its child is read in file order rather than failing (#622).
- First-load JavaScript is 200.8 KiB gzip instead of 228.0 KiB. The New chat pickers, the request cards and the later pages' English text are fetched when they are needed rather than with the first page, and a check fails the build if a string ends up in the half its code does not use; a test also fails on a raw i18n key reaching a page. The budget itself is unchanged at 228 KiB.
- What this release costs, from the A / B / A′ bench gate against v0.11.11 (provisional: the machine's load average was 5–8): an idle server holds about 3.7 MB more (43.9 MB against 40.2 MB), the new modules (host load, memory and the rest) being loaded; with a page connected it uses about 0.3% more of one core (0.68% against 0.37%), because the sidebar's host load line has the server read every 2 s; and the JavaScript a cold page fetches in its first second is 247 KB in 25 files against 234 KB in 5, because the chunks New chat needs now arrive just after the first page instead of inside it. The server after a long conversation and while a reply streams is 17% smaller than in v0.11.11 in the same gate (61.7 MB against 74.5 MB, 64.4 MB against 79.0 MB).

### Presets (#625)

- A model preset now carries the subagent models too, as omp's `task.agentModelOverrides` (an agent name such as `reviewer` or `scout`, its model and its thinking level), next to the role models. Save current as… keeps the subagent models the conversation actually runs on, or the config's when it follows it, and its dialog says which. Settings › Presets lists them under each preset, and the subagent button of a preset opens an editor to add or remove an agent and pick its model and thinking level; the editor loads with Settings, not with the first page.
- Applying a preset applies them: in a conversation they replace that conversation's subagent models, and from Settings (or Set as default in a conversation that carries some) they replace the global ones. A preset that sets no subagent models leaves the current ones exactly as they are, so a conversation switched away from a preset that had some keeps them.
- Which preset is shown as active is still decided by the roles and the thinking level alone, as omp decides it; of two presets that differ only in their subagent models, a conversation shows the one it was switched to and Settings shows the first by name.
- They live in the preset's own entry, `modelPresets.<name>.agentModelOverrides` in omp's `config.yml`, so renaming, copying and deleting a preset take them along and omp still reads the file. omp itself never applies that key: `/modelpreset switch` in a terminal changes the roles only, and a terminal `/modelpreset save` of an existing name replaces the whole entry, subagent models included.

### Guard per conversation (#626)

- Guard dangerous commands can now be set for one conversation: its own mode (Off, Reviewer model or Ask me), its own reviewer, and whether to ask you when no reviewer can be reached, in This session and in New chat (the Guard: … button in the composer's footer changes the process that is warming up, so the conversation is under them before its first message). Every field a conversation does not choose follows Settings › Safety, and keeps following it as Settings change; the panel says which it is, the settings' or its own.
- The choice is kept with the conversation in `<data dir>/approval.json` and in a paused conversation's record, so it survives a restart, a pause, a resume, the server adopting a running process and the file being opened again; where both records exist the stricter one is taken (Off < follow Settings < Reviewer model < Ask me).
- Both records are the server's, not the file's: the server looks at the file once a second and writes its memory over an edit, so an Off that an agent writes into `approval.json` never weakens the guard.
- Only a move proven to be the same conversation moved on takes the choices along — a fork, a branch, a new session or a hand-off the server sent, and the first file of a new chat — and then only a field that is stricter than what the new file would get by following Settings. Damage travels with the fork and stays damage, so a damaged conversation opens as the stricter of Settings and the default (Reviewer model), never as Off. A cancelled fork carries nothing.
- It is changed on this computer only; a page that is not on it sees the guard read only, and an import's own guard choices are left alone while the import is writing.

### Development (#612, #623)

- The tests that failed only under the parallel suite are deterministic: the instance test takes a port below the system's ephemeral range, so a neighbouring port freeing between two starts no longer changes which one the server takes, and the migrate test no longer reads the tree while the running server removes files of its own. The Files tab spec takes its routes down and lets answers under way finish instead of leaving them to be disposed, and the sidebar spec dates its conversations past those of the specs that ran before it in the same worker. The server now answers a signal before it prints that it is ready, so an app or a test that stops it right after that line leaves no `server.pid` and no open database behind (#623).
- A new conversation is announced without a file until omp's first answer names one: the session-file-spelling test now ignores those announces and still fails on any different spelling of the file, which is what #448 promised. The classifier's speed tests measure how CPU time grows with an input 16 times longer (about 16 when linear, about 256 when quadratic, limit 60) instead of a wall-clock bound, so machine load no longer decides them.
- The memory page's secret check bounds the URL scheme it looks for: 64,000 characters of `a.a.` take 0.09–0.24 ms instead of 587–1628 ms.

### Known issues (#624)

本次发布关闭了 14 个 issue：#611、#612、#613、#615、#616、#617、#618、#619、#620、#621、#622、#623、#625 和 #626。有一项只是参考，没有关闭任何 issue：#614（其他 Mac 的窗口，第一步）随本版本发布，而该 issue 仍然开着。自动滚动和运行列表的收尾也在其中（#586、#587）。

### 新增（#613、#615、#616、#617）

- 本机负载（#613）：侧边栏底部（侧边栏收起时在窄栏里）显示运行服务器的这台 Mac 现在有多忙：`CPU 12% · GPU 3% · 内存 61%`，后面一个按内存压力着色的圆点（正常为绿，警告为琥珀，严重为红，系统不提供压力时为灰；没有可读的 GPU 时不显示 GPU；页面没有连接时整行变淡）。点击打开曲线，同一个面板也是侧边面板里的“本机”标签页：CPU、GPU 和内存各有自己的数值块，最近 1 小时（每次读取一个点）和最近 24 小时（每分钟一个点）的曲线，内存压力高于正常的时段在内存曲线上着色，没有读取过的时段（Mac 睡眠、服务器没在运行）曲线会断开，还有一张列出服务器、omp 和中继各自占用的表（CPU 按“占一个核心的百分比”，和活动监视器一致）。读取不需要权限，也不用 `sudo`：CPU 来自内核按核心的计时器，内存取活动监视器的“已使用内存”加内核给出的压力级别，GPU 的利用率经 IOKit 在单独的线程里读取。那个线程在第一次读取时才启动，不在启动时，并带 2 秒的期限（第一次读取为 5 秒，因为要启动它）：驱动卡住时被卡住的是那个线程而不是服务器，服务器会停掉它、这一轮剩下的时间里不带 GPU 继续记录；在探测里崩过的启动会被记住，下一次启动也不再读 GPU；`OMP_WEBUI_HOST_GPU=0` 关掉探测，`=1` 则要求重试。有页面显示这些数据时每 2 秒读一次，否则每 10 秒一次；隐藏的页面和被停放的窗口什么都不请求；最近一小时和最近一天的历史（约 52 KB）只保存在服务器内存里，所以曲线能回溯到还没人打开之前，服务器重启后重新开始。Linux 只有 CPU 和内存。它几乎都不在首屏加载里：那一行是侧边栏出现后才获取的小块，曲线（以及用量页也在用的图表库）在打开面板时才获取。
- “记忆”页面（#616）：侧边栏的“记忆”列出 omp 的长期记忆，也就是 `memory.backend: mnemopi` 所保存的：每个项目都会回忆起的记忆，以及各个项目自己的。可以搜索内容、智能体给出的原因、文件夹或 id；按归属、项目、类型（智能体保存或你添加的笔记、omp 自己保留的对话摘录——默认不显示、omp 整合出来的记忆）和已停用的来筛选；并打开每一条的全文和它的来历：保存它的工具、原因、文件夹，以及对话（如果那个对话在你的列表里就是一个链接）。可以编辑、添加、停用、恢复和删除。删除前会先问你，并可以在同一步里把 omp 为它做的整合副本一并停用；看起来像密钥或令牌的内容，只有你勾选确认是故意保存的才会存下。每次删除之前、以及编辑一条还没有任何副本包含的记忆之前，会先备份存储（在 `<数据文件夹>/memory-backups/<库>/` 下），除此之外每个库每 10 分钟最多一份，所以一分钟内的连续删除共用一份副本，那份副本里有这一串删除的每一条记忆。保留最新的 10 份，其中会留着被删掉的内容（包括密钥）（见“配置与开发”里的“记忆”，那里也写了怎样回到某一份）。读不到 omp 的设置时，页面会说明，并且什么也不改。这个页面的每一条路由都拒绝不是在这台电脑上的页面，无论是经隧道来的还是经网络来的，无论带着什么令牌。它的代码和文字只在打开页面时才加载。
- 拖入的文件（#617）：任何文件都可以拖到消息框里、粘贴进去，或用“添加文件”按钮选择，而以前只能是图片。消息框旁会出现一个小选择（←/→ 在两个按钮之间移动，回车确认，Esc 或关闭按钮取消，之后键盘回到消息框；点击外面不会关掉它）。“作为附件”把文件本身放进消息：图片作为图片（每张 8 MiB，每条消息 20 MiB），文本文件作为文本，即一个 `<file name=… size=…>` 块，里面是围栏代码块，在对话里显示为可以展开的标签（每个文件 256 KiB，每条消息 512 KiB；是不是文本看整个文件是否为 UTF-8，不看扩展名，所以其他编码的文件只能插入路径）。“插入路径”把文件的绝对路径写进消息（路径含空格时加引号）——是普通路径，不是 @ 提及，因为 omp 会自己去读 @ 提及的文件。从剪贴板粘贴的图片仍然直接作为附件（除非你为图片记住过别的选择）。omp 会展开消息里任何位置的 @ 提及，附上的文本里的也一样，所以选择框和文件标签会警告这样的文件：omp 会把它指向的文件读进提示词，不需要工具授权。PDF 和 Office 文档、其他二进制文件和文件夹只能插入路径，因为 omp 的提示词只接受文本和图片，而它的 read 工具会根据路径转换这些文档。在 macOS 应用里，窗口留着拖入内容的真实路径（WebKit 从不告诉页面文件的路径），所以“插入路径”写下的是文件真正所在的位置，文件夹也一样；粘贴的内容和用按钮选择的文件即使在应用里也没有路径，会像在浏览器里一样上传。浏览器里的页面——本机的或经隧道访问的——无法知道路径，所以“插入路径”先把副本上传到对话所在文件夹里的 `.omp-webui/uploads/<YYYY-MM-DD>/<名称>`（带进度条和“取消”），再插入这个路径。文件名会缩减为纯文件名（不含控制字符和不可见字符），绝不覆盖任何文件（重名的变成 `name (1).ext`），不跟随链接；页面只指明是哪个对话，所以上传绝不可能落到那个文件夹之外。上限：每个文件 50 MiB，上传文件夹 500 MiB 和 20 000 项，一次拖入 20 个文件；同一个文件夹的上传一次只处理一个，所以不管同时发来多少个这些上限都有效，30 秒内没有再发来数据的上传会被放弃并用自己的话说明。对话所在的文件夹里的 `.omp-webui` 是任何一个 omp-webui 的数据文件夹（本服务器的、macOS 应用的、网页版的）时，这个对话不接受上传，而应用里的“插入路径”在那里仍然可用。`.omp-webui/.gitignore` 让上传的文件不进入 git。文件还在发送时又拖入新的文件，会说明前面的没有发送。应用和浏览器各自记住对不同类型文件的选择，因为只有应用能插入真实路径；在设置 › 拖入的文件里可以更改或忘掉它。
- 项目文件夹（#615）：设置 › 项目文件夹是新项目建立的位置：你选的文件夹；没选时是 `~/omp`。`~/omp` 即使还不存在也会显示为默认值，并在第一个项目文件夹建在其中时创建（只创建 `~/omp` 这一个文件夹）。如果 `~/omp` 处是一个不是文件夹的东西（文件、失效的链接），会如实告知，也不会覆盖它；指向真实文件夹的链接直接使用。新对话的文件夹选择框里有“新建项目文件夹”：输入名称，就会创建 `<项目文件夹>/<名称>` 并在那里开始对话，已有的文件夹仍然可以选；“返回”关闭这个表单。这个设置只能在运行服务器的这台电脑上更改，因此在经隧道或经网络来的页面上相关控件是只读的，拒绝的提示在页面上按界面语言显示。

### macOS 应用（#614）

- 其他 Mac 的窗口（#614，第一步；需要 macOS 14 或更高）：“Macs”菜单（在“View”和“Window”之间）保存一份你通过 Cloudflare Access 访问的其他 Mac 的列表，里面有“添加 Mac…”和“管理 Mac…”。选一台就会打开它自己的窗口，显示那台 Mac 上运行的 omp-webui——它的对话、它的智能体——在窗口里通过 Access 登录（邮箱收到的一次性 PIN 可用；Google 自己的登录页会拒绝内嵌网页视图）。窗口把“这是谁的”写在页面盖不住的地方：标题以那台 Mac 的名字和“（远程）”开头，页面上方一条带色调的栏写着 `远程 · <名称> · <主机名> · <状态>`，旁边有“断开”按钮——因为智能体在这个窗口里运行的一切，都是在**那台** Mac 上、以它的使用者的身份运行。其他 Mac 的窗口就是一个远程页面，权利和远程页面完全相同：那台 Mac 的服务器分不出这是应用还是浏览器，也没有改动。添加一台 Mac 时会先看它的地址再保存，并说出看到的结果（转到 Access，或者用文字说明为什么判断不了；联系不上的 Mac 仍然可以照样添加）。远程窗口由窗口自己隔开这台 Mac——因为另一台 Mac 的页面就运行在这台 Mac 自己的服务器旁边（都在 `127.0.0.1` 上）：内容拦截器拒绝 http 和 ws 请求，以及任何可能是这台 Mac 或它所在网络的地址，而链接只有在真正点击之后才会在别的应用里打开，一秒最多一个。退出到后台、退出应用和更新都会关掉这些窗口，它们的对话在那些 Mac 上继续运行。这一步里没有：在两台 Mac 之间搬文件、远程窗口的通知、不经 Cloudflare 的局域网 Mac，以及服务商拒绝在内嵌网页视图里显示的登录（私有名称或单段名称的身份服务商完全用不了）。

### 安全（#611、#621）

- 只属于本机的设置由连接本身决定，而不是由请求头或绑定地址决定（#621）：那些属于运行服务器这台 Mac 的路由——隧道的设置、防护的设置、更新的设置、迁移到另一台电脑、在文件页打开或在访达中显示、项目文件夹——拒绝一切不是从这台 Mac 连进来的页面，无论它带着什么令牌。这也包括服务器绑定网络地址时来自局域网的页面，而在此之前它拿着令牌可以做所有这些事。这样的页面在其他方面也是远程页面：文件页受防护、有风险的命令运行前会先询问、收不到防护和更新的消息，而且它仍然可以登录。这个判断看 socket 对端的地址、Host，以及代理会加上的请求头；不加任何请求头的转发（`ssh -L`、`socat`、保持默认设置的 nginx `proxy_pass`）在服务器看来仍然是这台电脑，README 里写明了这一点。
- 绑定在网络地址上的服务器，这台电脑上没有页面，README 现在如实这样说，而不再让它的主人去打开 `127.0.0.1`：要改属于这台 Mac 的设置，请先停掉它，不带 `OMP_WEBUI_HOST` 启动一次。设置里保存的内容留在数据文件夹里，下一次绑定启动时生效；一项契约测试跑通了这个完整流程，包括回环服务器和绑定服务器上 socket 的本机标记。
- 防护覆盖一个 omp-webui 可能服务的每一个端口（#611）：它自己的端口、首选端口和其上 20 个端口、其他实例 `server.pid` 记录里的端口，以及开发代理的端口，而不只是绑定的那个，因此另一个端口上的回环 `/api/` 会被询问，无关的端口则放行。另一个实例的数据文件夹也受到保护（应用的、网页版的，登录令牌在那里），可变端口在未加引号的形式下也会被询问。`.risk` 文件现在每次查看都比较内容，不是普通文件时、或者路径上被放了管道时，会被替换而不是读取。这关闭了 #608 记录在 #611 里的后续工作。

### 性能（#622）

- 打开一个很长的对话并在其中翻看，不再让服务器比 v0.11.7 时更大。构建对话历史的 worker 在最后一个任务后 3 秒停止（以前是 30 秒），它的堆和各文件的索引随之释放；读者逐页翻入的上方或下方窗口不再作为响应体保留；索引按 2 MB 一块建立，每个父 id 只保留一份。在一组交错的测量中（只是暂定结果：三次起点的机器负载均值分别为 76、99 和 42），长对话之后服务器的占用是 48.0 MB，v0.11.7 是 50.2 MB，v0.11.11 是 69.0 MB；回复流式输出时的峰值是 52.6 MB，对应 54.6 MB 和 73.9 MB。不属于 Latin-1 的父 id（`父`、`🙂`）会被原样保留而不再被弄坏；父条目写在子条目之后的路径，其窗口按文件顺序读取，而不再失败（#622）。
- 首屏 JavaScript 从 228.0 KiB 降到 200.8 KiB（gzip）。新对话的选择器、请求卡片以及后面那些页面用到的英文文案改为需要时才获取，而不再随首页一起下载；如果某个字符串被放进了它的代码不用的那一半，构建会失败；另一项测试会拒绝让原始的 i18n 键出现在页面上。预算本身仍是 228 KiB。
- 这一版的代价（对 v0.11.11 的 A / B / A′ 基准门禁，暂定结果：机器负载均值为 5–8）：空闲服务器多占约 3.7 MB（43.9 MB 对 40.2 MB），因为加载了新模块（本机负载、记忆等）；有页面连着时多用约 0.3% 的单核 CPU（0.68% 对 0.37%），因为侧边栏的本机负载那一行让服务器每 2 秒读一次；冷启动页面第一秒获取的 JavaScript 为 25 个文件 247 KB，此前为 5 个文件 234 KB，因为新对话需要的分块现在紧跟在首页之后到达，而不再包含在首页里。同一次门禁中，长对话之后和回复流式输出时的服务器比 v0.11.11 小 17%（61.7 MB 对 74.5 MB，64.4 MB 对 79.0 MB）。

### 预设（#625）

- 模型预设现在也带着子代理模型，即 omp 的 `task.agentModelOverrides`（子代理名称，例如 `reviewer`、`scout`，以及它的模型和思考强度），和角色模型放在一起。“将当前配置另存为…”会保留这个对话实际在用的子代理模型（跟随配置时就是配置里的那些），并在对话框里说明是哪一种。设置 › 预设会在每个预设下列出它们，预设旁的子代理按钮会打开一个编辑器，可以增删子代理并选择它的模型和思考强度；这个编辑器随设置加载，不在首屏。
- 应用预设时会一并应用：在对话里会替换这个对话的子代理模型；从设置里（或在带着子代理模型的对话里点“设为默认值”）会替换全局的那些。没有设置子代理模型的预设会让现有的完全保持不动，所以从一个带子代理模型的预设切换到别的之后，原来那些仍然保留。
- 哪个预设显示为当前预设仍然只由角色模型和思考强度决定，和 omp 的判断一致；两个只在子代理模型上不同的预设之间，对话显示它被切换到的那个，设置里显示按名字排在最前的那个。
- 它们放在预设自己的条目里，即 omp `config.yml` 的 `modelPresets.<名称>.agentModelOverrides`，所以重命名、复制和删除预设都会一并带走，omp 也仍然能读这个文件。omp 本身从不应用这个键：在终端里 `/modelpreset switch` 只改变角色模型，而在终端里用已有的名字 `/modelpreset save` 会替换整条记录，包括子代理模型。

### 每个对话的防护（#626）

- 现在可以只为一个对话设置“防护危险命令”：它自己的模式（关闭、审查模型或问我）、它自己的审查模型，以及联系不上审查模型时是否询问你；位置在“当前对话”和“新对话”里（输入框底部的“防护：…”按钮会改动正在预热的那个进程，所以这个对话在第一条消息之前就已处在这些设置之下）。对话没有自己选的那一项跟随“设置 › 安全”，并且随后跟着设置一起变；面板会说明用的是设置的还是它自己的。
- 选择会随对话保存，在 `<数据文件夹>/approval.json` 里，也写进暂停对话的记录，因此服务器重启、暂停、恢复、服务器接管一个正在运行的进程、以及再次打开它的文件之后都还在；两处记录都有时取更严的那个（关闭 < 跟随设置 < 审查模型 < 问我）。
- 这两处记录都是服务器的，而不是文件的：服务器每秒看一次文件，并用内存里的内容覆盖掉对文件的改动，所以智能体写进 `approval.json` 的“关闭”永远不会削弱防护。
- 只有被证明是同一个对话被搬走的移动才会带走这些选择——服务器发出的分叉、分支、新会话或交棒，以及新对话的第一个文件——而且只带走比“跟随设置”给新文件的结果更严的那些字段。损坏会随分叉一起走并保持为损坏，所以损坏的对话按“设置”和默认值（审查模型）中更严的那个打开，绝不会是“关闭”。被取消的分叉什么都不带走。
- 它只能在运行 omp-webui 的这台电脑上更改；不在本机的页面只能只读地看，而导入进行期间，导入带来的防护选择不会被改动。

### 界面（#618、#619）

- 已暂停的对话，“当前对话”面板显示 omp 暂停时的设置（#619），任何页面都是如此，服务器重启后也一样；改动其中某一项后对话仍然保持暂停；暂停期间改过的模型，在解冻结束之前就已经在保留的状态里，而不是要等另一个页面再问一次（#619）。
- 在主机上运行的对话，不必先点一下就会显示它跳动的运行圆点（#618）；新增了回归测试。
- 侧边栏的八个标签重新适配默认宽度：每个标签仍是完整的 24 × 24 px 点击区域，本机标签不再被裁掉。这是本机标签加入时带来的回归，没有为它开 issue。
- 自动滚动（参考 #586）：向上滚动过的读者只在真正到达末尾时才重新跟随，而不是在离末尾 80 px 以内；要求减少动态效果时箭头立刻到位；打开一个对话时在它定位之前就先设为跟随，一轮结束后在页面跟随的那一端放开被按住的读者。
- 设置 ›“运行中的对话”里，两轮之间还在工作的目标会显示为运行中；一个页面被告知仍在进行的一次运行，在 omp 说它已结束后就会被清除（参考 #587）。

### 修复（#617、#620、#616）

- iPhone 或 iPad 主屏幕应用里聊天标题栏不再模糊（#620）：靠的是顶部边缘一条 11 px 高的固定条，它让 iOS 不再在那里画自己的模糊。它不画任何东西，也不接收触摸，而且只出现在主屏幕应用里——浏览器标签页、安卓和桌面都拿不到它，那里什么都不会移位。
- 拖入的文件，收尾（#617）：在“作为附件”“插入路径”、Esc 和关闭按钮之后，焦点回到消息框（除非你自己把它移到了别处）；第一次检查之后变成二进制的文件会被拒绝并弹出提示；README 列出了三个拒绝上传的数据文件夹。
- 记忆，收尾（#616）：omp 已经停用或替换过的整合记忆保持 omp 留下的样子；只有你自己输入的内容看起来像密钥时才会询问，omp 自己存下的不算。

### 开发（#612、#623）

- 只在并行测试套件下才失败的测试变得确定了：实例测试改用系统临时端口范围以下的端口，所以两次启动之间邻近端口被释放不再改变服务器选中的是哪一个；迁移测试不再在运行中的服务器删掉自己的文件的同时遍历目录；“文件”标签页的 e2e 先撤下自己的路由，并让正在进行的答复结束，而不是留给它去被丢弃；侧边栏的 e2e 把自己的对话日期设在同一个 worker 里先前那些 spec 的之后。服务器现在先应答信号，再打印它已就绪，因此读到那一行就停掉它的应用或测试，不会留下 `server.pid`，也不会留下没关的数据库（#623）。
- 新对话在 omp 第一次答复说出文件名之前，是以没有文件的方式通知页面的：文件拼写测试现在忽略这些通知，但仍然会在文件拼写不同时报错，这正是 #448 保证的事情。分类器的速度测试改为测量输入长 16 倍时 CPU 时间怎样增长（线性约 16，平方约 256，上限 60），而不是一个按墙钟时间定的界限，因此机器有多忙不再决定它们。
- 记忆页面的密钥检查给它要找的 URL scheme 加了边界：64 000 个 `a.a.` 用时 0.09–0.24 ms，而不是 587–1628 ms。
