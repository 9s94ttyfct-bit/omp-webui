## English

### A full audit, and every finding fixed

This release is the result of a full audit of omp-webui: the server, the web app, the code they share, the macOS app, the Windows and Linux launchers, and the build, release and CI scripts. Every finding became an issue under #44, and 134 of them are fixed here, each by its own commit that names it, with a test that failed before the fix wherever one could reach it. The findings that need a decision about how omp-webui should behave stay open as questions: #57, #77, #113, #122, #162, #168, #176.

What you are most likely to notice:

- **Remote access and the guard are stricter.** A remote page's Browser tab is disconnected as soon as remote access is turned off or its allow-list changes. The guard now reads `$'…'` quoting, brace lists, `find` options and a `find` with no start folder the way the shell does, matches protected places in any letter case on macOS and Windows, and recognises secret file names in Windows paths. A ZIP download leaves out a private key even in a file over 1 MiB, and a GitHub token is no longer shown in the Issues tab's error text.
- **Moving to another computer keeps more.** Replace keeps this computer's secret values where the archive was made without logins, Merge adds the keys a settings file lacks without losing its comments, and a file of the same length but different content is replaced instead of kept.
- **Errors are said instead of swallowed.** Copy buttons say when the clipboard refused, the unlock screen tells a wrong token from an unreachable server, and pages that could not load their list (Questions, Plugins, Files search, permission mode) show the error with a Retry.
- **Keyboard and screen reader.** The slash-command menu, the confirmations, the side panel as a sheet and the cost breakdown work from the keyboard and are named for screen readers, the connection dot says whether it is connected, and a PDF's text can be read and selected.
- **Two changes in behaviour.** Restore in Quick prompts now puts the built-ins back in the draft and saves nothing until you press Save. Two launchers started on one data folder take turns instead of both failing.

## 中文

### 一次完整审计，所有发现都已修复

这个版本来自对 omp-webui 的一次完整审计：服务器、网页应用、两者共享的代码、macOS 应用、Windows 和 Linux 启动器，以及构建、发布和 CI 脚本。每个发现都提交为 #44 下的一个 issue，这里修复了其中的 134 个，每个都由点名它的单独提交修复；凡是测试能覆盖的，都附有修复前失败、修复后通过的测试。需要决定 omp-webui 应该怎么做的发现，作为待决定的问题保持打开：#57, #77, #113, #122, #162, #168, #176。

你最可能注意到的：

- **远程访问和守卫更严格了。** 关闭远程访问或更改允许列表后，远程页面的浏览器标签页会立即断开。守卫现在按 shell 的方式理解 `$'…'` 引用、花括号列表、`find` 的选项以及不带起始文件夹的 `find`；在 macOS 和 Windows 上不区分大小写地匹配受保护的位置；也能识别 Windows 路径中的机密文件名。ZIP 下载即使在大于 1 MiB 的文件里也会排除私钥，Issues 标签页的错误文字里不再出现 GitHub token。
- **迁移到另一台电脑时保留得更多。** 当归档不含登录信息时，“替换”会保留本机的机密值；“合并”会补上设置文件缺少的键而不丢失其中的注释；长度相同但内容不同的文件会被替换，而不是被保留。
- **错误会说出来，而不是被吞掉。** 复制按钮会在剪贴板拒绝时说明；解锁页面能区分错误的 token 和无法连接服务器；无法加载列表的页面（问题、插件、文件搜索、权限模式）会显示错误并提供重试。
- **键盘和读屏。** 斜杠命令菜单、确认框、作为浮层的侧边面板和费用明细都可以用键盘操作，并为读屏软件命名；连接状态点会说明是否已连接；PDF 中的文字可以被朗读和选择。
- **两处行为变化。** 快捷提示里的“恢复”现在只把内置项放回草稿，按“保存”之前不会保存任何内容。在同一个数据文件夹上同时启动的两个启动器会依次启动，而不是两个都失败。

### 服务器

- 关闭远程访问或更改允许列表后，远程页面的浏览器标签页套接字仍保持打开 (#45)

### 构建、发布和 CI 脚本

- 文档变更推送发生在运行取消或失败之后时，CI 会让未经测试的代码显示为通过 (#155)
- release-local 会接受没有构建任何软件包的 CI 运行，之后在下载阶段仅报出笼统的“gh exited with 1” (#156)
- 手动触发的 CI 运行不检查提交身份或消息，但 release-local 仍会把它算作该提交的 CI 通过记录 (#157)
- 个人数据检查会漏掉文件名、主机名、其他账户的 noreply 地址和 IPv6 地址；git diff-tree 失败时也会通过 (#158)
- 从未检查作者和提交者姓名以及带注释标签的身份；release-local 会使用 git 解析出的任意身份创建标签 (#159)
- CI 的 unit + contract 步骤看不到失败的 test-shard.ts，随后会在整个仓库上运行 bun test (#160)
- 不带服务器场景的 bench.ts --only 每轮都会导致加载、列表和流式测试失败（包括帮助信息中的示例）(#161)
- update-smoke 和 upgrade-pause-check 清理时会对记录的 PID 发送 SIGKILL，却不检查它们是否仍是自己启动的进程 (#163)
- 出错或按下 Ctrl-C 时，freeze/run.ts 和 bench-gate.ts 会遗留临时副本（真实对话、整个检出目录）及进程 (#164)
- 有三种不同的 CPU 性能分析汇总器，其中两种把每个样本的耗时归给了错误的样本；measure-family-dedup.ts 从未被引用 (#165)
- 发布工作流会把 contents:write token 提供给可变的第三方 action 标签，并将其保留在检出目录中 (#166)
- 未提供 --top 时，freeze/profile.ts 不会打印任何行 (#183)
- freeze/run.ts 会在不存在的文件夹中创建对话，因此探测程序无法打开它 (#184)
- upgrade-pause-check 期望的是服务器已不再写入的版本 1 停放记录 (#185)
