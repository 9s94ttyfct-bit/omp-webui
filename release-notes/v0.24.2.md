## English

### Keys stay hidden when a provider signs in from its row

- **A key typed for a terminal sign-in is no longer shown.** Some providers (LM Studio, GitHub Copilot, Perplexity and others) sign in with `omp login`, which asks for the key in plain text and, in a terminal, shows it as it is typed. The sign-in now runs without a terminal: what omp prints is shown as before, and each question is answered in a field under it. While the question asks for a key, a token or a secret the field is masked, the browser does not offer or keep what is typed, and the output shows `********` in its place.

### Terminal tab in an isolated project with bash

- **The project's programs stay first on `PATH` whatever your bash startup files do.** A `~/.bash_profile` or `~/.bashrc` that set `PROMPT_COMMAND` (for example `PROMPT_COMMAND="history -a"`) used to leave the project's program folders behind the system's, so a program of the same name outside the project ran instead. bash now starts with a startup file of its own that runs `/etc/profile` and your login file first, then puts the project's folders in front. `logout` and `~/.bash_logout` work as before.

## 中文

### 在服务商那一行登录时，密钥不再显示出来

- **终端登录时输入的密钥不再显示。** 有些服务商（LM Studio、GitHub Copilot、Perplexity 等）用 `omp login` 登录，它以明文提问密钥，在终端里输入时会原样显示出来。现在登录不再经过终端：omp 输出的内容照常显示，每个问题在下方的输入框里回答。问题要的是密钥、令牌或 secret 时，输入框会遮住内容，浏览器既不提示也不保存输入的内容，输出里也只显示 `********`。

### 独立项目里用 bash 的终端标签页

- **不论 bash 的启动文件怎么写，项目的程序都排在 `PATH` 最前。** 以前如果 `~/.bash_profile` 或 `~/.bashrc` 设置了 `PROMPT_COMMAND`（例如 `PROMPT_COMMAND="history -a"`），项目的程序文件夹会排到系统的后面，项目外同名的程序会被优先运行。现在 bash 用一个自己的启动文件启动：先运行 `/etc/profile` 和你的登录文件，再把项目的文件夹放到最前。`logout` 和 `~/.bash_logout` 照常可用。
