## English

First batch of the review round: 45 issues fixed. Every fix has a regression test (or a recorded smoke run).

### One omp per conversation (#350, #354, #385, #419, #420, #356)

- If the server dies while a conversation is working, its omp and the tools it started are stopped, and a new server waits for them before it opens that conversation again. Two omp processes no longer write the same session file.
- Reopening a conversation that is still finishing its turn waits for it, or says it is still finishing, instead of starting a second omp after 10 s.
- `omp -c`, `--continue`, `-r <id>` and `--resume=<id>` in the built-in terminal hand the conversation over like `--resume <file>` does. A terminal whose page closed meanwhile is not started.
- A paused conversation whose relay accepts the connection but never answers no longer keeps the server from starting.
- A conversation whose omp has not settled (a background job, a compaction) counts as busy: idle reaping, restarts, terminal hand-offs and updates leave it alone.

### Goals (#382, #383, #390, #358, #432, #451)

- A goal that used up its token budget stays visible as "Budget reached" and can be dropped. Setting a new goal beside it is refused with a clear message instead of failing.
- A retry wait that follows opening an idle conversation is shown with its countdown, Cancel and Retry now (#451).
- A goal run gives one "finished" notification and tab mark, at its end, not one per turn.
- An active goal that omp has stopped continuing reads "Waiting for you", not "Working on goal".
- After `/new`, fork, branch or resume in the same process, the previous conversation's goal and subagents are gone.
- The budget field understands `200k` and `1.5M`, and refuses what it cannot read.

### Reliability (#349, #353, #365, #395–#399, #421, #422, #424, #425, #437–#441, #443, #444, #447)

- omp and git helper commands that hang end at their time limit with everything they started, so settings, plugins and model lists can no longer get stuck behind them.
- An omp killed by a signal is reported as "killed by SIGKILL" (or the signal), not "code -1".
- Search (⌘K) says when a search fails and offers Retry; typing on cancels the searches it has passed.
- Quota pills: no request loop for limits that reset weeks away, and no polling while the window is hidden.
- Settings > Accounts says when Manage or the list reload fails, and no longer restarts its helper omp on every reconnect.
- API answers are compressed off the server thread; a large export no longer stalls other conversations.
- `@file` suggestions include files created moments ago.
- Folder picker: `~` works, symlinked folders open, a long list says how many folders it left out, "Use this folder" takes the typed path, and errors are short.
- Settings: model choosers list omp's models in either mode; saving roles keeps roles the editor cannot show; "Save current" waits for unsaved role edits; an invalid `config.yml` or unreadable `models.yml` shows omp's actual error; a setting that could not be saved is not applied.
- Old temporary directories of paused conversations are cleaned up.

### macOS app (#373, #374, #375, #381)

- If the server stops unexpectedly, the app starts it again on the same port and the page reconnects; only four stops within a minute end in the alert. The server also logs stray errors and keeps running instead of exiting.
- The "server stopped" alert reliably includes the server's last lines.
- Quitting no longer freezes the window while the server shuts down.
- A window covered by other windows keeps its page running, so replies and notifications are not delayed.

### omp features (#351, #352, #423)

- omp's fourth permission mode, "Ask and remember" (`always-ask-cached`), can be seen and chosen, per conversation and as the default. A mode set by a newer omp is shown by name and left in force.
- A conversation's folder follows omp's `/move` and `/wt`: header, presets, the Loaded dialog and plugin/skill scopes use the new folder.
- Resuming a conversation whose folder no longer exists asks for a folder instead of silently running omp in the sessions directory.

### Development (#376–#380, #449)

- Scripts (`dmg`, `app`, `long-run`, `screenshots`, `lighthouse`, `release-local`) clean up processes, mounts and temporary files when interrupted. `release-local` checks its prerequisites before the long test run.
- New `scripts/bench.ts` benchmark (with `--shards` to use several cores) with the v0.11.7 baseline in `docs/perf/`, and `scripts/soak.ts`, a real-model long-run stability test.
- Test infrastructure: bounded server teardown, socket requests that fail on close, one login lookup per run, a contract test that no longer mistakes a short-lived omp helper for its tool process under load.

## 中文

本轮审查的第一批修复，共修复 45 个 issue。每个修复都附有回归测试或记录在案的冒烟验证。

### 每个对话只有一个 omp（#350、#354、#385、#419、#420、#356）

- 服务器在对话运行中崩溃时，该对话的 omp 及其启动的工具会被停止；新服务器会等它们结束后才重新打开这个对话，不再出现两个 omp 同时写同一个会话文件。
- 重新打开一个仍在结束本轮的对话时，会等它结束，或提示它仍在收尾，不再在 10 秒后启动第二个 omp。
- 内置终端里的 `omp -c`、`--continue`、`-r <id>`、`--resume=<id>` 会像 `--resume <文件>` 一样交接对话；页面在等待期间关闭时，不再启动终端。
- 已暂停对话的中继接受连接却始终不应答时，不再导致服务器无法启动。
- omp 尚未稳定（后台任务、压缩中）的对话被视为忙碌：空闲回收、重启、终端交接和更新都不会关闭它。

### 目标（#382、#383、#390、#358、#432、#451）

- 用完 token 预算的目标会显示为“已达预算”并可以放弃；在它旁边设置新目标会给出明确提示，而不是直接失败。
- 打开一个空闲对话后，随后出现的重试等待会正常显示倒计时、取消和“立即重试”（#451）。
- 一次目标运行只在结束时发出一次“已完成”通知和标签页标记，不再每轮一次。
- omp 已停止继续推进的活动目标显示“等你处理”，而不是“正在执行目标”。
- 在同一进程中执行 `/new`、分叉、分支或恢复后，上一个对话的目标和子代理会被清除。
- 预算输入框能识别 `200k`、`1.5M`，无法识别的内容会被拒绝。

### 可靠性（#349、#353、#365、#395–#399、#421、#422、#424、#425、#437–#441、#443、#444、#447）

- 卡住的 omp 和 git 辅助命令到时限后会连同其启动的所有进程一起结束，设置、插件和模型列表不再因此卡住。
- 被信号杀死的 omp 会显示为“被 SIGKILL 终止”（或相应信号），而不是“code -1”。
- 搜索（⌘K）失败时会明确提示并提供重试；继续输入会取消已过时的搜索。
- 额度标签：重置时间在几周之后时不再陷入请求循环，窗口隐藏时不再轮询。
- 设置 > 账户：“管理”或列表刷新失败时会提示，重新连接时不再重启辅助 omp。
- API 响应的压缩移出服务器主线程，导出大对话时其他对话不再卡顿。
- `@文件` 补全能看到刚刚创建的文件。
- 文件夹选择器：支持 `~`，能打开符号链接文件夹，列表被截断时会说明省略了多少，“使用此文件夹”采用输入框中的路径，错误提示更简短。
- 设置：模型选择器在两种模式下都列出 omp 的模型；保存角色时保留编辑器无法显示的角色；“保存当前”会等待未保存的角色修改；`config.yml` 无效或 `models.yml` 无法读取时显示 omp 的实际错误；未能保存的设置不会生效。
- 已暂停对话遗留的旧临时目录会被清理。

### macOS 应用（#373、#374、#375、#381）

- 服务器意外停止时，应用会在同一端口重新启动它，页面自动重连；只有一分钟内停止四次才会弹出提示。服务器遇到零散错误时会记录下来并继续运行，不再直接退出。
- “服务器已停止”提示能可靠地显示服务器的最后几行输出。
- 退出应用时，窗口不再在服务器关闭期间卡住。
- 窗口被其他窗口遮挡时页面仍保持运行，回复和通知不再延迟。

### omp 功能（#351、#352、#423）

- 可以查看和选择 omp 的第四种权限模式“询问并记住”（`always-ask-cached`），既可按对话设置，也可设为默认。较新 omp 设置的模式会显示其名称并保持生效。
- 对话的文件夹会跟随 omp 的 `/move` 和 `/wt`：标题栏、预设、“已加载”对话框以及插件和技能的作用范围都使用新文件夹。
- 恢复一个文件夹已不存在的对话时，会请你选择文件夹，而不是悄悄在会话目录里运行 omp。

### 开发（#376–#380、#449）

- 各脚本（`dmg`、`app`、`long-run`、`screenshots`、`lighthouse`、`release-local`）被中断时会清理进程、挂载和临时文件；`release-local` 会在漫长的测试之前先检查前置条件。
- 新增基准测试 `scripts/bench.ts`（可用 `--shards` 利用多核），v0.11.7 的基准数据在 `docs/perf/`；新增使用真实模型的长时间稳定性测试 `scripts/soak.ts`。
- 测试基础设施：服务器关闭有时限，套接字关闭时请求会失败，每次运行只查询一次登录信息；一个契约测试在负载下不再把 omp 的短暂辅助进程误当作工具进程。
