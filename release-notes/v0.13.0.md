## English

### Agents can look up how omp-webui works

- The agents in your conversations now have a read-only tool, `webui_docs`, that answers questions about omp-webui itself from its own documentation: what a feature does, where it is in the app, every setting with its key, allowed values, default and effect, the server's API routes and which of them only work on the computer omp-webui runs on, limits and security notes. Ask the agent "how do I let my phone reach this Mac?" or "what does *Where a compact you queue runs* do?" and it reads the answer instead of guessing.
- The tool lists the topics, searches them by keywords and reads a topic or one section of it. It opens no file, changes no setting, runs nothing and sends nothing anywhere: the documentation is built into the app, and a name that is not a topic (a path) is refused. No permission mode asks about it. It costs a conversation that never uses it one line of its prompt: omp mounts it at `xd://webui_docs` and shows its full description only when the agent asks.
- Every conversation the app starts has it, except one started with your own `--trusted-extension` flag (omp does not allow the app's extensions next to it). A conversation started before the update has it from its next start.
- The documentation is `docs/agents/` in the repository, one page per feature area, with an index and an `llms.txt` at the root. It is in English only, by choice; the agent answers you in your language. A test holds it to the code: a setting, a Settings entry or an API route that the app has and the documentation does not (or the other way round) fails the checks every change must pass.

### A full-window Markdown editor

- A `.md` file of a conversation's folder now opens over the whole window with its source on the left and its rendering on the right, redrawn as you type and scrolled together. **Preview** shows the rendering alone, **Source** the text alone; on a phone the two are tabs.
- Open it from the Files tab's preview of a Markdown file, the large view, the Changes view, a link to a Markdown file in a message or in a rendered file, and the file a tool wrote or edited.
- The rendering has tables, task lists, strikethrough, autolinks and footnotes, code in the conversation's colours, math (KaTeX), Mermaid diagrams, and the front matter as a small table of its keys. KaTeX and Mermaid load the first time a file needs them, so the page does not get slower to open.
- It renders a file as the conversation renders a reply: HTML in the file is shown as text, links that would run code are dropped, and pictures come only from the conversation's folder, never from the web.
- ⌘S / Ctrl+S or **Save** saves, with the large view's rules: a file this page may not write opens read only. If the file changes on the computer while it is open, the editor takes the new text when you have nothing unsaved, and otherwise asks: **Reload**, **Overwrite** or **Show diff**. It never writes over a change you have not seen. Closing with unsaved changes asks first (**Keep editing**, **Discard changes**, **Save and close**).

### Your GitHub Actions runs in the side panel

- A new **CI** tab, next to Issues, shows the GitHub Actions runs of the conversation's folder: those of its current branch, or of every branch. Each run shows whether it is queued, running, passed, failed, cancelled or skipped, the workflow, the commit or pull request title, the branch and event, when it started and how long it took, and a link to it on GitHub.
- Click a run (or press Enter on it) to see its jobs with their state and duration, the step that failed first, and a **Log** link that opens the job's log on GitHub.
- The tab carries a dot for the latest commit on your branch: pulsing while it runs, red when it failed, green when it passed, so you see it from whichever tab is open.
- It reads with your own GitHub CLI (`gh`), like the Issues tab, and never writes to GitHub. The runs are looked at again every 10 seconds while one is in progress and every minute once all are finished, only while a page has the side panel open, and one look is shared by every page watching the same repository. Errors and GitHub's rate limit make it wait longer. When `gh` is missing or not signed in, or the folder is not on GitHub, the tab says so.
- Optional: the bell in the tab tells you with a notification when a run of your branch finishes (off by default; in a browser, with notifications allowed).

### Guidance checked against the folder's AGENTS.md and memory

- When you save a conversation's model guidance (**Save for this conversation**) or switch it to another template, a small model compares it with what omp already tells the agent in that folder: its `AGENTS.md` and the other instruction files omp loads there (`CLAUDE.md`, `.omp/AGENTS.md`, your own `~/.omp/agent/AGENTS.md` and the like), and what omp remembers for the project. If something contradicts — the guidance says "reply in English", `AGENTS.md` says "reply in Chinese" — the Guidance tab lists each conflict with both statements quoted, why they clash, and a proposed fix as a diff.
- The fix changes the guidance by default, since that is what you just wrote; it may instead change a file of the folder or forget a memory when that is clearly the outdated side. **Nothing but the guidance changes unless you press Apply on that change** (or **Apply all**); **Skip** leaves it. A file is changed through the Files tab's save, so a file edited meanwhile is never overwritten; a forgotten memory can be brought back on the Memory page.
- The check never blocks a save: if no model is available, it takes too long or its answer cannot be read, the tab says "Couldn't check for conflicts" and the guidance is saved. **Check for conflicts** in the tab runs it again at any time. Templates edited in Settings are not checked against any folder; the editor says how to check a conversation that uses one.
- Cost: one request per check to the Guard reviewer's model (by default omp's `smol` role), with at most about 40,000 characters of files and memories; the same text against the same files is not asked twice. Turn it off in Settings › Model guidance › **Check guidance for conflicts**. It runs only on the computer omp-webui runs on, like every guidance change.

### Ask the agent to change settings for you

- **Settings › Ask agent for help** opens a conversation of its own, labelled *Settings help*, whose agent explains any setting and changes it for you. It runs in its own folder, so no project's files or instructions are in its context.
- Ordinary settings (appearance, layout, languages, Light's model, side questions' model, quick prompts…) change at once. Settings that weaken a protection — the guard, remote access and its shells and files, the permission mode of new conversations, unattended mode, update checks, keeping the Mac awake, notifications, where Light sends conversations and what it may run — each show a card with the current and new value and wait for your **Allow** or **Deny**; no answer in 5 minutes is a Deny.
- Its access ends after 30 minutes, when you press **Revoke now** (the strip under the conversation's header shows the time left), or when you close the conversation. In that conversation the agent is asked about before every command or file write, in every permission mode, so it cannot edit the settings files behind the tool's back.
- Every change is listed in Settings under **Changes made by the agent**, with the old and new value and whether you allowed it, and can be undone one by one or all at once per conversation. It works only on the computer omp-webui runs on (the macOS app included), not from a remote page.

## 中文

### 智能体可以查阅 omp-webui 的用法

- 对话里的智能体现在多了一个只读工具 `webui_docs`，用 omp-webui 自己的文档回答关于 omp-webui 本身的问题：某个功能做什么、在应用的哪里、每个设置的键、允许的取值、默认值和作用、服务器的 API 路由以及哪些只能在运行 omp-webui 的这台电脑上使用、限制和安全说明。问智能体“怎样让手机连到这台 Mac？”或“‘你排队的压缩在何时执行’是做什么的？”，它会去读答案，而不是猜。
- 这个工具可以列出主题、按关键词搜索、读取一个主题或其中的一节。它不打开任何文件、不改任何设置、不运行任何东西，也不向任何地方发送内容：文档内置在应用里，不是主题名的名字（比如路径）会被拒绝。任何权限模式都不会为它询问。不用它的对话只为它多付提示词里的一行：omp 把它挂在 `xd://webui_docs`，智能体需要时才显示完整说明。
- 应用启动的每个对话都有它，只有用你自己的 `--trusted-extension` 参数启动的对话除外（omp 不允许应用的扩展和它同用）。更新之前就已启动的对话，在下次启动时带上它。
- 文档在仓库的 `docs/agents/` 里，每个功能领域一页，另有索引和根目录的 `llms.txt`。文档有意只用英文；智能体会用你的语言回答你。有一个测试让文档和代码保持一致：应用里有而文档没写的设置、设置页条目或 API 路由（或者反过来），都会让每次改动必须通过的检查失败。

### 铺满整个窗口的 Markdown 编辑器

- 对话文件夹里的 `.md` 文件现在可以铺满整个窗口打开：左边是源码，右边是渲染结果，随输入实时更新，两边一起滚动。**预览**只显示渲染结果，**源码**只显示文本；在手机上两者是标签页。
- 可以从文件标签页里 Markdown 文件的预览、放大视图、变更视图、消息或渲染出的文件里指向 Markdown 文件的链接，以及工具写入或编辑的文件打开它。
- 渲染支持表格、任务列表、删除线、自动链接和脚注，代码按对话的配色着色，支持数学公式（KaTeX）、Mermaid 图表，前置元数据显示为一张键值小表格。KaTeX 和 Mermaid 只在文件第一次需要时才加载，所以页面打开不会变慢。
- 它像渲染对话回复那样渲染文件：文件里的 HTML 显示为文字，会运行代码的链接被去掉，图片只来自对话的文件夹，从不来自网络。
- ⌘S / Ctrl+S 或**保存**按钮保存，规则与放大视图相同：这个页面不能写入的文件以只读方式打开。文件打开期间在电脑上被改动时，如果你没有未保存的内容，编辑器会直接载入新内容；否则会询问：**重新载入**、**覆盖**或**显示差异**。它绝不会覆盖你没看到的改动。有未保存的修改时关闭会先询问（**继续编辑**、**放弃修改**、**保存并关闭**）。

### 在侧边面板里看 GitHub Actions 运行

- 新增 **CI** 标签页，在 Issues 旁边，显示对话所在文件夹的 GitHub Actions 运行：当前分支的，或所有分支的。每次运行显示它是排队中、运行中、通过、失败、已取消还是已跳过，以及工作流、提交或拉取请求的标题、分支和触发事件、开始时间和用时，还有指向 GitHub 的链接。
- 点一次运行（或在它上面按 Enter）可以看到它的作业：每个作业的状态和用时、第一个失败的步骤，以及打开该作业 GitHub 日志的**日志**链接。
- 标签页上有一个圆点，表示你所在分支最新一次提交的结果：运行中闪动，失败是红色，通过是绿色，不管当前打开的是哪个标签页都能看到。
- 它和 Issues 标签页一样用你自己的 GitHub CLI（`gh`）读取，从不向 GitHub 写入。有运行在进行时每 10 秒查看一次，全部结束后每分钟一次，而且只在有页面打开侧边面板时才查看；看同一个仓库的所有页面共用一次查看。出错或遇到 GitHub 的速率限制时会等得更久。没有安装或没有登录 `gh`、或者文件夹不在 GitHub 上时，标签页会说明。
- 可选：标签页里的铃铛可以在你的分支上一次运行结束时发通知告诉你（默认关闭；在浏览器里使用，需要允许通知）。

### 对照文件夹的 AGENTS.md 和记忆检查模型指引

- 为对话保存模型指引（**仅保存到此对话**）或换成另一个模板时，一个小模型会把它和 omp 在这个文件夹里已经告诉智能体的内容对照：它的 `AGENTS.md` 以及 omp 在那里加载的其他指令文件（`CLAUDE.md`、`.omp/AGENTS.md`、你自己的 `~/.omp/agent/AGENTS.md` 等），还有 omp 为这个项目记住的内容。有矛盾时——指引说“用英文回答”，`AGENTS.md` 说“用中文回答”——“模型指引”标签页会列出每个冲突：两边的原话、为什么冲突，以及以差异形式给出的建议修改。
- 建议默认修改指引，因为那是你刚写的；如果明显是另一边过时了，也可能建议修改文件夹里的文件或遗忘一条记忆。**除了指引，任何内容都要你对那一项点了“应用”才会改**（或“全部应用”）；“跳过”就不改。文件通过文件标签页的保存来改，所以期间被改过的文件绝不会被覆盖；遗忘的记忆可以在记忆页面恢复。
- 检查从不阻止保存：没有可用的模型、太慢或读不懂回答时，标签页会说“无法检查冲突”，指引照样保存。标签页里的**检查冲突**随时可以再查一次。在设置里编辑的模板不对照任何文件夹检查；编辑器会说明如何检查使用它的对话。
- 费用：每次检查向 Guard 审核模型（默认是 omp 的 `smol` 角色）发一个请求，文件和记忆合计最多约 40,000 个字符；同样的文字对照同样的文件不会问第二次。可以在 设置 › 模型使用指引 › **检查指引中的冲突** 里关闭。和所有指引改动一样，它只在运行 omp-webui 的这台电脑上进行。

### 让智能体替你修改设置

- **设置 › 请智能体帮忙** 会打开一个单独的对话（标为“设置助手”），由智能体解释任何设置并替你修改。它在自己的文件夹里运行，任何项目的文件和指令都不会进入它的上下文。
- 普通设置（外观、布局、语言、轻量模式的模型、旁问的模型、快捷提示等）立即生效。会削弱保护的设置——守卫、远程访问及其终端和文件、新对话的权限模式、无人值守模式、更新检查、保持 Mac 唤醒、通知、轻量模式把对话发往何处以及能运行什么——每一项都会显示当前值和新值的卡片，等你点 **允许** 或 **拒绝**；5 分钟没有回答视为拒绝。
- 它的权限在 30 分钟后、你点 **立即撤销**（对话标题下方的条会显示剩余时间）或关闭对话时结束。在这个对话里，智能体每次运行命令或写文件前都会先问你，任何权限模式下都如此，所以它无法绕过工具直接改设置文件。
- 每次修改都列在设置的 **智能体做出的修改** 里，带有旧值、新值和是否经你允许，可以逐项撤消，也可以按对话全部撤消。它只在运行 omp-webui 的这台电脑上可用（包括 macOS 应用），远程页面不可用。
