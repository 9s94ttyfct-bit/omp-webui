## English

### Usage & cost counts your days

- **A day of the daily cost chart is a day where you are.** The chart, its table and "since …" used UTC days, so in an evening west of UTC (the US, for example) the day's requests were counted under the next date. Days now run from midnight to midnight in the page's time zone, as omp 18.20.1 and later count them. When omp's database cannot be read and the page shows omp's own last 24 hours, those days are shown in the page's time zone too, whichever omp version counted them.

### Signing in from Accounts

- **A provider's sign-in asks in its own row.** The question for a key, a token or a code now opens in the provider's row and is scrolled into view, instead of somewhere else on the page.
- **Keys and tokens are masked as you type them.** An API key or token you enter to sign in is hidden like a password; an authorization code stays visible.
- **Providers omp cannot sign in over its RPC sign in from a terminal.** For those providers the row opens a terminal running `omp login`, and it keeps that one process when the row redraws mid-question.
- **An empty key says that nothing was stored.**

### Isolated project environment

- **The switch, the header mark and the agent's note say what goes inside and what does not.** npm's global installs go inside the folder's environment only when Node is not managed by nvm; the docs also name what still installs outside.

## 中文

### 用量与费用按你的日期统计

- **每日费用图里的一天是你所在地的一天。** 图表、表格和“自 … 起”原来按 UTC 日统计，在 UTC 以西（例如美国）的晚上，当天的请求会算到第二天。现在一天从页面所在时区的午夜到午夜，与 omp 18.20.1 及更高版本的统计方式一致。omp 的数据库读不了、页面显示 omp 自己的最近 24 小时时，这些日期同样按页面所在时区显示，不论是哪个版本的 omp 统计的。

### 在“账号”里登录

- **登录时的提问出现在该服务商自己的那一行。** 需要输入密钥、令牌或验证码时，提问在该服务商的行里打开并滚动到可见位置，而不是出现在页面别处。
- **输入的密钥和令牌会被遮住。** 登录时输入的 API 密钥或令牌像密码一样隐藏；授权码仍然可见。
- **omp 的 RPC 无法登录的服务商改在终端里登录。** 这些服务商的行会打开一个运行 `omp login` 的终端；提问中途该行重新渲染时，仍沿用同一个进程。
- **提交空的密钥时会提示没有保存任何内容。**

### 隔离的项目环境

- **开关、标题栏标记和给代理的说明会写明哪些安装在环境内、哪些不在。** 只有 Node 不由 nvm 管理时，npm 的全局安装才会进入该文件夹的环境；文档也列出了仍会装到环境外的内容。
