### Remote access (#537, #538, #539, #540, #548, #549, #550, #551, #554, #556, #557)

- Settings › Remote access opens this app from another machine: a Cloudflare tunnel carries a public address on your own domain to this Mac, and Cloudflare Access asks who you are before it lets you in; the card walks you through it in order: install cloudflared, log in to Cloudflare in the browser, create the Access application in the Cloudflare dashboard (Zero Trust › Access › Applications › Self-hosted) and paste its AUD, the team name and the allowed e-mail addresses, then "Set up the tunnel" and "Start the tunnel".
- A request to the public address is served only with a valid Cloudflare Access sign-in, which the server checks itself: the right application, the right team, not expired, and an e-mail address on your list.
- The server installs and runs cloudflared for you, and only the person at this computer can change the tunnel: a page that came in through it cannot.
- The card says whether the tunnel is off, starting, connected or failing and offers the public address to copy; a small mark under the versions in the sidebar shows the same, and a remote page warns when its permission mode runs tools without asking.

- "Ask for every tool while remote" is not lifted the moment the phone's connection drops: it stays for about ten minutes, and until the conversation is idle.
- Every command a remote page sends, a prompt, a resume, a retry, a preset switch, a mode change, an answer to a dialog or a pause, waits for that same hold, so none of them runs in your own permission mode.
- Allowed e-mail addresses are compared as plain ASCII, so a look-alike address cannot slip in through Unicode case folding.
- The hold on a remote conversation survives a restart of the server, so a conversation waiting out a usage limit still asks when it resumes.
- Turning remote access off ends a cloudflared an earlier server left running, so the address does not point at a port nobody serves.

### 远程访问（#537、#538、#539、#540、#548、#549、#550、#551、#554、#556、#557）

- 设置 › 远程访问让你从另一台机器打开这个应用：一条 Cloudflare 隧道把你自己域名上的公网地址连到这台 Mac，Cloudflare Access 在放你进来之前先问你是谁。卡片按顺序带你完成：安装 cloudflared、在浏览器里登录 Cloudflare、在 Cloudflare 控制台创建 Access 应用（Zero Trust › Access › Applications › Self-hosted）并粘贴它的 AUD、团队名和允许的邮箱地址，然后“设置隧道”“启动隧道”。
- 公网地址上的请求只有带着有效的 Cloudflare Access 登录才会被服务，而且由服务器自己核对：应用对、团队对、没有过期、邮箱在你的名单上。
- 服务器替你安装和运行 cloudflared，而且只有坐在这台电脑前的人能改动隧道：从隧道进来的页面不能。
- 卡片会说明隧道是未运行、启动中、已连接还是出错，并给出可复制的公网地址；侧边栏版本号下面的小标记显示同样的状态，远程页面在权限模式允许工具不经询问运行时给出警告。
- 远程页面的 Cloudflare Access 登录过期时，它的连接会被关掉，页面会重新登录，而不是一直挂着。
- “远程时每次工具都询问”不会在手机连接断开的瞬间解除：它会保留大约十分钟，并且要等对话空闲。
- 远程页面发出的每一条命令——发提示词、继续、立即重试、切换预设、改模式、回答对话框、暂停——都等着这同一个限制生效，因此没有一条会按你自己的权限模式执行。
- 允许的邮箱地址只按纯 ASCII 比较，因此一个形似的地址不会借 Unicode 的大小写折叠混进来。
- 远程对话上的这个限制能跨过服务器的重启，因此一个正在等待用量额度重置的对话恢复时仍然会询问。
- 关闭远程访问会结束上一个服务器留下的 cloudflared，因此这个地址不会指向一个没人服务的端口。
- 再次设置隧道时，如果这台 Mac 上还留有那条隧道的凭据，就会接手账号里已有的那条隧道，因此设置文件丢了隧道 id 之后也不会卡住；否则卡片会说明该删掉哪条隧道。

- 审批只在它等的那条消息真正发出之后才被拒绝，因此发送失败的消息不会动到审批。
- omp 不会立即运行的任何消息都会拒绝待处理的审批，“现在发送”的后续消息也一样。
- 审批卡片和输入框都会说明：发送消息会拒绝这次审批。
- 指定某个对话的搜索会从它的全部内容里给出答案，并说明这个答案来自该对话的多少内容。
- 装着对话的文件夹会一直保留为根目录，读不了的根目录文件会另存一份，而不是被覆盖。
- `--session-dir` 文件夹只列出自己的对话，不会把旁边的子代理和顾问记录也列进来。
- `--profile` 或 `--session-dir` 文件夹里的对话可以置顶和取消置顶，并且出现在侧边栏读的那份列表里。
- `--profile` 或 `--session-dir` 文件夹里的对话保留自己的预设和自己的等待额度恢复选项。
- 相对的 `--session-dir` 会按 omp 的读法，记为对话所在文件夹下的一个文件夹。
- 查找尚不知道的对话时，会覆盖服务器读取的每一个文件夹，因此写在别的文件夹里的对话即使监视事件来得晚也会被找到。
- 读不了的 `--session-dir` 或 `--profile` 文件夹不再拖垮整个库：别的对话照样列得出来、照常搜索得到，读不了的那个只提示一次就被放到一边。
- 应用启动之后才建立的 `--session-dir` 或 `--profile` 文件夹，一出现就会被监视，因此它的对话的消息数、预览、标题和费用都保持最新。
- 对话记录的最后一行没有写完时，命令面板不再一直说它还在建立索引；问够几次之后它会停下，并说明这个对话还没有完全建立索引。

### 长时间运行和稳定性（#355、#357、#367、#368、#372、#448、#451、#459、#460、#462、#494、#536、#543、#559、#560、#561、#566）

- 暂停、恢复、再次冻结一个对话时列出进程的动作不再卡住服务器。
- 结束的进程在没有人看它时会放开它的对话记录，长时间使用时不会把所有对话都留在内存里。
- 会话文件始终从同一个已打开的文件读取，因此读取期间的改写不会把新旧内容拼在一起。
- 无法监视文件的机器上改为轮询会话列表，扫描失败也会重试，而不是留下一份陈旧的列表。
- 归档列表和常用模型列表改为整体替换写入，被截断的文件会另存一份，而不是被当成空列表。
- 一个对话的会话文件在各处只有一种写法，因此符号链接的主目录不再被看成“对话被移动了”。
- 页面接入一个空闲对话之后，omp 宣布的重试等待仍然会显示。
- 等待用量额度恢复可以跨过服务器：即使期间应用被关掉，到了重置时刻等待仍在。
- 从上一个服务器接手过来的 omp 安装或更新任务，在跟进时不会卡住服务器。
- 没有服务器连接时，中继仍会继续读取 omp 的输出，因此长时间的等待不会把 omp 卡住。
- 在两次请求之间写入的对话，会出现在页面最终拿到的列表里。
- 运行中的 omp 安装或更新任务一开始就写下记录，因此在这头几秒里退掉的服务器不会把这个任务丢给没有人。
- 无法把某个进程和号码相同的另一个进程区分开的安装或更新任务会被结清，而不是一直显示为在运行；取消它也不会动到那个别的进程。
- 这台服务器自己启动的安装或更新任务，不会再因为机器读不出进程列表而在一分钟后被写成失败。
- 取消一个从上一个服务器接手过来的任务时不再等待进程列表，因此服务器在等待期间照样能服务。
- 进程已经不在的任务会立刻结清，而不是显示为在运行一分钟。
- 服务器检查期间才结束的安装或更新，会按它写下的结果结清，而不是显示为失败。

### 性能（#360、#364、#369、#370、#389、#428、#429、#458、#467、#470、#530、#531、#562、#563）

- 回到一个对话时只读取最后一条之后的内容，不再重读整份对话记录。
- 每个页面只读取它自己显示的东西，因此别处正在流式输出的对话不会再让它重绘。
- 有分叉的对话只发送一次共享的路径，而不是每个分叉发一次。
- 一次文件变动只扫描监视器指出的那几个会话文件，不再扫描整个库。
- 目标的一轮只向 omp 读取一次状态，而不是每一帧都读。
- 向一个已经打开了几百条消息的对话流式输出，代价和只有最新消息时一样，第一条消息一键可达。
- 流式输出的列表、表格或引用块每段只绘制一次，而不是每个 token 都整段重绘。
- 正在工作的对话每 30 秒查看一次服务商的额度，一轮结束时再查一次。
- 状态读取只带页面要用的内容，不再带上系统提示和工具的 schema。
- 页面会放开已经展示过的视图，因此分离的节点和监听器不会随着每次访问增长。
- 没有分叉的对话不会再被放进一张包含它全部条目的表里，因此打开它不花代价。
- 写一个分叉时，只把那个分叉发给显示它的标签页，而不是把整家人再发一遍。
- 就地改写、大小和修改时间都不变的分叉会重新发过来，而不是在页面上一直是旧的。
- 监视不了的文件夹会被排除在监视之外，而不是让整个库每三秒重扫一遍。
