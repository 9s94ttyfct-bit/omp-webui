## English

### The built-in browser

- **Phone is a phone to the sites.** The Phone size used to lay the desktop page out at 390 px, so a site that sends phones another page still sent its desktop one, squeezed. The page now says it is Chrome on an Android phone (the user agent and the client hints `Sec-CH-UA-Mobile` and `Sec-CH-UA-Platform`) with touch, and is loaded again when you switch between Phone and Desktop or Panel, so a site gets the request a real phone would send. Desktop and Panel send the browser's own user agent again.
- **What one session sets on a page no longer outlives it (Mac app).** The agent's browser tool and the Browser tab share a page's one DevTools channel in the app's browser, so a size, a user agent, extra headers or a request interception one of them set stayed after it went and applied to the other (#27). The server now remembers what each session set and, when the session ends, gives the page back what the one before it set, or undoes it.
- **Two windows popped out for one conversation** no longer bring the browser back into the side panel when you close one of them (#26): each window has an id of its own, and the panel shows the browser again only when none is open.
- **Escape leaves the browser's full screen in the Mac app, also while the page has the keyboard** (#25). The app tells the page of the key, the full screen ends, and the key still reaches the page.

### Host load

- **Whole-machine power.** The pane has a *Power* tile and graph: what the whole Mac draws in watts, display included, read from the SMC (no privileges, no process, about 2 ms a look). The graph is drawn against a round number of watts, not 100. A computer that tells no power shows neither.

### Conversations

- A running conversation's settings file is written again if something removes it (#30): it is looked at every 15 s and written from what the server holds, and its time stamps are renewed so that the system's cleaner of the temporary folder does not take it after three days.

### Tests

- Fixed the flaky tests of #19 (four end-to-end specs that waited on a state that could pass too early), #23 (the browser-engine test opened the conversation's endpoint before the server had taken the app's greeting), #24 (two unit files left a stub `fetch` behind) and #29 (temp folders are removed with retries, for Windows). #20 is not reproduced: its test helper now says how a socket ended.

### Not fixed

- #28, *Change folder* for a conversation whose folder is gone: omp does nothing for a `/move` to the folder it is already in, so resuming into the chosen folder does not re-file the conversation; the only way is to start omp in another folder first, which the app does not do. It stays open with the finding.

## 中文

### 内置浏览器

- **“手机”对网站来说就是手机。** 以前“手机”尺寸只是把桌面页面按 390 px 排版，所以按设备返回不同页面的网站仍然发来桌面版，被挤在窄屏里。现在页面会声明自己是 Android 手机上的 Chrome（用户代理，以及客户端提示 `Sec-CH-UA-Mobile` 和 `Sec-CH-UA-Platform`），带触控；在“手机”与“桌面”或“面板”之间切换时会重新加载页面，网站收到的就是真手机会发出的请求。“桌面”和“面板”恢复发送浏览器自己的用户代理。
- **一个会话对页面做的设置不再比它活得更久（Mac 应用）。** 应用的浏览器里，agent 的浏览器工具和“浏览器”标签页共用一个页面的 DevTools 通道，所以其中一个设置的尺寸、用户代理、额外请求头或请求拦截，在它离开后还留着，并影响另一个（#27）。现在服务器会记住每个会话设置了什么，会话结束时把页面还给上一个会话设置的内容，或撤销。
- **为同一个对话弹出两个窗口**，关掉其中一个不再让浏览器回到侧边面板（#26）：每个窗口有自己的 id，面板只在没有任何窗口打开时才再次显示浏览器。
- **Mac 应用里，浏览器全屏也可以按 Esc 退出，即使页面拿着键盘**（#25）。应用把这个按键告诉页面，全屏随即结束，按键仍然送到网页。

### 本机负载

- **整机功耗。** 面板里新增“整机功耗”数值块和曲线：整台 Mac 的功耗（瓦），包含显示屏，来自 SMC（不需要权限，不启动进程，每次约 2 毫秒）。曲线按一个整数瓦作纵轴，而不是 100。电脑不提供功耗时两者都不显示。

### 对话

- 运行中对话的设置文件被删掉时会重新写出来（#30）：每 15 秒看一次，按服务器手里的内容重写；它的时间戳也会定期更新，避免系统清理临时文件夹时三天后把它拿走。

### 测试

- 修了 #19（四个端到端用例等的状态可能过早满足）、#23（browser-engine 测试在服务器收下应用的问候之前就打开了对话的端点）、#24（两个单元测试文件留下了替身 `fetch`）和 #29（临时文件夹带重试地删除，针对 Windows）的不稳定测试。#20 没有复现：它的测试辅助现在会说明连接是怎么结束的。

### 没有修复

- #28，对文件夹已不存在的对话使用“更换文件夹”：omp 对“移到它已经在的文件夹”什么也不做，所以先在选定的文件夹里恢复对话并不会把它重新归档；唯一的办法是先在另一个文件夹里启动 omp，而应用不这样做。这一条保持打开，并附上了结论。
