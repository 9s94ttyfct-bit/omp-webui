# omp-webui v0.25.0 audit

Baseline: `main` at v0.24.3 (commit `6a1dcd0`). Each finding was filed as a GitHub issue and fixed before v0.25.0; the
Status column names the fix.

omp reference: the installed **18.20.2**, and **18.12.3** (`OMP_COMPAT.min`, the oldest release the web UI supports),
the two releases CI runs the unit and contract tests on.

## 1. Summary

- **19 findings**: 2 high, 8 medium, 9 low, each filed as an issue (#189–#207) and fixed with a regression test or a
  check before v0.25.0 (§3, Status names the commit).
- **High, both in the safety story for remote pages**: a page that holds only the access token could reach the
  owner-only routes through a command it ran on this computer (A-101), and the Guard's classifier let a write through a
  glob or a variable reach the gate's own state, which turned the guard off (A-103). The switch "Let remote pages open a
  shell" did not stop a token-only page from running commands (A-102), and several macOS wrappers hid what they ran from
  the classifier (A-104).
- **Behaviour a user meets**: a conversation was taken for idle while its subagent still worked, so Delete or the idle
  reaper cut it off (A-106, omp ≥18.21); Stop's withdrawn queue was lost when the person opened another conversation
  before Stop was answered (A-110); a slash command could be given back to be sent twice after a dropped connection
  (A-111); three Stop/Cancel controls failed without a word (A-112); two English errors on a Chinese page (A-113).
- **Gates that missed things**: CI against the newest omp was red for test reasons (A-105); the guard's macOS-only case
  (A-114) and four e2e tests that need a login (A-116) ran in no gate; CI's packaging jobs used actions by tag (A-115);
  `bun run parity` passed when it read nothing (A-118).
- **Hygiene**: a flaky test that hid its cause (A-107), a doc naming a removed file (A-108), dead code (A-109, A-119), the
  Windows browser download unpacked by whatever `tar` is on PATH (A-117).
- One more risk was noted and not filed (§4): nothing checks that a release is signed with the same certificate as the
  last one.

## 2. What was checked, and how

The code was read in five slices, one after another, each by a reviewer that could run the code but changed nothing in
the repository (scratch files under `.tmp/audit-<slice>/`, not committed). A claim about behaviour was checked by running
it: a probe against a test server (`tests/support/server.ts` `startTestServer`, with a home and an omp agent folder of
its own) or the test that covers it; what could not be run is marked as an inference.

| Slice | Scope |
| --- | --- |
| A1 security | authentication and remote access (`server/auth.ts`, `server/remote-*.ts`, `server/csp.ts`, the HTTP and WebSocket routing of `server/main.ts`), file access (`server/files.ts`, `server/dirs.ts`, `server/folder*.ts`, `server/upload.ts`, `server/transfer-*.ts`, `server/export*.ts`), process execution (`server/pty.ts`, `server/omp/run.ts`, plugin, git and `gh` routes), the Guard and its classifier (`server/guard*.ts`, `shared/remote-risk.ts`, `server/omp/gate/`), secrets |
| A2 server runtime | conversations and omp processes (`server/live.ts`, `server/omp/*`), terminals, sessions and history, the search index, migration, sleep, the host sampler |
| A3 page | `web/src`: stores, components and libraries |
| A4 platform and release | the macOS shell (`macos/`), the built-in browser (`server/browser/`), `server/platform/`, `scripts/` and `.github/workflows/` |
| A5 cross-cutting | `shared/` and the protocol between server and page, translations, documentation against the code, test hygiene |

## 4. Noted, not filed

- **Signing continuity of a release** (A4-06, [INFERENCE]): `scripts/lib/release-preflight.ts` checks only that an
  identity named "omp-webui local signing" exists, and `scripts/dmg.ts` compares the image's designated requirement with
  the app just built. If the signing keychain were lost and the identity made again (`scripts/signing-identity.ts`), the
  release would publish normally and every installed app's updater would refuse it (`server/update/verify.ts`, the
  `requirement` refusal), so the person would have to download the new version by hand. Not reproduced (it needs the
  identity to be lost); a check would compare the new app's certificate leaf with the last published release's, read from
  its dmg, without committing the hash. Left as a known risk of the release process.
- **Server error texts** reach a Chinese page in English when the page shows them as they are (`ReplyError` messages
  such as "Live session not found"). The page translates the errors it expects (by `code`); the rest are rare failures.
  Not a defect of one place: a protocol-wide change, not made for this release.

## 5. Checked, no finding

- **Authentication and remote access**: token file `0600`, constant-time compare, cookie `HttpOnly; SameSite=Strict`;
  Cloudflare Access JWT (RS256, `kid`, `iss`/`aud`/`exp`/`nbf`), Host and Origin pinning, `Sec-Fetch-Site` for API and
  WebSocket, owner-only prefixes refused before dispatch; CSP with hashes; proxy headers demote a request.
- **Files**: `..`/absolute/NUL refused, links resolved and kept inside, hidden and secret names refused to guarded pages,
  per-entry checks in archives and uploads, disk reserve; `git` and `gh` routes refuse repository-scoped command keys;
  exports in a private folder removed after reading; no `OMP_WEBUI_*` variable reaches an omp tool.
- **Processes**: the RPC client fails every pending request on exit and refuses new ones; the relay client's deadlines;
  `Live.open` never runs two omp on one file; terminals bounded and owned by their page; caffeinate has no restart loop;
  cleanup re-checks every path after the delete; an import backs up before each write.
- **Page**: reconnect rejects what was not acknowledged and resends nothing twice; late replies are keyed by process;
  module caches bounded; listeners and timers cleaned up; no icon-only button without a name; settings forms refuse
  invalid input. The 209 web unit test files passed on the baseline.
- **Platform and release**: release-local requires CI's success on the exact commit with all four packages, never moves a
  tag, pushes it only after every step; `CI ok` fails on any failed or cancelled job; the 16 e2e shards hold all 2249
  tests once; `release.yml` pins its actions and runs none of the tag's code; `linux-install.sh` swaps folders atomically;
  the WKWebView navigation policy and the CDP proxy's per-conversation filtering.
- **Cross-cutting**: every server and client message of `shared/protocol.ts` is sent and handled (except A-109); every
  zh-CN module is typed by the English keys, so a missing translation fails the type check; every backticked repo path in
  the docs exists (except A-108); `tests/e2e/timings.json` names exactly the 2250 tests Playwright lists and
  `.bun-test-timings.json` only files that exist; no `.only` in the tests; `bun run parity` 171/171.

## 6. Could not assess

  read, not run (A-117 is an inference).
- **Real-model behaviour**: the reviewer model's verdicts under prompt injection and the guided-goal interview need model
  calls the audit did not make (the release runs `test:live` and `test:live:e2e`, which call a model).
- **Interactive and windowed tests**: omp's TUI `!command` in a token-only terminal (the `--mode rpc` variant was run),
  `OMPW_GUI_TESTS`, the real keychain and signing identity.
- **Cloudflare**: the tunnel login and `server/remote-ai.ts` end to end need `cloudflared` and an account; read only.
- **Read in part**: the rest of `server/live.ts` (pause/resume, park/adopt), `server/migrate/export.ts`, the search index
  worker, `server/family*.ts`, `macos/remote*.swift`, and the ~104k lines of `web/src` beyond the sampled stores,
  composer, dialogs and settings forms (with scripted scans for translations, labels, listeners and swallowed promises).
