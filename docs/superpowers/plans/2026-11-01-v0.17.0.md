# v0.17.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New chat starts a new project by default; the "writing" shimmer becomes a breathing caret (and the stutter is
traced and fixed); the Windows launcher updates itself; New chat remembers the guidance last used.

**Architecture:** Server: an auto-named project folder in `ProjectsFolder`; the app updater split into a macOS and a
Windows install (`server/update/`). Page: a `#/new?cwd=` route for "new chat in this folder", New chat's new-project mode
that starts omp only on send, a remembered-guidance synced pref, CSS/React changes to the live animations.

**Tech Stack:** Bun 1.4 (server, tests, `bun build --compile`), React + Vite, Playwright e2e, GitHub Actions
(`windows-latest`), PowerShell (Windows helper), `tar.exe` (zip extraction on Windows).

**Spec:** `docs/superpowers/specs/2026-11-01-v0.17.0-design.md`

## Global Constraints

- Version `0.17.0` in `package.json`; release notes `release-notes/v0.17.0.md` with `## English` and `## 中文`.
- Auto name: `chat-YYYY-MM-DD-HHMM` (server's local time), then `-2`, `-3`, … when taken.
- Windows asset: `omp-webui-v<version>-windows-x64.zip`; zip has one top folder `omp-webui-windows-x64/` holding
  `omp-webui.exe` and `web/index.html`.
- Windows update refuses an asset with no `digest`; checks size, SHA-256, `omp-webui.exe --version` == release version.
- Leftovers: `<install>.updating`, `<install>.previous`, `<install>.failed` as on macOS (`helper.sh` semantics).
- Docs in English and Chinese (`README*.md`, `docs/TECHNICAL*.md`, `docs/agents/*.md`); privacy hooks pass; noreply
  identity; no `git stash`; one pusher to `main`.
- Live animations: `transform`/`opacity` only; reduced motion turns them off; idle runs no animation and asks for 0
  animation frames (`tests/e2e/live-motion.spec.ts`).

## Review Focus

1. A `!command` or goal sent from New chat in new-project mode runs in the new folder, never in the projects root (Task 3).
2. Folder creation fails (root gone, no permission, name taken in between): nothing is sent, draft and images stay (Task 3).
3. The new-project warm-up in the root leaves no session file, conversation or recent-project entry (Task 3).
4. A failed Windows swap (rename fails, new exe never acks) puts the old folder back and starts it (Task 8).
5. Remembered guidance names a deleted template: New chat falls back to Settings' default, not to nothing (Task 4).
