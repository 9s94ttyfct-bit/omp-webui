# v0.11.20 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the six parts of the approved v0.11.20 design: a short session panel, the whole usage history, guidance edited in place (also for closed conversations), sidebar search by message content, and a benchmark of Apple's on-device model as guard reviewer.

**Architecture:** Each part is independent and lands as its own commit(s) and GitHub issue. Server: Bun/TS (`server/`), page: React (`web/src`), shared types in `shared/`. Usage figures move from `omp stats --json` (24 h only) to read-only queries of `~/.omp/stats.db`; everything else reuses existing routes and stores.

**Tech Stack:** Bun, `bun:sqlite`, React, Radix Popover, Tailwind, Playwright e2e, `bun test`.

**Spec:** `docs/superpowers/specs/2026-10-28-v0.11.20-design.md`

## Global Constraints

- Every new user-visible string in English and zh-CN (the namespace files under `web/src/i18n/`).
- Comments say why, in the repo's existing voice.
- `~/.omp/stats.db` is opened `readonly: true` and never written.
- Model guidance changes stay "this computer only" (`onThisComputer`), as today.
- No DeepSeek; at most one Sonnet subagent at a time.
- Unit tests only where a plausible bug would fail them; e2e for page behaviour; contract test for the stats database.
- Run tests in parallel (`bun test --parallel`, Playwright with the default 4 workers).

## Review Focus

1. Usage range "All time" on ~116k rows: the answer must arrive in well under a second (indexes on `timestamp` exist); Task 2 measures it.
2. The guard bucket and the main figures must cover the same window; a guard request just outside the range must not be counted (Task 2 test).
3. Editing guidance of a closed conversation while another page opens it: the opened process must carry the edit (Task 5 e2e reopens after the edit).
4. Sidebar content search with the archived view or a project filter on: content matches outside them must not appear (Task 8 test).
5. "Also update template" when the template was deleted meanwhile: the save must fail visibly, not create a stray template (Task 6 test).

### Task 1: Stats from the database

**Files:**
- Create: `shared/usage-range.ts`, `server/omp/stats-db.ts`
- Test: `tests/unit/stats-db.test.ts`, `tests/contract/stats-db.test.ts`

**Interfaces:**
- Produces: `type UsageRange = "24h" | "7d" | "30d" | "all"`; `USAGE_RANGES`; `DEFAULT_USAGE_RANGE = "30d"`; `isUsageRange(v: unknown): v is UsageRange`; `usageWindow(range, now: number): { from: number; to: number }` (`from` = 0 for `all`, `to` = now).
- Produces: `statsFromDb(dbPath: string, window: { from: number; to: number }, bucket: "hour" | "day"): OmpStats | null` — null when the file cannot be opened or lacks a column the queries use. Same shape as `omp stats --json` (`overall`, `byModel`, `byFolder`, `byAgentType`, `timeSeries`, `costSeries`, `modelSeries`, `modelPerformanceSeries`; series keys as omp's: `timestamp, requests, errors, tokens, cost` / `model, provider, cost, unpricedRequests, costInput…, requests` / …). Buckets at UTC hour / UTC day, as omp's are.

- [ ] Step 1: Unit test with a temp sqlite file holding a `messages` table (columns as `~/.omp/stats.db`) and ~10 rows over 3 days, 2 models, 2 folders, one error row, one row of agent_type `advisor`: assert `overall.totalRequests`, `failedRequests`, `totalCost`, `byModel` per-model counts, `byAgentType`, `costSeries` day buckets, and that a row 1 ms before `from` is excluded. A db without `agent_type` → `null`.
- [ ] Step 2: Run `bun test tests/unit/stats-db.test.ts` → FAIL (module missing).
- [ ] Step 3: Implement with `new Database(path, { readonly: true })`, column check via `PRAGMA table_info(messages)`, `GROUP BY` queries. Formulas for derived fields (`cacheRate`, `errorRate`, `avgTokensPerSecond`, `avgTtft`) are whatever makes the contract test equal omp's own answer.
- [ ] Step 4: Contract test: run `omp stats --json`, then `statsFromDb(~/.omp/stats.db, {from: answer.overall.firstTimestamp, to: answer.overall.lastTimestamp}, "hour")`; assert equal `totalRequests`, `failedRequests`, token totals, `totalCost` (±1e-6), and `byModel`/`byAgentType` request counts.
- [ ] Step 5: `bun test --parallel tests/unit/stats-db.test.ts` and `bun run test:contract` (the new file) → PASS. Commit.
